= RTDB cluster

This AWS module runs one ECS service of RTDB nodes behind a private Arrow Flight endpoint.
Use the same immutable Linux ARM64 `rtdb` image for both modes.
The default-mode image needs the Kafka and S3 backends, such as the `all-backends` runtime image.
The legacy `rtdb-multi` image remains available to installations using its role-based runtime.

Supply a DNS-enabled VPC, routed private subnets in at least two availability zones, and the security groups of the Flight clients.
Supply a private DNS zone and a matching ACM certificate for `tls.hostname`.
The Network Load Balancer terminates TLS with HTTP/2 ALPN and forwards each Flight connection to one node in the VPC.
The `flight_endpoint` output is the client URI.

Supply an existing dedicated S3 bucket in the same region and a KMS key ARN.
The module owns that bucket's default SSE-KMS configuration.
Allow the task role to use the key in the key policy, and allow the ECS execution role to decrypt any injected secrets encrypted under that key.
Keep sessions on their Flight connection and establish a new Flight session after a disconnect.

Pass `root_password_secret` as a Secrets Manager selector for the root password.
Use Secrets Manager selectors for journal client PEM values in Multi mode.
Terraform stores these selectors rather than the credential values.

== Default mode

Set `kafka_bootstrap` to brokers reachable from the private subnets and `kafka_topic` to the primary database's source topic.
Create the source topic and its `<topic>-replica` topic before startup.
The native node opens the ordinary Kafka source and replica logs and stores its database files in S3.
Each task caches remote files in its own ephemeral disk under `/var/lib/rtdb/cache`.
The bundled `cluster-default.yaml` enables `defaultV1Serving` for the primary database.
Provision v1 writes on a primary with fresh topics and object storage.
Bring all replica-log readers up with v1 serving enabled before admitting those writes.
Each replica opens the same database incarnation from S3.
An applied Classic transaction makes the primary database's v1 branch route unavailable.
Tracked queries, page continuations and claim guards require a shared token-key vault in the runtime.

== Multi mode

The `all-backends` runtime image launches `rtdb node --multi` with the same serving driver as `rtdb dev --multi`.
Use the separate Logkeeper cluster module to supply `journal_url` unchanged.
Attach an existing Logkeeper client security group through `journal_client_security_group_id` and pass the same ID in Logkeeper's `client_security_group_ids`.
This lets both modules plan before any new security group ID exists.
Set `journal_credentials` to a map with a certificate, private key and CA selector for each node slot, starting at zero.
Issue a distinct client identity per slot and authorize each for reads and writes.
RTDB leases a credential slot for the lifetime of its process and discovers the live nodes through private DNS.
The Multi pool supports up to eight nodes, the size of a private DNS multivalue answer.

ECS mounts an IAM-restricted, KMS-encrypted EFS access point for durable database generation keys and credential slot leases.
Multi stores its immutable objects in the S3 bucket.
Supply permanent database UUIDs in `databases` to run an explicitly provisioned catalog, or use the generated UUID for the initial `xtdb` database.
Keep the same bucket, cluster name and catalog across node replacement.
See the https://github.com/bijectionhq/logkeeper/blob/896ed7818780d86e435ebf25c467ac179a1023fb/deploy/README.md[Logkeeper deployment guide] for client issuance and named credentials.

The bundled Multi configuration grants no deployment administration access.
To supply a deployment administrator, store the complete node YAML in an operator-owned secret and set `multi_configuration_secret` to its ECS Secrets Manager selector.
Use the bundled `rust/release/cluster-multi.yaml` as the starting configuration and retain the Flight listener on port 3000.
Configure the authentication provider that verifies the deployment administrator, and list its exact authenticated principal name under `deploymentAdminPrincipals`.
Use `deploymentCreatePrincipals` for identities that need only `CreateDeployment`, such as an assigned cell provisioning new databases.
The ECS execution role receives read access to the selected secret and needs access to its encryption key.

=== Consensus keeper journal

To journal through Logkeeper's consensus keepers instead of the stream keeper, set `consensus_journal` and leave `journal_url` unset.
The object supplies the commissioned encrypted EFS `file_system_arn`, a dedicated `access_point_arn`, the `mount_target_security_group_id` and an optional `file`, `journal.json` by default.
Write the keepers' client `JournalConfig` JSON to that file under the access point's root, readable by UID and GID 20000.
It lists the keepers, the catalog keeper and the placement domains, as in the Logkeeper deployment guide.
ECS mounts the access point read-only at `/run/rtdb/journal`, and the module sets `RTDB_JOURNAL_URL` to `logkeeper-consensus:///run/rtdb/journal/<file>`.
An explicit `journal_url` must name that same file.
The module allows NFS from the node security group to the mount targets and grants the node role TLS-only `ClientMount` at that access point.
Each node rereads the file every few seconds, so placement changes such as draining or retiring a keeper reach running nodes without a restart.
The per-slot `journal_credentials` and `journal_client_security_group_id` work as for the stream keeper; admit the client group on the keepers' application port.

=== Private Classic recovery relay

Set `classic_candidate_ingress` for a Multi deployment that is receiving a Classic history through its enrolled Original recovery service.
The object supplies `port`, `source_security_group_id` and `configuration_secret`.
Choose a dedicated unprivileged TCP port and give the Classic recovery tasks the named source security group with egress to the native nodes on that port.
The module opens this port directly on the private Multi nodes so the relay can follow a selected-writer redirect.
Use the `classic_candidate_relay_target` output's `entry` and `port` in the Classic recovery configuration.
Use a server name trusted by the Original relay and covered by the server certificate on every eligible native peer.
The existing Flight load balancer serves ordinary clients.

The ECS secret holds JSON with `certificate_pem`, `private_key_pem`, `approval_public_key` and `source_public_key`.
The two public Ed25519 keys use distinct 32-element JSON byte arrays.
The approval signer and Original source signer keep their private keys in their own custody.
The ECS selector gives the native task only its candidate TLS identity and the two verifier keys.
The deployment's journal client credentials keep their existing slot-based projection.

=== Private native dependent custody

Set `native_dependent_custody` to the ARN of an operator-provisioned encrypted EFS file system and its dedicated access point.
Mount `installation.json` and its mTLS certificate and private-key files under the access point's private root, using UID and GID 20000.
The profile references files under `/run/rtdb/native-dependent-custody`.
Provision mount targets in the task AZs with NFS ingress from the node security group.
The file-system policy must require TLS and restrict the node role to this access point and read-only mount access.
The task receives `ClientMount` and mounts the input directory read-only.
The commissioning owner retains write access separately.

For metadata or operator status and settlement, set `ingress.port` and `ingress.source_security_group_ids`.
The profile declares the same port and separately enrolls the permitted leaf identities and incarnation pairs.
Omit `ingress` for an observer-only profile.
The process refuses startup when the mounted profile disagrees with the deployed listener selection.
Use `native_dependent_custody_target` for the private address and enroll the certificate name on eligible selected writers.
The port has no public or ordinary Flight listener.
The custody protocol and request shapes are in link:../../../dev/doc/rtdb-custody-release-handoff.md#stock-private-custody-transport[the RTDB handoff].

=== Original private replay approvals

Set `original_private_replay_approvals` on a Multi cluster with a custom configuration to mount the independently published replay approvals at `/run/rtdb/original-private-replay`.
Use that directory for `originalPrivateReplay.approvalDirectory` and configure the independent public verifier in `originalPrivateReplay.approvalPublicKey`.
Supply the commissioned encrypted EFS file system ARN, dedicated access point ARN and mount target security group ID.
The module allows NFS from the native node group and grants the node role TLS-only `ClientMount` at that access point.
The file-system owner controls its resource policy, read-only consumer access and the separate publisher's write access.
The app reader and native writer each verify the same signed records before use.
Keep the approval signing key and application enrollment credentials outside this projection.
The order and wire for authorization, completion and disposal are in link:../../../dev/doc/rtdb-custody-release-handoff.md#mounted-original-private-replay[the RTDB handoff].
