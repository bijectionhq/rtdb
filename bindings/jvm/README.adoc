= Embedded Java and Clojure migration

This module implements `AdbcDatabase`, `AdbcConnection` and `AdbcStatement` over the Rust C ABI.
It uses JDK 25 Foreign Function and Memory calls and Arrow Java 19 C Data import/export.
It has no dependency on `xtdb-core` and does not delegate database execution to JVM code.

Set `-Dxtdb.native.library=/absolute/path/to/librtdb_ffi.dylib` on macOS, or the corresponding shared library on the host platform.
Enable native access with `--enable-native-access=ALL-UNNAMED` and Arrow's required `--add-opens=java.base/java.nio=ALL-UNNAMED`.
The native library remains loaded for the process lifetime so retained Arrow release callbacks remain callable.
The binding requires a 64-bit process.

The first ordinary `NativeDatabase.open` call captures `Boolean.getBoolean("java.util.Arrays.useLegacyMergeSort")` in a private initialization holder.
Subsequent ordinary opens reuse that selection; the overload with a final `boolean legacyMergeSort` accepts an explicit caller-captured value for each runtime.
Both enter the bounded native property transport and keep the selection immutable within the node and its query contexts.
The reference `Arrays.LegacyMergeSort` holder has its own initialization time.
If the host changed the system property after that holder initialized, the adapter's current-property capture cannot recover its earlier value; use the explicit overload with the retained reference initialization value.
The adapter does not read or expose the vector-null-check property through this transport.

[source,java]
----
try (var allocator = new RootAllocator();
     var database = NativeDatabase.open(allocator,
         "server: null\nflightSql: null\n", 512L * 1024 * 1024);
     var connection = database.connect();
     var statement = connection.createStatement("SELECT 42 AS answer");
     var result = statement.executeQuery()) {
    while (result.getReader().loadNextBatch()) {
        var batch = result.getReader().getVectorSchemaRoot();
        System.out.println(batch.contentToTSVString());
    }
}
----

The supplied Arrow allocator belongs to the caller.
Close readers, retained Arrow batches and imported vectors before closing that allocator.
Closing a statement leaves previously returned readers usable.
Closing a node cancels its readers and joins the native drivers; already retained Arrow buffers remain readable.
Ordinary session and statement calls are serialized by the caller, as required by ADBC.
`cancel()` is safe from another thread.

`xtdb.rust.AdbcDriverFactory` accepts `xtdb.config-yaml`, `xtdb.config-path` and `xtdb.native-memory-bytes`.
`NativeDatabase.openFile(allocator, path, nativeMemoryBytes)` opens the same native YAML configuration directly from a `.yaml` file.
`getServerPort()`, `getServerReadOnlyPort()`, `getFlightSqlPort()` and `getHealthzPort()` report each bound port or `-1` when absent.
The JDBC connection builder uses the read-write PostgreSQL listener when present and otherwise uses the read-only listener.
`getDatabaseNames()` and `latestCompletedTxs()` read the native catalog's open databases.
`latestCompletedTxs()` retains a null entry for each partition that has yet to complete a transaction.
`authMethodFor(user, remoteAddress)` inspects native authentication rules without opening a connection or authenticating the caller.
Only `CREATE_APPEND` bulk ingest is supported, matching the pinned embedded API.
Arrow binds are copied, including duplicate or unnamed parameter columns, so an external source allocator may close immediately after `bind` returns.
Metadata includes `getInfo`, `getObjects`, `getTableTypes` and `getTableSchema` with the standard ADBC schemas.
SQL transaction-control statements are rejected; use autocommit, commit and rollback, or the explicit native begin/commit methods.
`beginReadOnly()` and `beginWriteOnly()` have overloads for a read basis or write settings.
`setTransactionReadOnly`, `setTransactionReadWrite` and `setTransactionTimeZone` shape the transaction before its first query or write.
Null arguments to the read-only and read-write setters retain the current settings for that access mode.
`commitSyncResult()` returns the indexed key and abort information, and `commitAsyncResult()` returns the submitted transaction ID.
Both return null when there is no write transaction to submit.
`executeTx` and `submitTx` on a connection accept a list of typed transaction operations and optional `TxOptions`.
Use `SqlOperation` for parameterized SQL or `PutDocuments`, `PatchDocuments`, `DeleteDocuments` and `EraseDocuments` for documents.
Document maps can use string field names such as `_id` and values supported by the Transit request codec.
Use `NativeDatabase.executeTx` or `submitTx` to select a database for those operations.
For transaction operations expressed as Clojure documents or SQL, use `xtdb.api/execute-tx` and `xtdb.api/submit-tx`.

[source,clojure]
----
(require '[xtdb.api :as xt] '[xtdb.rust])
(with-open [allocator (org.apache.arrow.memory.RootAllocator.)
            node (xtdb.rust.NativeDatabase/open
                   allocator "server: null\nflightSql: null\n" (* 512 1024 1024))]
  (xt/execute-tx node [[:put-docs :docs {:xt/id 1 :value "native"}]])
  (xt/q node "SELECT * FROM docs"))
----

Loading `xtdb.rust` extends the existing `xtdb.protocols/Connectable` protocol onto native databases and connections.
Queries remain reducible, early reduction closes their cursor, node operations merge their await token, and connection operations reject a `:database` override.
The passive database adapter owns the merged await token; each borrowed connection owns its native transaction state.
Existing transaction-op parsing, key functions and value readers come from `xtdb-api`.
Clojure queries opened on a native database use `XTDB Clojure API` as the default application name.
Set the `:application-name` query option or use `NativeConnection.setApplicationName` on an existing connection to customize `SHOW application_name` and query trace attribution.

== Explicit compatibility boundary

The existing `Xtdb.Connection` is a concrete class tied to JVM allocator/query/catalog internals.
`NativeConnection` implements ADBC and the Clojure protocol instead of claiming binary compatibility with that class.
Java callers whose variables use `Xtdb`, `Xtdb.Connection`, `ResultCursor`, `RelationReader` or JVM `Xtdb.Config` must migrate to this module's ADBC/native API.
JVM module, authenticator, storage and log factory objects do not cross the C ABI; configure their native equivalents in YAML.
The binding rejects the `xtdb.config` factory-object option explicitly.
Existing remote JDBC, PostgreSQL, Python Flight SQL and Rust clients retain their protocol interfaces.

`NativeDatabase.open(allocator, yaml, nativeMemoryBytes, instantSource)` uses a host `InstantSource` to timestamp transaction appends on in-memory source logs.
The log records the instant at microsecond precision, sampling in append order within each log.
The callback must be safe to call concurrently across logs and finish without reentering the database.
If the source throws or supplies an instant outside the microsecond range, the append fails before it publishes a record.
The database releases the callback when close finishes.

`NativeDatabase.flushAll(timeout)` submits an explicit block flush in each open writable database and waits for indexed progress through those requests.
Each request targets the database's adopted block index at submission.
If another boundary has already advanced that index when the request is processed, the request advances source progress without cutting another block.
The timeout covers submission and waiting across all targeted databases.

The new module does not invoke Cargo from Gradle and does not build or load a native library during source preparation.
The binding tests load a separately built native library from `xtdb.native.library`.
The native CI job builds the library and runs both binding test tasks against it.
The Clojure suite invokes the original query-tail, duration literal, null-or-missing UNNEST, and declared-column extrema test bodies with a fresh `NativeDatabase`.

=== SQL parser errors

The JVM parser can attach a live ANTLR `RecognitionException` to a SQL error.
The cause can expose the recognizer, token stream and, for some errors, dead-end configurations.
Parses of the same JVM parser class share the recognizer's decision DFA objects.
The embedded native API treats a SQL error as a diagnostic value.
`NativeException.getCause()` returns null, and Clojure anomaly wrapping preserves diagnostic values in the cause chain.

Java callers can replace exception-cause inspection with `NativeException.category()`, `code()`, `getMessage()` and `transit()`, or read the corresponding ADBC error details.
Clojure callers can match `:cognitect.anomalies/category` and `:xtdb.error/code` in `ex-data` and read the message with `ex-message`.
For syntax errors, Java exposes the strings `incorrect` and `xtdb/sql-error`, and Clojure exposes the keywords `:cognitect.anomalies/incorrect` and `:xtdb/sql-error`.

Tools that traverse recognizers or alter decision DFAs and configurations need to remove that dependency from embedded native calls before migrating.
Keep JVM-specific parser inspection in separate tooling using the original JVM parser and pass diagnostic values to the application.
Applications that depend on changing parser state to alter later parses need to remove that behavior before switching engines.

`NativeException.getMessage()` preserves an absent native diagnostic message as Java null and an empty message as an empty string.
The Clojure bridge retains that distinction when reading the diagnostic Transit payload.
The embedded Clojure API carries OID, REGCLASS and REGPROC values as typed Transit values using their Arrow extension names as tags.
Native requests preserve the JVM numeric widths of Byte, Short, Integer and Float in transaction documents and query arguments.

The embedded native connection accepts logical relation EDN with named Transit arguments on its normal read basis.
The logical relation cursor exposes its declared result types through the Arrow schema, independently of row availability.
Logical scans bind to the awaited database snapshot and accept stored column symbols, scan predicates, and valid-time and system-time filters.
Logical relation output preserves operator page boundaries, and a literal page source supplies its pages in the specified order, including empty pages.
The Clojure logical relation options `:explain?` and `:explain-analyze?` request the native plan or measured execution respectively.
The native EDN statement form is `[:explain {:mode :plan} relation]` or `[:explain {:mode :analyze} relation]`.
SQL and logical relation requests use the same transaction settings for the snapshot token, snapshot time, query clock, and time zone.
Literal pages can declare their Arrow column types when the pages do not carry enough rows to infer a schema.
Logical group-by uses native aggregates with exact column symbols, including distinct factories, filters, and array ordering.
Ordered-set percentiles use the native continuous or discrete aggregate with literal or parameter fractions.
Logical joins bind each equijoin expression to its own input and run the native cross, inner, outer, semi, anti, or single join.
Logical mark joins apply eligibility conditions before evaluating the three-valued mark across each probe row's candidates.
Logical apply binds each probe row's values in a lexical scope for the dependent relation, including when a nested apply shadows a parameter.
Logical let bindings expose a materialized relation to each reference in their lexical scope and retain its page boundaries.
Logical row numbering can count across a relation or restart at each operator page.
Logical windows bind named partition and ordering specifications for row number, lead, and lag.
Logical sort and limit accept named or positional arguments and keep the boundaries of the retained input pages when ordering is absent.
Logical list sources stream their elements in configurable pages, and logical unnest expands list or set elements with optional per-row ordinality.
Native logical relation tests run with the original Clojure assertions and the native relation cursor.
