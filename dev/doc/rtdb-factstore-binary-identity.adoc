= FactStore Binary identity cutover

This is the private RTDB source contract for Bijection's FactStore adapter.
The initial Bijection caller inventory was read at main commit `ec376fb543478a96ec8399f6014e9aed3ac0cbc1`.
The applied confirmation, unique window and World archive callers were traced at Bijection main commit `8083ed015a0428fcd375f660fb8ad631a5d1da92`.

== Address bytes

Use the complete canonical `AddressRef::encode()` as a non-null Arrow `Binary` `_id`.
Preserve the custody check in `AddressRef::to_wire()` by requiring current native custody before emitting those bytes.
The image includes the address kind, table incarnation and escaped complete key.
Decode a returned fact identity with `AddressRef::decode` and validate the expected table and canonical image at the caller boundary.
Construct seek boundaries with the same binary order-image writer and original boundary extent, including synthetic prefix successors from `wire_order_boundary`.
The ordering is unsigned lexicographic, with a shorter prefix before its extensions.

RTDB uses `EntityId::Binary(Vec<u8>)`, `EntityIdRef::Binary(&[u8])` and `Value::Binary` in owned paths.
In a wire component that explicitly expects a complete typed handle, Binary uses tag byte `04` followed by the unmodified identity bytes.
The enclosing component supplies its existing length framing.
The IID is the first 16 bytes of SHA-256 over ASCII `b` followed by the identity bytes.
The IID routes to a bucket and the full typed key identifies the assertion within it.
Arrow `_id` cells and compact Binary point/window entries carry the identity bytes directly.
The typed-handle tag belongs only in handle components, including regional change bounds and expiry candidates.
In those regional bound components a zero-length handle still denotes an unbounded side.

Provision the Binary fact relations against a clear physical cut.
An existing Utf8 key and a Binary key occupy separate identities.
The Binary scan profile requires a Binary identity column at the selected cut.
Bijection should keep the existing Utf8 path names, control and catalog IDs, publication heads, attempt IDs and protected row and World-slot IDs.
Root protected shared-column carriers have a separate Binary contract below.
Public pgwire accepts the existing text, keyword, signed integer and UUID entity identities.

== Request and response mapping

* For `Create.v1`, `Commit.v1`, `Commit.v2`, `CommitOrdered.v1` and hosted/import/restore groups, put Binary in the existing Arrow `_id` field for fact rows.
  The point condition fields, operation names, schedule, deadlines and row or group order are identical.
  A batch with a text control row and a Binary fact row can use the corresponding typed legs when its existing operation layout admits a dense union.
* Scalar Root and world points, positioned points, valid-window and version requests send Binary in the existing Arrow `_id`.
  Keep the requested valid and system coordinates and the 16-byte original event position independently of the identity.
  A returned position remains the signed big-endian i64 transaction followed by the unsigned big-endian u64 event ordinal.
* `ReadPoints.v1` and `ReadRanges.v1` retain their scalar selectors, framing, per-entry results and first scalar refusal.
  `ReadSelection.v1` selector 9 is the Binary form of selector 0, selector 10 is the Binary form of selector 1, and selector 11 is the Binary form of selector 8.
  A compact Binary point is the 16-byte held handle, the length-prefixed relation, the signed big-endian i64 valid instant and raw address bytes to the end of the entry.
  A compact Binary window follows the relation with the signed big-endian i64 system time, valid start and valid end, then raw address bytes.
  The batch count and each selector and length use the existing framing.
* `ReadHeldAbsentKeys.v1` accepts one plain Binary column and keeps the common valid instant, original order and leading absence count.
  The held identity page, all-valid page and world identity page actions select the key type from the Arrow type of the nullable exclusive `after` column.
  Send a typed Binary null on the first page and the last returned raw Binary `_id` thereafter.
  The reply remains Binary on empty pages, and the all-valid page collapses repeated validity slices of the same identity.
* Ordered point and range bounds, continuations and fixed range evidence use Binary for the terminal `_id` of a fact key.
  Other tuple columns retain their declared types.
  If a completely empty ordered relation requires a concrete Binary reply layout, supply a typed key bound that establishes the identity type.
  The held ordered, historical, overlay and replay paths use the same complete-key order.
* Change touches and ranked or spatial identity unions include a Binary leg after their existing legs.
  Decode the selected Arrow child by type and retain its full bytes in each touch or hit.
  Staged search and nearest overlays and spatial gathers accept Binary in their existing `_id` cells.
  Expiry's nomination remains opaque text and its `identity` column carries the complete typed handle.
* Source replay stores Arrow Binary facts and typed Binary operation operands, with the existing validity, presence and operation positions.
  Archive effects and residues keep their original origin and exact event coordinates.
  Replay validates the Binary put cell against its stored complete typed handle.
  Replay constraint member receipts keep the Utf8 member key and use holder marker `02` followed by the existing big-endian u64 length and raw bytes for a Binary holder.
  Where a prepared Sample membership exclusion names a Binary identity, send SHA-256 of byte `ff` followed by the raw identity payload in the existing sorted digest list.

== Applied confirmation

In Bijection's `owned_flight.rs`, update `AppliedPointCheck` and `HeldRead::confirm_applied_hosted_read` to send flag `02` for a Binary fact point.
After the relation prefix send a big-endian u16 equal to `1 + address_bytes.len()`, tag byte `04` and the raw canonical address bytes.
The raw address payload is 1 to 4096 bytes.
Send the original signed i64 valid instant and the existing absence byte or presence byte with the original signed i64 revision and 16-byte event position.
Keep flag `00` for no point and flag `01` with a raw Utf8 key for publication markers and other text points.
The floor, deadline, following hosted control groups and confirmation reply keep their existing framing.

== Protected shared-column carriers

Provision `fact_unit_shared_column_carriers` in the installed Root schema with explicit validity, no lifetime, and one required non-null `opaque_binary` field named `sealed_payload`.
Write complete Arrow Binary IDs to this relation and keep Root winner selector IDs, ordinary protected-row carrier IDs and World carrier slots in `fact_unit_column_payloads` as Utf8.
The shared-column carrier prefix is 106 bytes: ASCII `BFCP2`, history (16), unit alias (32), tablet (16), payload part (1), field (16), column (16) and generation (4, big endian).
The full 4202-byte ID appends the complete 4096-byte opaque image.
Arrow and compact point operands use the raw ID, and components that require the complete typed handle prepend byte `04`.
Treat the bytes as a scoped opaque identity throughout the client and archive, including when checking original membership, ciphertext context and erasure.

Use `rtdb.owned.ReadHeldProtectedCarrierCoverage.v2` and `rtdb.owned.ReadHeldProtectedCarrierPage.v2` with the existing Root hold handle, length-prefixed relation name and one-row Arrow request.
Send a non-null Binary `prefix` to both, and a nullable Binary `after` and Int64 `limit` (1 to 64) to the page.
Use a Binary null on the first page and the full last Binary `_id` as the exclusive bound on the next page.
Page replies carry a Binary `_id` column even when empty, with the existing more flag and a range witness on completion.
Coverage returns the existing Base64-encoded 72-byte stamp and nonce, with data and purge frontiers from the new relation.
The stamp contains the original placement scope (40 bytes), attached database equality epoch (16 bytes), and the signed big-endian data and purge frontiers (8 bytes each).
The final-count operand on the existing `protected_membership` condition is byte `02`, the raw 106-byte prefix, and the existing 64 ASCII lowercase hex bytes of the unit fence ID.
The existing row-membership operand starts with byte `00`.

World census and pinned parent point details are in xref:rtdb-assertion-families.md[Assertion families].
Bijection must provision the split relations before opening new-format holds and update the carrier, locator, winner body, retained ciphertext binding and replay or retirement records together.
Restore must validate the exact original scope and use the original event positions and full typed handle when replaying puts, residues and admitted purges.
Switch only from an empty shared-carrier population or a paired cutover that accounts for every provider and retained cut before serving v2.
The v2 receiver has no hex carrier reader.

The shared-carrier retirement caller submits its current carrier check, erase and create-only receipt through `DecideHosted.v4` with its installed writer checks.
The live admission verifies the complete Binary carrier and ciphertext, its original ordered membership and the later unit fence against the same predecessor before applying the erase and receipt together.
Original replay still uses its archive admission.
The sealed search inventory caller invokes the protected-carrier page against `fact_sealed_search_unit_rows`, outside the protected-carrier page's installed relation scope even in v1.
The paired integration needs a scoped inventory read before publishing the live retirement path.

== Unique window replies

In `owned_flight.rs`, update `HeldRead::unique_window` to admit `_id` as the standard dense Arrow identity union, including on the empty response schema.
The union has type IDs 0 through 4 for Utf8, Keyword, Int64, UUID and Binary respectively.
In `fact_points/ordered.rs`, update `unique_window_projection` to select the active child and its value offset for each row.
For a Binary fact route require the Binary child and decode its raw bytes with `AddressRef::decode`.
Keep validating the expected table, complete claim key and clipped interval, and retain the caller's overlap checks.
The request, reply's remaining Binary `key` and two Int64 validity columns, and held witness metadata keep their existing framing.

== Archived World shadows

In Bijection's `recovery/owned_archive/catalog/proposals.rs`, make `WorldEffects::finish` emit ASCII `BJWP8` for every nonempty private World effects body.
This is the sole accepted header for this Bijection-private replay body.
In `require_overlay`, replace the `owned_string_id()` frame with the validated original complete `_entity_key` handle from `recovery/owned_archive/events.rs`.
Validate the handle against the original IID and the active Arrow `_id` cell before copying the shadow.
For ordinary facts send `04` followed by the exact Binary identity.
For text control or carrier rows send `00` followed by the existing Utf8 bytes.
The existing big-endian u32 frame length includes the tag.
The frame follows the original u32 assertion position, 16-byte World ID, and length-prefixed text relation name.
The signed i64 validity endpoints, field count or tombstone marker, subsequent field frames, omitted positions, topology and assertion-line evidence keep their existing encoding.
Replay uses the same original ordinal on the destination transaction and still refuses duplicate or unqualified positions.
The `BJWP8` header governs the private restore operand.
Already resolved replicas carry their own typed entity keys and replay through the ordinary replica format.

== Bijection source work

* Carry typed keys through `crates/native_store_runtime/src/rtdb/fact_points.rs` and `fact_points/write_runs.rs`, including `FactHeader`, `FactRun`, boxed or packed `Entry` rows, reposting, and the shared point builders.
* Update `fact_points/history.rs`, `worlds.rs` and `worlds/period_batch.rs`, `store/diff.rs`, `store/expiry.rs`, and `changes.rs` to send and consume Binary on fact routes.
  Preserve exact cut selection, request-order duplicates, same-identity interval behavior, and failure propagation through `owned_flight` scalar and batch dispatch.
* Update `fact_points/ordered.rs`, `ordered/checkpoint.rs`, and `ordered/proposal.rs` for typed terminal keys, binary bounds, cursors, posting builders and staged overlays.
  Update `fact_points/search.rs` and spatial or vector request builders where they carry ordinary fact identities.
* Update `owned_flight` IPC decoders, archived source capture and restore in `rtdb/recovery/owned_archive`, and typed expiry and Changes decoders.
  Preserve the origin coordinates, full handle versus raw Arrow identity distinction, and the text formats of unrelated owner records.
* Keep text serialization for references and controls that use it in their own format.
  Replace the fact identity's hex read and write paths together in the Bijection caller migration.

The Rust domain, source replay and Flight wire regressions were authored with this change and left unexecuted.
