= Kafka Connect transform class names

Each `transforms.<alias>.type` value names a concrete transform by its fully qualified, case-sensitive Java binary name.
The assignment uses the native factory registered for that exact name when one exists.
Otherwise it looks up the name among the built-in Kafka transforms.

The built-in classes use the package `org.apache.kafka.connect.transforms`.
These ten transform families require `$Key` or `$Value` after the class name to select the part of the record to transform.

* `Cast`, `ExtractField`, `Flatten`, `HeaderFrom`, `HoistField`
* `InsertField`, `MaskField`, `ReplaceField`, `SetSchemaMetadata`, `TimestampConverter`

For example, `org.apache.kafka.connect.transforms.ExtractField$Value` extracts a field from the record value.
The six whole-record classes are `DropHeaders`, `Filter`, `InsertHeader`, `RegexRouter`, `TimestampRouter` and `ValueToKey`.
Adding `$Key` or `$Value` to one of these names fails built-in lookup with `xtdb.kafka-connect-source/plugin-class-not-found` before the transform validates its options.

The Kotlin loader passes the configured name directly to `Class.forName`, checks that it implements `Transformation` and calls its no-argument constructor.
Bare names of the ten key/value families identify abstract classes and fail at construction on the JVM.
The native dispatcher also rejects these bare names and reports `plugin-class-not-found`.

== Assignment startup

The assignment opens every referenced predicate before it opens any transform.
It visits predicate aliases in the order transforms first refer to them, shares each predicate across its steps and skips unused predicates.
It then opens the transforms in declaration order.
A predicate class or configuration error therefore reaches the caller before any transform factory runs.

After a startup failure, the assignment releases already-opened transforms in reverse step order, then predicates in reverse first-use order.
Dropping a completed chain releases transforms in step order, followed by predicates in first-use order.
Steps that share a predicate alias use the same instance and release it once.
Native plugins run their Rust destructors on the caller, and these cleanup orders apply when the destructors return normally.
