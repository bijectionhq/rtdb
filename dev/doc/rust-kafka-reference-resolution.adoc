= Rust Schema Registry reference resolution

The native Connect registry converter resolves reference lists depth-first in source order.
Each reference version lookup completes before its name is checked against the visited set.
The resolver marks a new name before descending and appends that schema's text after its dependencies.
The first visit determines the schema retained for a name.
Cycles and duplicate names still demand their version lookup but do not descend again.
Avro receives reference texts in this dependency insertion order before the root text.
JSON Schema continues to receive a name-indexed map.
Protobuf resolves imports by the registered reference name and validates that references contain Protobuf schemas.
The Protobuf compiler also resolves Confluent logical-type declarations and the Google types bundled with the reference converter.

Reference requests use the supplied signed version and `deleted=true`.
A requested version of `-1` is replaced in the containing reference by the fetched response's version before duplicate detection.
A missing response version remains null and is omitted from subsequent lookup-body serialization.
Zero and negative returned versions retain their values.
Missing or null whole reference lists normalize to empty lists.
Individual null entries remain in source order and fail only when their edge is demanded, after any earlier valid fetches.
A duplicate fetched schema's null entries are not demanded when its descent is skipped.
Missing reference names, subjects, or versions fail when their edge is reached.
Empty names and subjects remain distinct from missing values.

The initial provider root has no parent subject, independently of the application subject-name strategy.
A fetched schema's response subject supplies the parent context for its children.
Default-tenant qualification affects only the version-request URI; the original reference subject remains in the document.
For example, parent `:.ctx:parent` and child `child` request `:.ctx:child`.
The explicit default-context child `:.:child` under that parent requests `:.ctx::.:child`; with no parent it requests `child`.
Fetched subject/version metadata belongs to a separate response envelope and cannot enter the subject-version POST body.
Reference resolution and version replacement precede that POST, which uses `normalize=false` and `deleted=true`.
An empty root reference list is omitted from the POST body under the source NON_EMPTY policy.

== Protobuf writer and reader selection

The Confluent payload prefixes the message with its Registry schema ID and a ZigZag varint path through that schema's declared messages.
The path drives record-based subject naming and selects the writer descriptor.
The default topic-based subject can reuse a writer document for every message in the schema.
When reader selection is configured, the selected Registry schema supplies the Connect version and the reader descriptor.
Projection caches hold their descriptor or schema reservation for as long as the entry is live.

The bundled Google common type schemas under `connect/registry/protobuf/google` come from the Apache-2.0 `com.google.api.grpc:proto-google-common-protos:2.22.1` artifact used by Confluent Schema Registry 7.8.0.
The artifact SHA-256 is `b0642455c9b3fbbf9bd805c3a31bdaf865b5f1d3b535df5874219e5eeaf75c37`.

== Ownership and admission

The converter remains passive and completes resolution on its caller without creating a task.
One call-local frame vector owns the active depth-first path and one visited set records completed or active names.
The immutable `ResolvedReferences` value publishes its indexed texts and ordered names together.
Document equivalence includes their order.
A completed intermediate value carries the updated root and references until subject-version lookup supplies the document's application version.

Initial frame storage and each reference step are admitted before their native allocations.
The checked step bound includes text copies, map nodes, request overhead, and three slots per frame and ordered name.
Three slots cover geometric vector reallocation with old and new buffers simultaneously live.
The completed document separately charges retained map nodes, string capacities, and ordered-vector storage.
Root reference-vector capacity uses the full nullable slot size, including null entries and spare capacity, and optional string capacities remain charged even when nullable version replacement makes their serialized entries empty.
Metadata and rule JSON containers retain explicit heap bounds, and serialized size is measured with a passive counting sink without creating an output buffer.
Each typed reference-vector conversion admits three nullable slots per input array element before deserialization, including null members and geometric growth overlap.
The shared nullable-list decoder creates no intermediate vector; missing and null lists require no vector allocation.
The reference-count limit is the available budget; response byte limits remain in force.
Cancellation and errors drop partial graph data, while the conversion context retains its reservation charges until that context drops.
Published documents retain their own lease after the context is released.

== Remaining qualification

This source implementation covers reference-resolution order, nullable list and entry demand, nullable version replacement, subject contexts, and their ownership boundaries.
Persistent fetched-version cache semantics remain separate work.
The native subject-version lookup still precedes semantic schema/reader/datum work that Java performs before that lookup.
Parsed schema ownership, canonical and other empty-field POST serialization, semantic record subject names and Jackson response coercions still require source integration.
The shared request path also retains UTF8 URL encoding and URL dot-segment handling that differ from Java's UTF16 URI encoder.
Generic response JSON parse admission remains separate from the typed vector admission above.
No runtime compatibility or Phase 1 completeness claim follows from this bounded change.
Its HTTP, error-order, identity, context, and memory regression sources first execute in Phase 2 under the implementation handoff.
