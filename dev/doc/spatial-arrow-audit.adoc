= Arrow serialization audit

This inventory follows the native geospatial path from Bijection's clear Root invocation through RTDB's owned actions, primary pages, spatial postings, and held result pages.

[cols="1,2,2",options="header"]
|===
| Path | Avoidable conversion | Current path

| Bijection spatial schema authoring
| The current table builder could not declare a spatial path from the SDK.
| The SDK exports the native geometry field validator independently of the `spatialIndex` recipe.
Adding the recipe to an installed eligible table keeps the validator and the stored geometry carrier fixed, so Root publication can stage and backfill the new path.

| Bijection write admission

|===

Arrow IPC provides the Flight and persisted posting representations.
IPC decompression and alignment, legacy metadata normalization, and ordered gathering can allocate buffers for their physical layouts.
The geometry kernel consumes the geometry carrier for coverings and exact predicates.
Bijection converts application values at its API boundary and preserves their canonical images for document semantics.
Owned action headers carry authorization, framing, and held-read controls.

== Remaining control-plane conversions

Bijection's `schema_predecessor` and `open_root_facts` read the installed owner, schema digest, and relation inventory over PostgreSQL before staging or opening deploy hooks.
`read_accepted_layouts` receives row records and decodes each declaration body in that transaction.
The Arrow hosted-control point action can read one declared key at a held cut.
The preparation path still needs a held Arrow inventory that returns all active declarations under the same owner and program observation.

Ordinary hosted Flight holds and ordered commits call Bijection's PostgreSQL source verifier before advancing their retained source position.
The verifier reads `SHOW rtdb_hosted_source_barrier` as text and checks the returned position, writer claim, and previously retained positions against `xt.txs` in a read transaction.
A Flight replacement must certify the same source history and exact transaction ID and system-time pairs before advancing the retained frontier.

== Bijection and RTDB Flight integration tests

`rust/conformance/run_hosted_spatial_pair.py` starts isolated standalone and placed RTDB databases and uses a loopback TLS relay for the Bijection client.
Give it the `rtdb-flight-sql` `flight` integration test executable and the Bijection `native_store_runtime` library test executable, in that order.
The standalone test checks held pagination, empty and projected results, nearest distance ties, and visibility across concurrent replacement and delete.
The placed test checks durable postings over pre-existing data, a concurrent replacement, refusal before readiness, and one commit for the program and hook write.
