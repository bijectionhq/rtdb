= Arrow serialization audit

This inventory follows the native geospatial path from Bijection's clear Root invocation through RTDB's owned actions, primary pages, spatial postings, and held result pages.

[cols="1,2,2",options="header"]
|===
| Path | Avoidable conversion | Current path

| Bijection write admission
| The admission check serialized admitted geometry to WKB and discarded the bytes.
| Admission checks the geometry model.
The writer appends WKB into the location carrier after its tag and optional position accuracy.

| Bijection spatial pagination
| Every page encoded the same query geometry and canonical scalar partition values and rebuilt Arrow filters.
| The first page sends the Arrow filter and the held read retains the parsed region.
Continuation actions carry the filter capability, complete identity, bound, and observation flag.
Older wire versions accept their original stateless Arrow requests.

| Spatial Flight request decode
| The stream reader copied each message body into a new allocation after Flight had already received it.
| The decoder retains the received allocation and reads messages from buffer slices.

| Held exact-key lookup
| The handler converted a binary key and its valid-time parameter through a generic document map.
| It reads the valid time directly and decodes the selected identity cell.

| RTDB partition refinement
| The action cloned the region and partition values, and the scan cloned partition bytes into scalar expression values.
| The request borrows the Arrow cells and compares the partition columns on the resolved Arrow row.

| RTDB spatial posting build
| Covering keys and IIDs accumulated in row records before conversion to Arrow for IPC.
| The lane appends directly to typed Arrow columns and sorts row positions, then gathers each persisted page in order.

| RTDB held and maintenance path catalog
| The catalog reader materialized generic values and a list tree to resolve the spatial definition.
| It reads the path name, table, columns, and generation from typed Arrow cells.

| RTDB spatial posting read
| The file reader copied individual page bodies from the cached IPC allocation.
| Validated page ranges become Arrow buffer slices of the existing cache lease.

| RTDB held document projection
| The scan selected a separate one-row document batch for each provisional hit and copied those rows again into the result.
| Selection retains the source pages and winning positions.
Identity-only and document responses gather the final Arrow row positions.
The response reuses the identifier buffers when their layout conforms to the existing wire schema.
The legacy full-document action carries the identity in both locations defined by that version.

| RTDB held document transport
| Full document replies gathered and serialized geometry and index carriers that Bijection discarded on receipt.
| Bijection prepares the document columns from its held layout, and the projected Flight action gathers just those columns, identity, and revision.
Refinement reads its geometry and partition columns from the held Arrow pages.
An unrestricted projected read skips the geometry column unless the client requests it.
The projected reply carries the identity once and associates the document by its Arrow row position.

| Bijection held reply decode
| Message decoding copied the returned IPC body, and document identity checks and pagination re-encoded the received addresses.
| The decoder consumes the owned reply buffer, and the spatial page validates and reuses the original canonical address text.
| Clear Root geometry writes
| Create and commit converted geometry and partition columns to document maps before rebuilding the source Arrow vectors.
| Compatible payload columns pass from the upload through source IPC and ordered resolution into the Arrow event batch.
Transaction resolution still orders admission, locality, and final-state checks.

| Spatial path declaration and removal
| Declaration and catalog checks materialized generic row and list values for path names and columns.
| They read the text and list cells directly and build typed ordered control operations.

| Unindexed trie fallback
| An admitted page can borrow a large cache allocation for a small selection.
| Copying a selected page can release the rest of that allocation.
Posting files retain bounded Arrow buffer slices.
|===

Arrow IPC provides the Flight and persisted posting representations.
IPC decompression and alignment, legacy metadata normalization, and ordered gathering can allocate buffers for their physical layouts.
The geometry kernel consumes the geometry carrier for coverings and exact predicates.
Bijection converts application values at its API boundary and preserves their canonical images for document semantics.
Owned action headers carry authorization, framing, and held-read controls.
