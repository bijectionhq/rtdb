= Columnar values and retained pages

Columnar builders and readers are passive call-owned transforms.
`OwnedBatch`, `OwnedColumn`, and cloned Arrow arrays retain their allocation reservations independently of the query cursor.
`MemoryBudget` and `MemoryReservation` re-export the shared byte-admission types from `rtdb-types`.
Schema codecs preserve native logical types and the full signed decimal precision and scale at external boundaries.
Struct and list builders validate physical child validity through checked `ArrayData`, preserving bottom fields and explicit union NULL legs.

Execution admission uses `execution_type`, `execution_field_type`, `admit_execution_value`, and `read_execution_value`.
Unsigned integer storage is read as the signed integer of the same width, including nested cells, matching the pinned Arrow vector opener.
The in-place value adapter preserves integer bits and existing allocations.
The type adapter retains nullability and child encodings and joins union legs that become equal.
Raw `from_field` and `read_value` preserve physical types and values for IPC, source payloads, durable artifacts, and inspection.
Callers apply admission to domain values entering execution; spill sequence numbers and group identities retain their unsigned representation.
Calendar objects entering `admit_execution_value` or `build_array` use the reference vector object writer's day truncation and millisecond multiplication rules.
`copy_array` and semantic vector hashes reject unadmitted calendar objects, including nested cells.
Expression evaluation applies its checked day narrowing before handing completed values to these stored-cell surfaces.

`DeclaredBatch` retains a wire schema and a page conformed to that schema's physical layout.
`conform_batch` reserves schema work, decoded values, and builders before allocating them.
It preserves integer bits and exact decimal metadata, fills nullable missing fields, and rejects fields outside the target layout.
Adaptation preserves declared nested field order, child names, metadata and dense union type IDs.
Set and timestamp-range extensions retain their declared child layouts while validating the extension's storage container.
Signed execution integers conform to a same-width unsigned declared field by retaining their buffer bits under the declared physical type.
Named union admission still requires a matching declared leg.
Single typed columns are wrapped in declared unions, and nullable rows select the union's NULL leg.
Exact-schema pages pass through with their original physical layout.
Present NULL values can promote physical field nullability while the declared wire flags stay unchanged, following `core/src/main/kotlin/xtdb/arrow/ConformingUnloader.kt`.
The internal RecordBatch uses checked constructors; Flight IPC and C exports supply the separate declared schema.
This adapter's source tests cover null promotion, nested layouts, union remapping, column order, retained memory, missing required columns and decimal metadata mismatch.
All compilation, execution, and cross-runtime qualification remain pending.

URI object writes and reads validate Java URI syntax while retaining the original UTF-8 spelling and extension layout.
`tests/uri.rs` covers invalid stored spellings and object inputs as unexecuted regression source.

== Private scalar write and copy foundation

The crate-private `ScalarWriter` is a single-writer transient whose completed native storage is consumed into an `ExecutionVector`.
It supports Null, Boolean, fixed-width and variable-width storage, including the concrete primitive and byte methods admitted by scalar extension wrappers.

`ScalarReader` borrows the transient for primitive and byte reads; Rust borrowing excludes mutation while that reader is used.

Logical row admission remains separate from initialized byte-span admission.
A native buffer owns and charges its explicitly initialized extent, including zeroed growth from the source's minimum-128/doubling schedule.
SDK reads remain confined to their retained buffer slices.

Logical row count, byte/bit append positions and initialized extent are retained separately.
`ensure_capacity` and setters can create logical rows without advancing append positions.
Fixed setters widen their index before applying the setter stride.
Capacity requests, primitive getter strides, pointer spans, fixed copier products and variable offset reads preserve the source's wrapping i32 arithmetic.

`set_null` extends count where required and changes existing validity without promoting a nonnullable vector or clearing its payload.

This is an internal scalar kernel, not a universal recursive copier or a resource-only transport format.

== Source Null and Int initial counts

`ScalarWriter::source_null` and `VectorWriter::source_null` retain any signed i32 initial count, including negative values, with no data or validity allocation.
Their native descriptor retains the Null constructor class, name and nullability; the logical type is Nothing when nonnullable and Null when nullable.
Count wrapping, signed capacity maxima and nullable promotion use the existing scalar kernels.
Null promotion admits complete replacement metadata before installation and never allocates a bitmap.

`source_int_arrow19_default` on either writer opens a concrete I32 scalar under Arrow Java 19's stock default allocation profile and enabled bounds checks.
The profile uses page size 8192, max order 11 and a 16 MiB rounding threshold.
The constructor computes its data request as the initial count widened to i64 and multiplied by four.
A negative request produces `ReferenceFailure::NegativeAllocationSize` before metadata, allocation or validity work.
Zero returns empty storage before rounding; a positive request below 16 MiB rounds to a power of two, with a one-byte request rounding to two bytes, and requests at or above the threshold remain unchanged.
The retained capacity is ArrowBuf's exposed rounded request, independently of any larger private allocator chunk.
The data buffer is allocated and fully zeroed before the optional validity buffer is allocated and zeroed.
All data, validity-bit and validity-byte append cursors start at zero independently of the initial count.
For initial count one, data capacity is four bytes and nullable validity capacity is two bytes.
A checked long setter at row zero therefore fails after any validity-bit publication, while the logical count and append cursors stay unchanged.
The first Int append writes data at byte zero, writes validity at the initial logical row and increments that count last.
Subsequent growth retains the existing 128-byte minimum and doubling schedule; initial constructor allocation has its own capacity rule.

One passive `CountScalarMetadata` value retains the closed Null or default-profile Int class with derived field, logical metadata and a trailing header reservation.
The scalar owner holds that complete value after its count, validity and data fields; its payload leases outlive their allocations.
Initial positive buffer allocation reserves native extent and overhead before fallible allocation, while validity admission overlaps the live data and metadata leases.
A constructor failure releases all unpublished regions and returns no writer.
Both writer entry points construct the same passive `ScalarState` under their one existing publication gate.
Descriptor-based construction rebuilds metadata in the target budget and starts a fresh zero count with empty buffers and zero cursors; it does not replay the former initial count or capacity.
Promotion replaces the whole metadata value with overlapping admission before validity work.
Typed capture consumes that metadata and closed Null or Int payload into native provenance without imposing count-derived payload coverage.
Snapshots retain the actual descriptor, count, capacities and cursors through their existing leases.
The four parameterized `SourceScalarDeclaration` cases and strict SDK construction remain separate.

`SourceBytePointer::from_int_arrow19_default` requires the retained Int constructor class under a direct native reader with identity addressing.
The mutable scalar `source_int_pointer` bridge also permits inspection of a `NativeAborted` prefix without changing its gate.
Pointer formation retains a signed wrapped i32 row-times-four offset and length four without checking count, validity or payload span.
Only `demand_native` admits the retained bytes; facts and demanded bytes borrow the actual owner and expose no raw address or mutable alias.
Rounded padding can therefore be demanded through this source pointer path even when the ordinary checked cell boundary rejects that logical row.
An Int-produced pointer can supply the slot retargeted by a direct source scalar reader or first signed Slice.
Int source getBytes, primitive null/NPE/object/metadata reads, mutable aliases and retargeting from an Int reader remain outside this byte-fact surface.
Native scalar copying continues to demand actual retained spans and validity in source order; admitted SDK arrays keep their strict row and range boundary.

== Childless Time factory dispatch

`ScalarWriter::source_time_factory` and `VectorWriter::source_time_factory` implement the childless factory branch for concrete stored-parameter Arrow Java 19 Time types with a nonnull native name.
SECOND and MILLISECOND select the actual Time32 class; MICROSECOND and NANOSECOND select Time64.
The factory ignores every signed i32 declared width and derives its field, logical metadata and physical width from that selected class.
A SECOND input declaring width 64 therefore writes four-byte lanes, while a MICROSECOND input declaring width 32 writes eight-byte lanes.
Direct source Time declarations retain their explicit class and unit independently of this factory normalization.
A null unit preserves the source message-less NullPointerException producer as `ReferenceFailure::AbsentTimeUnit` before metadata or buffer admission.
This outcome has no implicit anomaly conversion.
Strict SDK field and logical validation continue rejecting mismatched Time unit/width pairs.

Both factory entry points call the same private scalar constructor under their existing single publication gate.
The constructor admits one complete `SourceScalarMetadata` value, followed by empty validity and data buffers with count and all cursors zero.
Construction and empty consuming capture share that one metadata lease; the factory creates no intermediate descriptor or second metadata reservation.
The existing parameterized descriptor origin, common write and copy kernels, nullable promotion, typed native capture, snapshots and descriptor rebuilds retain the actual selected declaration.
Time32 long writes narrow before appending four bytes; Time64 long writes append eight bytes and its Int writer remains unsupported.
Existing source byte readers expose pointer facts and delayed native demand, while Time getBytes stays unsupported.
Existing checked primitive and object reader boundaries remain separate.
