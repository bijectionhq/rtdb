= Native embedded ABI

Bound Arrow arguments retain raw imported fields and cells until query or DML admission.
Execution uses signed integer widths for unsigned storage and preserves field types for nulls and empty containers.
Bulk ingestion applies the same cell admission before constructing logical documents.

`rtdb-ffi` exports the versioned blocking C interface in `include/rtdb.h`.
It opens the Rust server composition, including configured storage, logs, authentication, source ingestion and listeners.
For an embedded node without network listeners, set `server: null` and `flightSql: null` in the native YAML configuration.
`all-backends` enables the native backend features exposed by `rtdb-server`.

`rtdb_v1_database_open` selects the default TimSort object sorter.
The additive `rtdb_v1_database_open_with_properties` entry accepts a borrowed UTF-8 JSON object of string values, limited to 4096 bytes, under the startup allocation budget.
Only `java.util.Arrays.useLegacyMergeSort` is accepted; duplicate keys use their last value, case-insensitive `true` enables legacy sorting, and other strings select TimSort without trimming.
Unknown names, nonstring values, malformed JSON, oversized input and exhausted startup memory fail before node resources open.
The resolved selection remains immutable through the native node's lifetime.
This entry does not read JVM properties; an embedded host supplies the value it captured for the reference lifetime it is matching.

`rtdb_v1_database_open_with_log_clock` accepts the same properties and a host callback for in-memory and local source transaction timestamps.
The callback supplies epoch seconds and a nanosecond fraction, which the log records at microsecond precision.
A rejected or invalid clock reading leaves the source log position available for a later append.
The host retains the callback and its context until database close joins admitted operations and drivers.

All operations use the native session, SQL preparation, query cursor and transaction resolver.
The library does not load the JVM database implementation.
The JVM adapter is in `bindings/jvm`; existing Python PostgreSQL/Flight clients and `lang/rust` remain external clients.

== Ownership

Handles are monotonically allocated 64-bit identities.
Retain creates another identity for the same object; release invalidates only that identity.
Closed objects reject work even through retained aliases.
Stale identities return a diagnostic rather than dereferencing a released host pointer.

`EmbeddedRegion` passively owns its Tokio runtime, server handle, driver join and retained startup configuration charge.
`Admission` is the monitor that excludes new calls while shutdown drains admitted work.
The existing `ServerDriver` owns asynchronous scheduling.
Shutdown cancels node and server lifetimes, waits for admitted calls, and joins the server before returning.

The handle registry, sessions, statements, operation tokens, cursors, diagnostics and byte results are passive objects.
Session and statement state each have one mutex writer.
Operation cancellation bypasses those locks, and each token descends from its session lifetime.
Each result owns a child cancellation token, so releasing a result preserves its caller's operation token and sibling results.
Releasing the last operation handle cancels its scope.
Statements retain the default database captured at creation for preparation, schema inspection and queries.
Changing the connection's current catalog affects subsequent statements and DML submission.
Statement creation and source replacement classify SQL under the node's memory budget.
An admitted Transit transaction input releases codec scratch before submitting its owned values.
The statement retains an admitted control command through schema inspection and execution.
Ordinary SQL retains its source text for preparation, and bulk ingest retains its schema and table names.
A rejected source replacement preserves the current source, preparation and bound arguments.
A successful replacement clears the prior preparation and bound arguments.
Session-variable SHOW remains available in failed ADBC transactions; query-classified SHOW and PostgreSQL's failed-command guard retain their access checks.

Arrow exports implement the Arrow C Data Interface.
Array buffers and release-callback metadata retain their reservations independently of the query cursor and runtime.
Each child and dictionary release owner carries the lease, including when a consumer moves a descriptor out of its parent array.
The array export charges its C descriptors and any newly allocated validity or view-length buffer while retaining the page's funded backing.
The combined export charges its C schema separately.
Bind imports consume valid Arrow structs and copy values into native ownership before returning.
The caller may then close its original vectors and allocator.
Immutable producers can call `rtdb_v1_statement_bind_retained` to transfer the C Data buffers without a snapshot copy.
Those buffers must stay immutable and the producer must support release callbacks on any thread until the last native batch drops.
The Java ADBC adapter takes one private Arrow buffer copy in the connection allocator and transfers it through the retained bind.
The caller may close the source vectors and their allocators as soon as binding returns.
Decimal C formats carry true signed 32-bit precision and scale for all four coefficient widths.
Native carrier metadata is absent from exports and rejected on imports.
Bind import reads the foreign C declaration directly unless a decimal format requires normalization.
Replacement C format strings share each schema child's retained release owner, so moving a child out of its parent preserves both its format and reservation.

ADBC parameter schema requests admit the Arrow fields before constructing them and return one empty-name nullable Null field per positional parameter.
ADBC query schema requests acquire a preparation context for each call and report type errors without opening a cursor.
Result schema inference releases its temporary vector of unknown parameter types and the vector's reservation before converting result fields to Arrow.
DML result schema requests return an empty schema without acquiring that context.
ADBC cursor schemas retain the advertised result layout.
Java ADBC imports that schema once per stream, then loads array-only exports into the existing result root.
Each runtime page passes through the passive `rtdb-columnar::DeclaredBatch` adapter before C export, following `ResultCursor.toArrowReader` and `ConformingUnloader`.
An exact page shares the cursor's immutable declaration and its reservation.
Present NULL vectors acquire the target physical layout while the exported schema preserves its advertised nullability flags.
The Rust batch retains nullable physical fields and uses checked Arrow constructors.
Schema alignment reserves decoded values and rebuilt buffers, and preserves exact decimal parameters.
The virtual-endpoint regression source checks the advertised timestamp field and emitted null buffers; it has not been executed.

The execution budget is shared with authentication, queries, transactions and startup configuration.
The configured cache split remains a separate cache budget within the same process allocation ceiling.
Before node initialization, raw parser events, expanded YAML nodes and environment copies acquire bootstrap reservations.
The retained configuration charge transfers to the execution budget before node allocations begin.
The host excludes concurrent native environment mutation during startup.
Error handles use a separate bounded 16 MiB diagnostic budget, including errors before a node exists.
If that budget is exhausted, diagnostic identity `1` reports the reporting failure without allocation.

== Transit client bridge

The Clojure adapter binds positional SQL rows using Transit MessagePack and can bind named logical-relation parameters through C Data.
The embedded row cursor writes Transit JSON from the admitted Arrow cells and lends the bytes to the Clojure reader until that batch finishes decoding.
Result documents use the private `rtdb/struct` tag, allowing the adapter to apply its selected key function to document fields while preserving ordinary map keys.
Null document fields are omitted and narrow integer/float values retain their Transit tags, matching `RelationReader.toMaps` and `StructVector.getObject0`.
The legacy C Transit cursor still returns the same owned-byte-handle interface.
Autonomous transaction requests carry operations, options and the asynchronous flag explicitly.
Absent SQL arguments and a present empty row batch remain distinct.

== Source verification

The native regressions exercise the C Data and Transit entry points directly.
Test source covers released identities, duplicate unnamed arguments, copied foreign binds, retained Arrow batches after parent close, idempotent Arrow release callbacks, independent stream cancellation and concurrent shutdown.
Decimal fixtures cover signed-parameter import/export, reserved-key rejection and detached schema-child lifetimes.
JVM and Clojure fixtures retain the upstream `AdbcTest` and `api-adbc-test` case identities.
Executable ABI, allocator, parity and concurrency verification belongs to the implementation gate described in the project handoff.

The C pointer preconditions remain the host's obligation.
The library can reject stale numeric handles; it cannot make arbitrary invalid foreign pointers readable.
Arrow release callbacks must not throw or re-enter this blocking API.

Diagnostic message field 2 borrows a null pointer with zero length for absence and a nonnull pointer with zero length for an empty message.
Other diagnostic fields retain their existing slice contracts.
Retaining the diagnostic keeps both its optional message and Transit representation alive until the last handle is released.
