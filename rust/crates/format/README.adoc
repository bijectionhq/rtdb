= Durable format implementation

All components in this crate are passive values or codecs.
IPC inspection exposes allocation bounds for messages, streams and files, including compressed buffers' declared decoded lengths and row descriptors.
Owned transaction streams admit Arrow buffers, field descriptors and validity work before reading complete frames.
Materializing values from those batches has its own allocation scope.
Immutable-file inspection reads compressed length prefixes without loading each encoded body, and records separate dictionary and page decoding bounds.
File and stream readers validate LZ4 output length with a fixed scratch buffer before Arrow 58.4.1's decoder materializes it.
Bounds include the complete framed metadata length and conservative decoder scratch allowances: 64 MiB for LZ4 frame buffers and their reallocation, and 1 MiB for Zstandard's bulk decoder context.
Zstandard output uses Arrow's declared-size bulk decoder.
File and stream readers derive unknown field null counts from physical validity before checked decoding, including compressed and dictionary buffers.
Projection retains the full source schema for that traversal, and null counts below the unknown sentinel remain invalid.
Callers reserve those bounds before decoding and retain their guards until the decoded buffers are released.
Generated protobuf messages retain field presence from XTDB's edition-2023 schemas.
The build script generates bindings from the original source files and maps their explicit-presence fields to prost's proto2 descriptor model.
Repeated scalar fields retain edition-2023 packed encoding.
Neither protobuf generation nor compilation has run during Phase 1.

The source and replica envelopes retain the source header, optional term sequence, optional external token, database operation, and transaction payload bytes.
Log records and block files that depend on RTDB-only features (native `rtdb.v1` transactions, owned relations, retry guards, placed transactions, serving records/checkpoints, derived artefacts, table retirements, later naming epochs, unparseable trie keys, L0 deletions or offloads bound to a publication) are framed so an XTDB node refuses them: source records take header byte `4`, replica records take header byte `4` followed by a leading zero byte, and `Block`/`TableBlock` files begin with a zero byte.
Every field RTDB adds to XTDB's shared protobuf messages is numbered from `1000`.
`basis::encode_time_basis` and `basis::decode_time_basis` encode and decode XTDB's `TimeBasis` SQL snapshot tokens, matching Java's `Base64.getDecoder()` leniency on optional padding and trailing bits.
The Transit codec retains tagged values, legacy error tags, and cache substitutions while decoding MessagePack.
Budgeted MessagePack decoding admits the packing graph, decoded containers and each cache expansion before allocating them.
The returned Transit value retains its own reservation after the packing graph is consumed.
The current schema writer records version 6; other storage generations must be qualified and registered before recovery accepts them.
Legacy source transaction bytes and obsolete flush records retain the JVM dispatch behavior.
Trie recency keys use `CivilDate` across the nonnegative Java calendar range through year 999999999, rendering unsigned years of at least four digits.
The key format retains its two-digit month and day fields.
Parsing follows the reference formatter's lenient year width and SMART date resolution: one through nine year digits with an optional plus sign, valid month and day ranges, and clamping to the month's last day.

The Arrow readers accept files and streams through Arrow IPC, including multiple pages and run-end encoded IIDs.
Trie metadata writers release the scan scratch after each page and admit the final schema and encoded file separately.
Decimal metadata is checked recursively before Arrow's native schema conversion in file, stream, standalone schema, COPY, and Flight input paths.
Unsupported bit widths return an Unsupported anomaly before Arrow 58.4.1's schema conversion.
Decimal precision and scale retain the complete signed 32-bit JVM and Arrow IPC range.
Native Arrow arrays use byte-sized parameters and reserved field annotations for wider values; coefficient buffers retain their original width and bytes.
Ingress derives those annotations from the real IPC decimal metadata and rejects external uses of either reserved key.
Egress removes the annotations and writes the true signed 32-bit parameters in the IPC schema and file footer.
Nonpositive precision and scale greater than precision remain representable metadata; ordinary column writes validate coefficients against the declared precision and physical width.
Typed event and metadata copies preserve existing coefficients with exact decimal parameters, including coefficients larger than their declared precision.
Owned event batches build one document column at a time under the same admission contract as source transaction batches.
Captured event schemas reject values outside their declared type legs.
`tests/ipc_decimal_metadata.rs` changes nested FlatBuffer metadata directly and retains those accepted and rejected boundaries as unexecuted regression source.
`tests/decimal_scales.rs` covers all physical widths, nested fields, independent union scales, empty/null zero-precision pages, protobuf column metadata and incremental sinks.
`tests/decimal_precisions.rs` extends those boundaries to signed precision, raw coefficients, run-end fields, reservation release and unchanged narrow-parameter bytes.
Narrow-scale standard Arrow streams retain their original bytes in regression source.
These guards do not validate every other Arrow schema kind.
Event operations are selected by union leg name because type IDs can differ across file schemas.
The writer uses eight-byte alignment and the JVM's four-byte end marker, and the unified native Java-layout stream writer stores dictionary, view, list-view and run-end columns in XTDB's plain layouts.
The standard Arrow stream and schema APIs retain caller-selected options for Flight transport.
Schema translation and the initial schema-frame buffer belong to the caller's reserved codec scratch; incremental sinks retain no complete stream.
Budgeted file writers retain schema and block-inventory reservations and acquire footer scratch before finalization.
Production block and compaction writers use those constructors; raw constructors require a caller-owned reservation.
Writers check every page's complete native schema, including nested full-width decimal annotations, before encoding it.
Cross-process writer identity remains an unexecuted acceptance check, including FlatBuffer construction, schema ordering, and metadata encoding.
The metadata codec retains column statistics and traverses IID and recency branches.
Column type metadata preserves the reference unsigned-integer and half-precision-float rejection codes, `xtdb/col-meta-unsigned-int` and `xtdb/col-meta-float-precision`.
Imported metadata retains its nested Arrow schema when written again.
New leaf statistics include nested child references, counts, numeric bounds, presence flags, and byte-backed Bloom filters.
Bloom filters use XXHash32 and MurmurHash3 x86 with the JVM's five hashes over 22 bits and portable Roaring serialization.
New metadata schemas have deterministic field order; exact JVM field allocation order and nullability remain part of the byte-identity acceptance check.

The HLL codec stores big-endian 32-bit registers and combines matching registers by maximum.
Its estimator reproduces the pinned Kotlin expression, including the signed narrowing of `0xffffffff` to `-1` in the large-range correction.
That source-level discrepancy needs a reference observation before any behavior change is proposed.

The passive YAML codec converts database declarations to the existing protobuf configuration, preserving defaults and nested provider/indexer types.
It keeps environment expansion separate: pinned `Database.Config.fromYaml` does not expand `!Env`, whereas node startup configuration does.
Provider aliases suppress inline credentials in the durable encoding.
Local-log clock overrides and Kafka topic-creation flags are accepted but omitted from database protobufs, matching the pinned serialization boundary.
Custom YAML registration, exact parser error text and input allocation qualification remain source and runtime review items.

Transit writer values can retain single precision through `TransitValue::Float32`.
MessagePack emits its 32-bit payload while the existing `Float` variant emits 64 bits; both wire widths decode as `Float`, matching the reference reader.
Internal JSON retains an explicit `float32` wrapper for writer values, and Transit JSON uses the single-precision decimal spelling.
`tests/transit_float_width.rs` records raw payload, map-key, decoder and internal-JSON contracts as unexecuted regression source.

`TransitReadBuilder` constructs values before the Transit read cache records them.
Cache references clone the caller's constructed value, allowing semantic readers to preserve reference identity within one decode.
`decode_with` chooses valid MessagePack or JSON syntax before construction and returns semantic construction errors without trying another wire format.
The existing wire-tree decoders retain their value representation and per-value cache reset behavior.
`tests/transit_read_builder.rs` records cache identity, decode isolation and semantic-failure behavior as unexecuted regression source.

Read builders can override binary representation handling before bytes enter the cache.
The wire-tree builder retains its canonical Base64 validation; the stored-object builder applies the reference Java decoder's padding and unused-bit rules.

Read builders own array and map construction states and receive each decoded entry before later entries are decoded.
A selected array handler constructs raw array contents directly; a nested tag or JSON map marker can select another constructor.
Read-cache rollover overwrites slots from index zero while retaining unwritten old slots, matching references in the same top-level value.
Fresh top-level values still begin with an empty cache.

Anomaly messages retain null separately from empty text in current `xt/error` and historical error readers.
The writer emits null for an absent message and a string for every present message.
Typed context continues to use the internal Transit JSON wrappers, including non-string map keys and tagged values.
`tests/transit.rs` records current and legacy null, empty and text messages, typed-context retention and invalid message-type rejection as unexecuted regression source.

File and stream readers adapt nested dense-union field nullability for Arrow Rust when a union leg can produce null.
Map keys retain their declared nonnullable field contract.
The decoded batches retain the declared type IDs, metadata and payload buffers.
The writer retains the Arrow field flags supplied by the storage schema.
