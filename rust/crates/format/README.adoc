= Durable format implementation

All components in this crate are passive values or codecs.
IPC inspection exposes allocation bounds for messages, streams and files, including compressed buffers' declared decoded lengths and row descriptors.
Callers reserve those bounds before decoding and retain their guards until the decoded buffers are released.
Generated protobuf messages retain field presence from XTDB's edition-2023 schemas.
The build script generates bindings from the original source files and maps their explicit-presence fields to prost's proto2 descriptor model.
Repeated scalar fields retain edition-2023 packed encoding.
Neither protobuf generation nor compilation has run during Phase 1.

The source and replica envelopes retain the source header, optional term sequence, optional external token, database operation, and transaction payload bytes.
The Transit codec retains tagged values, legacy error tags, and cache substitutions while decoding MessagePack.
The current schema writer records version 6; other storage generations must be qualified and registered before recovery accepts them.
Legacy source transaction bytes and obsolete flush records retain the JVM dispatch behavior.

The Arrow readers accept files and streams through Arrow IPC, including multiple pages and run-end encoded IIDs.
Decimal metadata is checked recursively before Arrow's native schema conversion in file, stream, standalone schema, COPY, and Flight input paths.
Precision outside an unsigned byte and unsupported bit widths return an Unsupported anomaly before Arrow 58.4.1's schema conversion.
Decimal scales retain the complete signed 32-bit JVM and Arrow IPC range.
Native Arrow arrays use a signed-byte scale and a reserved field annotation for wider values; coefficient buffers retain their original width and bytes.
Ingress derives that annotation from the real IPC decimal metadata and rejects external uses of the reserved key.
Egress removes the annotation and writes the true signed 32-bit scale in the IPC schema and file footer.
Precision zero and scale greater than precision remain representable metadata; coefficient validation belongs to the column writer.
`tests/ipc_decimal_metadata.rs` changes nested FlatBuffer metadata directly and retains those accepted and rejected boundaries as unexecuted regression source.
`tests/decimal_scales.rs` covers all physical widths, nested fields, independent union scales, empty/null zero-precision pages, protobuf column metadata and incremental sinks.
Narrow-scale standard Arrow streams retain their original bytes in regression source.
These guards do not validate every other Arrow schema kind.
Event operations are selected by union leg name because type IDs can differ across file schemas.
The writer uses eight-byte alignment and the JVM's four-byte end marker.
The standard Arrow stream and schema APIs retain caller-selected options for Flight transport.
Schema translation and the initial schema-frame buffer belong to the caller's reserved codec scratch; incremental sinks retain no complete stream.
Budgeted file writers retain schema and block-inventory reservations and acquire footer scratch before finalization.
Production block and compaction writers use those constructors; raw constructors require a caller-owned reservation.
Writers check every page's complete native schema, including nested full-scale decimal annotations, before encoding it.
Cross-process writer identity remains an unexecuted acceptance check, including FlatBuffer construction, schema ordering, and metadata encoding.
The metadata codec retains column statistics and traverses IID and recency branches.
Imported metadata retains its nested Arrow schema when written again.
New leaf statistics include nested child references, counts, numeric bounds, presence flags, and byte-backed Bloom filters.
Bloom filters use XXHash32 and MurmurHash3 x86 with the JVM's five hashes over 22 bits and portable Roaring serialization.
New metadata schemas have deterministic field order; exact JVM field allocation order and nullability remain part of the byte-identity acceptance check.

The HLL codec stores big-endian 32-bit registers and combines matching registers by maximum.
Its estimator reproduces the pinned Kotlin expression, including the signed narrowing of `0xffffffff` to `-1` in the large-range correction.
That source-level discrepancy needs a reference observation before any behavior change is proposed.

The passive YAML codec converts database declarations to the existing protobuf configuration, preserving defaults and nested provider/indexer types.
It keeps environment expansion separate: pinned `Database.Config.fromYaml` does not expand `!Env`, whereas node startup configuration does.
Provider aliases suppress inline credentials in the durable encoding.
Local-log clock overrides and Kafka topic-creation flags are accepted but omitted from database protobufs, matching the pinned serialization boundary.
Custom YAML registration, exact parser error text and input allocation qualification remain source and runtime review items.
