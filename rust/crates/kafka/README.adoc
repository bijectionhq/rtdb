= Kafka log adapter

`KafkaLog` is a passive append/read capability.
`KafkaLogDriver` is the active owner of producer submission, callback polling, and shutdown.
Capacity semaphores and per-append completion channels are monitors shared with callers.
`KafkaTail` is a passive cursor with caller-controlled polling and an explicitly assigned partition.
The native client owns transport threads; no Rust producer task is detached.
The owner runs the returned driver and cancels and joins it before releasing writable-log resources.
Read-only opening returns no producer or driver.

`enqueue` returns after the native producer accepts the record and fixes its submission order.
The receipt completes after the delivery callback reports the broker acknowledgement.
`acks=all` is mandatory.
Disabling idempotence also limits outstanding broker requests to one so retries cannot reorder appends.
This last override is stricter than the JVM producer configuration, which leaves that property overridable.
An error after submission can leave an unknown broker outcome; replication reconciles its term and sequence through read-back.
The supplied local timestamp is unused, as in the JVM Kafka transport; Kafka record timestamps have millisecond precision.

Each log requires one partition.
Topic creation uses one replica and `LogAppendTime` timestamps.
Existing replicated topics report weak minimum-ISR or unclean-election configuration through the required observer.
Denied configuration inspection is advisory.
Automatic consumer metadata requests cannot create topics.
The source and replica topic names and storage epoch use the existing protobuf schema.

Configuration properties merge bootstrap servers, the property map, then the ISO-8859-1 Java properties file.
The documented PLAIN JAAS configuration and SCRAM username/password configuration translate to native SASL properties.
Other login modules and Java client extensions require an explicit native adapter and return an error.
Native TLS and SASL properties pass through to librdkafka.
The schema registry URL is retained for source configuration; the log transports envelope bytes without a registry lookup.

Fresh broker watermarks determine the durable tip.
Retention, withdrawn observed offsets, unexpected gaps, tombstones, and fetch timeout before a known tip return errors.
Empty polling means the cursor reached the observed tip.
The transport does not open Kafka transactions; externally written transaction/control records that introduce offset gaps are rejected.
Poll batches and range reads have explicit limits; a range exceeding its limits fails instead of truncating silently.
Native prefetch and decompression allocations still require qualification against the process-wide memory contract.

Source references are `modules/kafka/src/main/kotlin/xtdb/api/log/KafkaCluster.kt`, `KafkaClusterTest.kt`, `KafkaLogFactoryTest.kt`, `KafkaDurabilityTest.kt`, and `allium/log-processor-lifecycle.allium`.
The Rust test sources cover configuration precedence, JAAS credentials, acknowledgements, topic partition validation, read-back, read-only handles, and cancellation while admission is backpressured.
They have not been compiled or executed during Phase 1.
Real broker failover, retained-range truncation, authentication, and native shutdown qualification remain required before backend compatibility can be claimed.

== Kafka Connect ingestion

`connect::SourceDriver` owns one explicit partition assignment and its consumer, converters, transform chain, indexer, and cancellation choice.
`SourceConfig`, `ConnectConfig`, schema/value descriptions, and resume tokens are immutable values.
Converters, predicates, transforms, and record indexers are passive capabilities opened for that assignment.
The status channel is a monitor with one writer.
The node registers `KafkaConnectSourceFactory` under the existing external-source protobuf type.
The durable configuration stores a Kafka remote alias, topic, Connect plugin options, and an indexer `Any`.
Node-local native plugin and indexer registries provide extension points.
Converter options are retained in the durable source configuration.

A first assignment seeks to the first retained Kafka offset.
A resumed assignment seeks immediately after the last admitted XTDB transaction token.
No consumer offsets are committed to Kafka.
The driver converts and transforms an entire bounded fetched batch before submitting any record from that batch.
Filtered records create no transaction; an entirely filtered tail is replayed after reassignment.
The document indexer obtains `_id` from the key, unwraps a single-field Connect Struct key, overwrites any document `_id`, and writes a delete for tombstones.
Document valid time defaults to the smoothed transaction system time through the end of time.
Decoder, transform, or indexer errors stop the assignment without an aborted placeholder transaction.
The current submission adapter waits for admitted read-back per record; the reference document indexer hands off after resolution and can pipeline read-back.

Native converters cover String, ByteArray, numeric, Boolean, schema-bearing or schemaless JSON, and the core Confluent Avro and JSON Schema wire paths.
The String converter selects the key or value deserializer encoding before decoding, with `converter.encoding` supplying the fallback to both serializer and deserializer configuration.
Selected serializer encodings are validated during opening even for ingestion.
The six standard Java charsets and their Java aliases are supported, along with BOM-sensitive little-endian UTF16.
UTF8 and UTF16 replacement consumes malformed byte groups at the Java decoder boundary; fixed-endian UTF16 preserves its initial byte-order mark as text.
Other Java charset families and installed charset providers remain source-completeness work.
Registry lookup uses bounded HTTP responses, a retained schema cache, reference resolution, subject-name strategies, and subject-version lookup; Avro datum preflight bounds decoded allocation before the native decoder runs.
Avro conversion retains narrow integer annotations, field defaults, Connect metadata, enum/fixed metadata, and non-string map entry records.
JSON Schema payload validation follows `json.fail.invalid.schema`, whose default is false.
The transform implementation covers ExtractField, ReplaceField, HoistField, ValueToKey, Filter, DropHeaders, HeaderFrom, InsertField, InsertHeader, Cast, MaskField, Flatten, RegexRouter, TimestampConverter, TimestampRouter, and SetSchemaMetadata, with the three shipped predicates.
Header and InsertHeader literal parsing retains Kafka numeric widths, collection schema inference, top-level quoting, and millisecond temporal types.
Decimal converters, defaults, header literals, and masks retain signed 32-bit scales.
Integer inference and mask conversion bound their work by coefficient digits, including at the scale limits.
Recursive Avro and JSON Schema definitions use immutable node graphs; detached field views retain their graph without ownership cycles.
Enhanced Avro unions retain full named-type namespaces; generalized unions/enums and singleton-union configuration follow the converter-specific naming rules.
Avro union values follow the pinned converter's candidate matching and destination-field validation, including generalized unions whose null positions cause a different field selection or a conversion error.
JSON union matching distinguishes integral numbers and counts nested Struct-property matches.
Schema default conversion runs after child metadata has been completed.
Registry authentication supports explicit URL, USER_INFO, SASL_INHERIT, STATIC_TOKEN, OAUTHBEARER, and SASL_OAUTHBEARER_INHERIT sources.
OAuth refresh runs on the request caller, retains a charged token cache, and applies the reference expiry threshold and end buffer.
Registry TLS uses the shared `rtdb-tls` codec for JKS, PKCS12, PEM trust/client identity files or inline material, and encrypted PKCS8 PEM keys.
Protocol selection, hostname policy, and HTTP proxy settings remain client-owned.
As in the pinned registry client, absent, empty, or `none` endpoint-identification policy disables hostname checks; configure `schema.registry.ssl.endpoint.identification.algorithm: HTTPS` to require them.
Registry domain read rules execute after datum decoding and before Connect conversion; write-only, migration-only, disabled, and `NONE`-tolerated rules permit reads.
Read rules run in reverse declaration order, use rule-name/type/default configuration override precedence, and distinguish a decoded Avro null from a JSON null node.
The shipped converter classpath has no rule executor service; an active rule without an executor takes its configured failure action, which defaults to `ERROR`.
Reader selection supports the writer schema, the latest subject version, and latest metadata matches with a bounded cache and expiry.
Upgrade migrations visit adjacent versions in ascending order; downgrade migrations reverse that order and use the target version's metadata for rule parameters.
DLQ actions select a subject-qualified rule registration, a rule-name registration, then the first registration of that type.
Action configuration merges converter options, default parameters, type parameters, and named parameters.
READ failures send the original Confluent frame; migration failures send the current JSON value.
JSON payloads and defaults preserve integral node identity and arbitrary integer digits through conversion and migration output.
Integer Connect fields use Jackson's low-bit narrowing.
Registry JSON retains BigDecimal precision and scale; generic JSON and Avro migration floats use Java double spelling.
Value failures retain the Registry key frame, while key failures send a null value.
The source uses headerless converter calls, so DLQ records carry the five generated rule headers.
A missing DLQ topic fails before producer creation; producer failures leave the rule failure as the returned conversion error.
The assignment owner awaits both converter drains after normal completion, errors, and cancellation.
Native Kafka dead-letter producers support PLAIN/SCRAM credentials and JKS, PKCS12 or PEM client material, including multiple private-key entries selected during the TLS handshake.
Java protocol and cipher-suite configuration uses the native OpenSSL client adapter; link:TLS.adoc[TLS configuration and open parity gaps] records its scope and pending qualification.
Additional Java producer extensions, custom credential/provider classes, and several nondefault converter settings remain unfinished source work.
Client certificate selection retains all keystore identities and matches signature schemes and acceptable issuer names.
PKCS12 store and private-key passwords are independent.
Registry default trust uses the pinned Temurin 25.0.1+8 certificate store under a retained decode reservation; configured trust retains its keystore reservation.
The native trust-store allocation bound requires runtime qualification.
Date patterns use native hybrid Gregorian, Buddhist and five-era Japanese calendars with the pinned CLDR locale data, week fields, localized names/numbers, named zones and construction-time two-digit-year pivots.
link:LEGACY-DATES.adoc[Connect date conversion] records the raw-millisecond boundary, process environment, resource ownership and remaining provider qualifications.
Java regex, charset, float formatting, Gregorian cutover behavior, and header inference edge cases remain to be matched against their reference assertions.
Source metrics expose an assignment-scoped registration guard and status channel, including native high-watermark minus application-offset lag.
The guard receives every retained record's timestamp lag after a successful indexer batch, using the same millisecond clock observation for the entire batch.
The native registry exports the reference commit-lag distribution summary; executable sample-timing parity remains unqualified.
Raw fetch batches and conversion retention have explicit limits and reservations.
JSON schema/default expansion has a pre-allocation decode budget; transform and document conversion reserve additional retained charges before cloning.
Custom plugin ownership and native decoder/prefetch allocations still require a complete memory-bound audit.
No Kafka Connect compatibility or memory-bound qualification is claimed before those paths and the unexecuted reference-mapped test sources pass Phase 2.

The source mapping is `KafkaConnectSource.kt`, `ConnectConfig.kt`, `RecordIndexer.kt`, `DocsIndexer.kt`, their Kotlin tests, and `kafka_connect_source.proto`.
Native converter and transform behavior is also traced to the Kafka 4.4.0 source artifacts, and registry conversion work targets Confluent 7.8.0.

Avro reader resolution is an immutable action graph over the writer and reader schemas.
It applies named and field aliases, record projection and defaults, ordered reader-union selection, numeric and string/bytes promotions, enum defaults, and recursive schema pairs using Avro 1.11.4 `Resolver` rules.
Incompatible writer-union branches fail when selected; selected reader defaults use the first union branch.
Binary reader resolution skips projected-away fields directly from the wire and reserves space for selected values and defaults.
Binary datum readers consume one value and ignore its suffix; the Confluent root-bytes path retains the complete payload.
Selected collection blocks consume their item counts; projected negative-count blocks skip their declared byte lengths.
Malformed skipped byte lengths may rewind within the datum slice and the pinned decoder's first-compaction window, with cumulative rewind distance limited to one datum length per decoding pass.
Rewinds before that window, Java cursor integer wrapping, and rewinds into the Confluent framing prefix remain compatibility boundaries.
The pinned byte-array decoder can expose that prefix for payloads of at least 16 bytes before its first compaction; the native decoder owns only the datum slice.
Schema-only datum plans defer Connect graph construction until the output schema is selected.
Reader output retains the writer Registry version and the converter's nonrecord writer-schema behavior.
The physical decoder leaves logical values as their integer or byte representation until Connect conversion.
Local raw JSON default descriptors retain oversized integer spelling and floating exponents without changing other JSON consumers.

The Avro migration codec follows `AvroSchemaUtils.toJson` and Avro 1.11.4 `JsonDecoder`: nested union labels, ISO-8859-1 binary strings, record field reordering and aliases, and required JSON fields remain distinct from binary reader-default resolution.
`AvroDatum` couples the physical datum with its actual schema; each passive `AvroMap` retains its raw keys, insertion history, and reader key class.
Its caller-owned map replay follows OpenJDK 21 `HashMap` bucket order, resizing, collision trees, and duplicate replacement at every map depth.
Collision trees use ordered lookup and linked iteration to preserve replacement and root movement without scanning entire buckets.
Malformed binary strings retain their original bytes through string/bytes promotions and use Java UTF-8 replacement at text conversion.
Distinct malformed `Utf8` map keys retain byte identity through reader selection; String reader keys, migration JSON properties, and Connect String keys collapse duplicates at their respective conversion boundaries.
Resolution, selected Connect graphs, JSON expansion, and detached conversion results retain their admitted memory charges through their owners.
The resolver, migration, output-selection, default-number, malformed UTF-8, and map-order regression sources have not been executed.
Registry HTTP and dead-letter producer clients accept empty Java identity and trust stores; server identity admission still requires a usable key.
Explicit empty trust stores retain no default roots and fail untrusted handshakes.
