= Borrowed direct conversion kernel

The internal conversion::direct entry measures and materializes values from a borrowed actual Avro schema/datum and a borrowed destination SchemaView.
The production AvroPlan::convert route does not select this kernel in this prerequisite.
Java policy activation still requires the complete ordered parser, default construction, union-context selection and retained cache admission.

Walk is a passive call-local single-writer transient.
It borrows the existing ConversionContext and owns one checked demand counter.
Its const BUILD mode chooses between measurement and materialization inside the same branch walk; measurement constructs no output Value tree.
Neither the walk nor a lookup index is retained in a plan or graph.
SchemaView inspects existing graph metadata and edges without resolved-view allocation or default cloning.
The caller keeps source/schema owners alive during conversion and retains the context's reservation owner until the output has been released.

Ordinary record conversion visits destination fields in their schema order and selects the exact raw actual field using the shared streaming lookup comparator.
The selected child's actual physical schema stays paired with its borrowed value.
Several destination fields can read the same child, and raw destination output names are preserved.
Every destination demand is visited separately during measurement, so a nested two-way collision family counts all 2^depth selected leaves.
No collision-count cap or linear input-size multiplier is used.
The supported MapEntry branch requires optional String destination keys and non-null String/CharSequence/enum key data.
It selects exact raw key and value fields, visits all source entry values before replacement, and uses the existing String hash replay for Java result order and latest-key replacement.
Nested ordinary records still use the configured scrub flag.
Required String keys select the ordinary Map representation, so an Array is rejected for that destination.
Null, numeric, binary and structured MapEntry key domains remain explicit unsupported kernel boundaries until their complete hash/equality/order behavior is integrated.

== Admission and materialization

Each demand adds a checked Value header, payload and container allowance before materialization.
Struct entries use 16 native (String,Value) slots plus 256 bytes and the raw output-name payload, matching the conservative Value document model.
Lists and maps preallocate their measured capacities.
Child headers are counted separately from container slots, retaining a conservative overlap allowance.
The existing input/schema/default owners remain live and are not credited against new output storage.

Measurement compares accumulated demand with allocation_remaining, including prior input/cache charges.
Its final context.reserve is authoritative for the shared budget and occurs before any output tree is constructed.
A semantic failure at a demanded field returns before output copying.
Checked overflow and resource failures propagate through Result.
The native depth guard remains 128 without a corresponding Java acceptance-limit claim.

Map order replay is itself allocation-bearing scratch.
Before either replay runs, the kernel reserves 8192 bytes per physical insertion, 12 bytes per raw key byte and a 4096-byte seed allowance.
The per-entry allowance covers geometric old/new Replay Entry vectors, simultaneous old/new BTree bucket maps during resize, prepared key vectors and both index vectors.
An Entry fits 16 native usize slots, a bucket key/value fits 10 usize slots, and two conservative 16-slot-plus-256 BTree entry allowances stay within 8192 bytes per insertion on the native 64-bit target.
The seed covers minimum vector capacity, and the key term covers simultaneous String decoding/growth and the later exactly sized prepared key copies.
Replay insertion/resize/treeification stays in the existing source-pinned java_map implementation.
Measurement holds its own scratch reservation and includes another complete scratch allowance for materialization; both coexist with retained input and output reservations.

The first replay identifies visible physical map values before conversion, so overwritten physical values are not demanded.
The second replay inserts converted String keys in that visible order.
Distinct malformed raw keys can become the same Java String; their source-visible values are still converted before the later result replacement.
Prepared keys and index vectors are admitted scratch rather than an output tree or retained lookup cache.
All temporary and final map container overlap is included in demand.

Primitive narrowing is fused into materialization, avoiding the old metadata::coerce reconstruction pass.
Ordinary child conversion precedes the parent logical representation checks.
Scalar physical-class validation precedes logical conversion; logical date conversion reserves its UTC text and produces the existing date object representation directly.
An empty Decimal coefficient fails before scale lookup, while scale validation precedes precision comparison for a nonempty coefficient.
UTF8 length measurement and exactly sized String construction share the same replacement-boundary walker, including malformed surrogate encodings.
Decimal precision compares borrowed signed coefficient magnitude with fixed 10^32 and 10^64 thresholds using a 32-byte stack array.
It rejects excessive precision before any BigInt or radix String allocation and allocates only the final 16- or 32-byte sign-extended coefficient after admission.
The thresholds and signed examples are finite source/data derivations; no project or Java execution supplied their expected values.

== Integration boundary and regression scope

The kernel unwraps an actual nullable/singleton Avro union when its destination is already the selected concrete Connect schema.
A structured Connect union must first be selected by the caller; an unselected union returns an explicit error.
Scalar names/parameters carrying union markers remain scalar conversions because Java performs the union test only inside its Struct branch.
The complete activation still needs the source ToConnectContext identity/cycle cache, dynamic record graph admission, candidate/destination matching and equality scratch, plus exact default-origin conversion and cache-retained graph/default leases.
Those responsibilities are not replaced by a schema-size reserve around the old graph builder.
No existing production parse, output bridge, union, metadata/default or resolution behavior changes in this prerequisite.

Confluent 7.8.0 AvroData.java is pinned in link:../names/selector-sources.sha256[the selector manifest], with link:../names/SELECTOR-COPYRIGHT[its retained header] and link:../names/LICENSE-APACHE[the Apache license].
Its toConnectData branches at 1538–1689 own primitive, array, map and destination-field record selection.
The fixed/enum union selection and ToConnectContext identity rules remain future integration obligations.
The native retained Value model and java_map caller-admission contract supply the container/replay allocation inventory.

Sixteen regression sources cover repeated-child identity and raw names, disabled scrub/raw alias failure, selected-child type failure before reservation, nested multiplicity with exact/below limits, held prior charges, nullable actual union selection, two-stage map visibility, scratch admission and last-context release, optional-String MapEntry raw selectors/replacement/order and unsupported domains, child-before-parent logical precedence, fused logical/narrow primitives, UTF8 boundaries, bounded decimal thresholds and the explicit unselected-union guard.
All prior assertions and production conversion bodies remain unchanged.
Rust/Java compilation and regression execution remain pending under the Phase 1 work order.
