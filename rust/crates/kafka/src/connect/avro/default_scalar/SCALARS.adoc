= Borrowed default scalar preparation

The inactive default_scalar helper prepares scalar defaults without constructing an output Value or allocating output text, bytes, a vector or a BigInteger.
The caller obtains a checked additional bound, admits it through its existing budget owner, and only then calls materialize.
The reservation remains with that caller through the returned Value's lifetime.
Failure diagnostics use the existing native anomaly representation; they are not prepared output allocations.
No production parser, converter, graph or default decorator selects this helper in this prerequisite.

== Values and boundaries

ScalarInput is a passive borrowed sum of prepared FieldObject, JsonNode and native child-default Value.
ConversionPath is a passive value distinguishing the wrapper default boundary from ordinary Map-child re-conversion.
PreparedScalar is a passive immutable call-local value containing primitive bits, borrowed payloads, deferred formatting inputs or a fixed 32-byte coefficient.
Its internal Text and Bytes values borrow source payloads; Octets is a passive single-pass borrowed iterator.
None of these objects owns an index, heap buffer, task, callback or allocation lease.
The test Output value is a passive owner that retains its reservation beside its materialized Value.

The caller supplies the logical name effective at the actual builder-default stage.
None disables logical conversion and does not fall back to the destination's final declared name.
This preserves primitive defaults built before explicit Date or Decimal name assignment.
validate_destination checks the prepared non-null output class without constructing a Value, at the caller's chosen SchemaBuilder or Struct validation point.
Null and missing optionality remain the caller's responsibility.

FieldObject input has already completed the Jackson source-object validation walk.
Ordinary object conversion preserves Java Integer, Long, Float, Double, Boolean, String and byte-array classes before logical conversion.
An existing child Byte, Short, Date or BigDecimal default does not become Integer or byte-array merely because it targets the same Connect schema again.
That class mismatch is a semantic invalid default, rather than a clone operation.

JsonNode input is an actual node after the owning JsonProperties.getObjectProp, untyped JacksonUtils.toObject and AvroData toJsonNode property roundtrip.
This module does not normalize a raw connect.default property into that node.
The caller resolves physical references and first-union selection before a demanded scalar node; a missing node returns without demanding its physical schema.
Explicit JSON null becomes the JsonProperties.NULL_VALUE sentinel and is written as JSON null again, preserving an actual NullNode through the property roundtrip.
An unmatched numeric node outside JacksonUtils's Int, Long, Double and Float branches instead becomes ordinary Java null; nested ordinary Java null fails unchecked during toJson conversion.
Production integration must preserve those distinct property-roundtrip outcomes before the accessor stage.

The existing avro.rs test avro_invalid_connect_defaults_are_ignored_after_nested_validation expects no default for an array of String with connect.default [null].
The pinned source roundtrip preserves that explicit null as ArrayNode containing NullNode; the String accessor then produces null text, predicting a list containing Utf8("null").
That source-versus-existing-observation mismatch remains recorded for Phase 2 reference reconciliation, with the old assertion unchanged.

Missing nodes, Java-null field objects, JsonProperties NULL_VALUE field objects and an actual Jackson NullNode remain distinct inputs.
NullNode integer accessors produce zero, asBoolean produces false, asText produces null text, and binaryValue produces Java null.
The native PreparedScalar exposes missing and null separately so the enclosing traversal can retain its source validation and suppression decisions.
Arrays and records with an actual NullNode still require their owning container-shape checks.

JsonNode numeric accessors retain low-bit BigInteger narrowing and floating saturation.
Float conversion uses the Double accessor before narrowing, including the positive and negative integral midpoint controls.
Integral asBoolean uses nonzero magnitude; floating and Decimal nodes retain the inherited false result.
Text Boolean conversion trims only Java characters at or below U+0020.
String conversion retains the actual node's text behavior, including normalized integral negative zero, Double formatting, Decimal scale and empty container text.
Deferred Decimal numeric accessors and text formatting allocate only inside materialize.

Binary text is read as ISO8859-1 with one replacement byte for each unrepresentable Unicode scalar.
Isolated UTF16 units outside Rust String representation remain outside this helper's source domain.
Decimal preparation first rejects an empty coefficient as the unchecked BigInteger failure, then validates scale as a semantic DataException boundary, then examines writer precision.
Coefficient sign padding, magnitude comparison and final 16- or 32-byte representation use fixed stack arrays and exact 10^32 and 10^64 thresholds.
No radix conversion or unbounded coefficient allocation occurs during preparation.
The native writer's greater-than-64-digit domain remains an explicit outer unsupported error; it is not silently classified as a Java invalid default.

== Additional allocation bound

Every result includes one Value header and a conservative 128-byte allowance.
Borrowed String and byte payloads add their copied output length; Latin1 output adds its character count.
Date output adds the three UTC bytes, and Decimal output adds its selected 16- or 32-byte coefficient.
Double text adds a conservative 4096-byte allowance for the existing java_f64_text formatter's finite numeric strings and simultaneous temporary buffers.
Deferred JsonDecimal text or numeric access adds four times its existing encoded text bound plus 4096 bytes, covering text construction, numeric formatting and output overlap.
All additions and multiplications are checked before admission.
The caller separately admits and retains source/default/schema owners, container storage, graph metadata copies, equality scratch and cached plans.
Successful preparation and bound calculation create no output heap owner.
