= Canonical Avro schema objects

The canonical module is registered for owned source objects and explicit admitted-source datum assembly.
link:producer/ADMITTED-OWNER.adoc[] records that actual datum-plan ownership and its consumer retention.
The Registry entry still uses the legacy parser, and canonical graph/default/conversion/SMT/writer consumers remain required before full activation.
The producer and subsequent logical regression sources have not been compiled or executed under the Phase 1 work order.

== Objects and lifetime

SchemasBuilder is a passive single-writer transient.
Its immutable Schemas arena owns canonical nodes, declaration bindings and the reservations for their storage.
SchemaHandle retains that arena and one checked region/object ID; SchemaView borrows it.
A named declaration, its recursive reference and the native root/definition copies associated by full name select the same canonical object.
A fresh primitive name lookup creates a fresh primitive object, as Parser.Names.get does.
Named aliases and docs remain metadata and do not create alternate declaration bindings.
Each parsed object also owns the source LogicalType result constructed after its properties and before aliases.
link:logical/LOGICAL.adoc[] records this distinct object value, source identity/class relations and effective factory/math profile.
Nonreused checked regions prevent stale IDs from becoming valid when storage addresses are reused.
canonical_native_record requires the native definitions and canonical arena to come from the same validated input producer.
Equal names in independent input documents do not establish source identity.

Text owns shared JavaString storage plus its captured reservation handle.
Names, JSON string values and member keys retain exact UTF16, including isolated surrogates.
Name validates the simple name after the last dot, takes namespace from that dot when present and converts an empty namespace to absence.
Namespace text is not subjected to simple-name character validation.
The declaration binding tree is a producer index over validated names, rather than an implementation of the source parser's HashMap allocation and diagnostic stages.

JsonNode is an immutable admitted Arc handle to one concrete source node value.
Integer, Long, BigInteger and Double remain separate node classes.
BigInteger coefficients are unbounded admitted magnitude words.
The supported node domain contains concrete parsed-JSON values and non-null numeric/text factory payloads.
Programmatic BinaryNode, POJONode and MissingNode values are outside this schema-document input domain.
Programmatic TextNode, BigIntegerNode and DecimalNode constructors carrying Java null are outside that domain and are not collapsed to NullNode.
Members retains insertion-ordered unique String keys with first-key/latest-value replacement and an index of positions into those same entries.
Its sorted lookup index owns no second key/value tree.
JsonNode owners retain child handles, text storage and coefficient storage after the construction context drops.

== Schema operations

FixedSchema receives an explicit FixedBytesLimit effective policy, with DEFAULT equal to Integer.MAX_VALUE-8.
The pinned SystemLimitException check runs after named-schema validation, then rejects negative size, size above that VM array cap and size above the effective bytes limit.
Effective signed limits preserve the source unsigned-property parser result, including negative wrapped values; the native constructor does not discover environment properties.

== Property maps

JsonProperties uses an anonymous ConcurrentHashMap whose overridden entrySet preserves a separate insertion-order queue.
Its inherited hashCode and first equals pass instead traverse the internal CHM table.
Properties retains the original Members and a quiescent table-encounter index of those same member positions.
PropertyOrder borrows the members and constructs admitted add-only String-key geometry: positive spread, default capacity, collision presizing, last-run transfer, first-list treeification, prepended tree insertions and split/untreeify behavior.
String comparison uses unsigned UTF16 units.
Final String hash/equality/comparison introduces no user callback or native scratch allocation, so the sorted lookup index preserves the observed property lookup relation.
Property equality has no upfront size guard, calls the right value's equality in the left table pass and then walks the right overridden insertion-order entrySet.
ObjectNode's ordinary LinkedHashMap and ArrayNode's ordinary ArrayList retain their different relations.
This profile covers unique parsed-property population followed by immutable reads, not concurrent mutation or forwarding traversal during resize.
The existing producer expiry-map algorithm supplied source evidence only; its specialized value owner is not reused for JSON.

== Native traversal scope

JSON/default retention enforces a native demand-depth limit of 128.
A deeper demanded traversal returns avro-native-traversal-limit even when the schema/value is valid for Java.
This is an explicit partial native resource boundary; the pinned Avro/JVM has no equivalent fixed depth limit of 128.
The depth counts field/property operation boundaries as well as recursive containers, and source identity/cache/size fast paths can avoid a deeper demand.
The JsonNode and SchemaHandle retention contracts state this boundary.
It must not be presented as unrestricted Avro relation or retention support at production activation.

== Admission and activation boundary

Owners reserve checked storage before allocation and retain leases after temporary conversion scopes drop.
Native growth reservations retain overlap with replaced vector/table storage.
Cached owner recounting includes text, JSON and collection geometry.

The constructor accepts a validated parsed-schema snapshot and preserves canonical object/value relations.
Field/default validation, reserved-property screening and declaration-order diagnostics belong to that producer boundary; this constructor is not an alternative raw Avro parser.
It does not yet implement the complete raw parser and mutable addProp error/allocation sequence.
Production input integration must select the actual parser numeric-node profile and apply Schema.parse's textual Float/Double field-default conversion before Field construction.
The coordinated exact UTF16 response/document decoder and canonical name gate must supply those objects without a replacement Rust String schema tree.
The Connect typed arena preserves exact UTF16 text; the complete document/input and consumer wiring remains coordinated integration work.
Full graph/default provenance, generalized union selection, arbitrary-key conversion, cache import ownership, native data ownership, downstream SMT and writer admission remain activation work.

The existing A09 array[String] connect.default:[null] suppression assertion is unchanged.
Its pinned explicit-null sentinel and String JsonNode accessor conflict remains an explicit Phase 2 reference question.
Nothing in this module establishes execution parity or resolves that conflict by rewriting the assertion.
