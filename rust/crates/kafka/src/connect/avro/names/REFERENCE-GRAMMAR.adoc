= Ordered canonical reference validation

The internal names::validate_ordered helper walks already parsed schema documents in caller-supplied order.
The production parser does not select it in this prerequisite.
A future caller supplies resolved dependency documents before the root and admits their parsed JSON owners before this borrowed walk.

CanonicalNames is a passive call-local single-writer transient.
Its BTreeSet owns only borrowed NameParts keys into the supplied immutable JSON documents.
Every newly registered definition admits a conservative tree entry allowance of 16 NameParts slots plus 256 bytes before insertion.
An inherited namespace is borrowed, so the set does not copy that payload for each definition.
The callback and name set do not escape the call or become a plan/cache field.
Owned parser, metadata and default indexes need separate admission for repeated namespace copies.

A record registers its canonical name before visiting its fields, permitting self references.
Nested declarations register in traversal order, and an earlier document can supply names to later documents.
A reference fails until its canonical declaration has been visited.
Aliases are validated after the containing declaration but never become reference keys.
The helper validates raw field-alias array/string structure without applying simple-name rules to those alias strings.

NameParts supplies the same last-dot, explicit-empty and inherited namespace rules as the Java policy.
A textual reference first tries the enclosing namespace and then the global namespace.
An object with a textual named type tries only its primary canonical name.
Object-valued or array-valued type members fail where Java requires text.
Named declarations cannot occupy a global primitive name; qualified names with a primitive suffix remain distinct.
Fields and enum symbols use the pinned Java UTF16 category rules.
Duplicate canonical definitions, fields and enum symbols are rejected.
Namespace changes remain local to the declaration's traversal, preserving the enclosing namespace after nested definitions.

The native depth guard remains 128, without an equivalent Java acceptance-limit claim.
The helper is an ordered name/reference gate, not a complete Java Avro grammar, default validator or error transcript.
Java error records are recognized by this gate; the generic native parser's error-record support remains a separate obligation.
JSON number-node distinctions, fixed-size system limits, declaration properties, union constraints and default validity require their own parser/converter qualification.
Production Java policy activation also requires the converter's branch-specific field/default lookup and complete allocation admission.

== Sources and regression scope

Apache Avro 1.11.4 Schema.java is pinned in link:sources.sha256[the category source manifest], with its retained header in link:COPYRIGHT[the source notices] and link:LICENSE-APACHE[Apache license].
Schema.Name at lines 706–723 owns canonical namespace construction; NamedSchema at 789–795 rejects primitive declaration names.
Names.get and Names.put at 1580–1609 own textual fallback and duplicate registration.
Schema.parse at 1689–1832 owns pre-field record registration, declaration traversal, object-type lookup and alias timing.
Schema.parseAliases at 1835–1848 accepts only array/string structure, and required type text is extracted at 1853–1865.
EnumSchema at 1069–1085 owns symbol validation and duplicate/default checks; Field construction at 556–562 owns simple field-name validation.
The gate is translated from those source branches and does not consult a Java execution oracle.

Twelve regression sources cover dependency order, self and nested references, aliases excluded from canonical lookup, textual/object fallback, namespace restoration, duplicate/global primitive identities, duplicate-field timing after later schemas, type-wrapper rejection, Java field/symbol categories, admission before insertion and borrowed long namespaces.
All prior name/selector tests and production parse/conversion bodies remain unchanged.
Rust/Java compilation and regression execution remain pending under the Phase 1 work order.
