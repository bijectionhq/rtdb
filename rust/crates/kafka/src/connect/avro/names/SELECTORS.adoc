= Java names and borrowed record lookup

link:../names.rs[The internal helpers] provide a call-local Java name policy, borrowed canonical name parts, a streaming scrub comparator, and borrowed record selection.
They are prerequisites for the converter's ordered reference checks and allocation admission.
The production parser and conversion routes do not select these helpers yet.
The policy neither registers nor reads a process-global validator.

Name validation uses the pinned link:README.adoc[UTF16 category data and source proof].
Apache Avro 1.11.4 Schema.Name splits at the final dot, validates only the suffix, and uses the prefix in preference to a supplied namespace.
Empty namespace suppresses inheritance; namespace text is otherwise preserved.
The native scoped policy returns an explicit empty namespace for global names so subsequent qualification retains that identity.
Borrowed name parts expose checked owned-text and fullname payload lengths; container headers, repeated namespace copies, and other conversion allocations remain the caller's admission responsibility.
This policy alone does not impose Java's ordered canonical-reference grammar or primitive declaration-name restrictions.

Confluent 7.8.0 AvroData.doScrubName first preserves an already valid ASCII identifier.
Otherwise it invokes Java URLEncoder with UTF8, prefixes x when the encoded first character is a digit, and replaces each non-ASCII-word encoded character with underscore.
For valid Rust strings, the internal iterator emits the same composition without a heap buffer: letters, digits and underscore pass through; URL-safe punctuation and space become underscore; other UTF8 bytes become underscore plus two uppercase hex digits.
For example, é becomes _C3_A9, plus becomes _2B, and a leading digit gains x.
An empty input remains empty, and a disabled scrub flag preserves every input byte.

AvroData.toConnectData's IndexedRecord branch iterates destination Connect fields, scrubs each lookup name, obtains the exact raw source field, and reads its position.
Selection keeps that source child's physical schema with its borrowed value.
Several destinations may therefore select the same source child.
Output field names remain the destination names.
The native selector scans record.fields directly because the native record.lookup index also contains field aliases; Java's raw field lookup does not substitute those aliases.
The actual-schema/value labels and lengths are checked before positional selection.
