= Borrowed Avro record conversion context

This inactive helper models the call-local record-reference lifecycle used by AvroData's ToConnectContext.
It has no production callers and does not activate parser, graph, default or union behavior.

ToConnectContext is a passive single-writer transient borrowing the actual Avro schema owner.
CycleReference is a passive copied caller-owned target identity plus the wrapper's optionality bit.
The context owns only its admitted record and detected-cycle vectors and retains no output graph or callback.
All source borrows end before the original schema owner can be dropped.
The caller retains each vector-growth reservation until the context is dropped.

Record-reference lookup uses actual schema object identity.
Registering a structurally equal record at a different address does not provide a reference to the first record's target.
An opaque RecordIdentity can only be constructed by selecting the canonical record in the immutable named-definition owner.
The original root and inline named schema clones are normalized to that owner, as are actual Ref selections, without cloning or allocating per selection.
The root record and its resolved self-reference consequently identify the same object even though the current AvroDatumPlan also retains a separate root Schema clone.
Independent named-definition owners retain distinct identities.
Missing canonical definitions are an outer error rather than permission to use an arbitrary clone address.
Registration happens before the record's fields are built.
A reference hit records the detected source and returns a wrapper with the optionality requested by that reference, independently of the registered wrapper's own optionality.
A cached top-level record seeds the same table with its cached target; cached nonrecords do not.
Registering an already-present identity replaces its target without growing the table.

Detected-cycle membership uses an explicit required Java Schema equality comparator during reference insertion and at finish.
The native Apache Avro canonical-form PartialEq relation is not a substitute: Java equality includes custom properties and field defaults that canonical form can discard.
The insertion comparison runs before detection-vector admission and publication.
A structurally equal detection is not inserted twice, independently of the distinct identity-keyed record-reference entries.
A completed record is removed only when no detected record matches that structural relation.
Comparator errors propagate through the outer native Result without changing either context table.
The activation caller must implement the actual Java structural relation and the Java HashSet hash/collision/equality evaluation order, errors and scratch at both membership boundaries.
The comparator-only prerequisite does not claim that a linear equality scan reproduces HashSet's hash filtering or collision-tree evaluation order.

Each vector growth checks the doubled capacity and a 16-times slot allowance plus256 bytes, admits that amount, then requests the new buffer before publishing an entry.
Earlier buffer reservations remain retained while old/new growth buffers can overlap.
Record-table and detected-table admissions are separate and precede their own mutation.
Rejected admission leaves the corresponding entry unpublished.
