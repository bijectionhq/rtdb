= Persistent UTF8 byte symbols

`ByteSymbols` implements the pinned default ByteQuadsCanonicalizer table profile for Jackson216 and Jackson221.
It is a registered inactive capability under the Registry response decoder's existing test gate.
The installed HTTP route, ordered bean machine, observation-driven UTF8 cursor and character canonicalizer remain unchanged.

== Source profile and API

The passive FactoryProfile value contains the selected source profile and actual byte-factory seed.
ByteQuadsCanonicalizer.createRoot derives its odd seed from System.currentTimeMillis, while the character factory uses identityHashCode.
The byte and character profile carriers therefore remain distinct.
No native clock, random number or identity supplies an observed Java seed.
The caller must establish the effective mapper source profile and original factory seed before using the capability for a source stream.
The conflicting declared dependency versions do not establish the effective classloader or shaded distribution.

The default Registry mapper enables field-name canonicalization, interning and FAIL_ON_SYMBOL_HASH_OVERFLOW.
This API models that profile; nondefault placeholder children and disabled features are outside it.
Root mutation is unavailable through the API, and release consumes its child.
The actual global InternCache/JVM identity and Java allocator/error domain remain separate qualification.

`child` attaches the immutable factory snapshot to the caller's ConversionContext before cloning it.
`find` uses already packed source quads and returns the admitted name or a miss.
An empty quad input returns the factory's admitted empty text without interning or mutation.
Quads.new constructs a borrowed nonempty signed-length-compatible view without allocation.
`prepare_name` admits the exact decoded UTF16 name and its shared owner before creating them.
`add` receives that same-region prepared owner and a borrowed InternAuthority.
The caller performs lookup before decoding/preparing a miss and must supply the actual parser's quad packing, padding, escape handling and name-length demand.
The table does not infer those lexical facts from decoded text and does not accept an observation declaring lookup success.
Name preparation, additions and release use the child's creation context.

The interning authority receives the admitted name at the source add stage and returns the original or an admitted existing owner with identical UTF16 contents.
Changed contents are an outer unsupported-authority failure.
Native failures during additions propagate unchanged and poison the unpublished child.
Name-preparation failures occur before addition and leave the child unchanged.
No callback is retained by the factory or beyond the call.

== Table order

The four quad hash shapes retain Java wrapping arithmetic, logical right shifts and the signed right shift in the long-name fold.
Lookup visits primary, secondary, its tertiary bucket and shared spill slots in source order, including the long-name secondary-empty behavior.
Long names verify every stored quad after their hash and length match.
The source's unused slot words remain untouched when adding short entries.

The first add copies the shared quad and name arrays before interning.
Add then interns its incoming name before selecting its final slot.
An empty primary slot returns before checking whether the table needs rehashing.
Occupied-primary insertion checks the source count/spill threshold before trying secondary and tertiary slots.
The spill cursor advances before the full-spill constraint check.
Full spill at sizes through 1024 resizes; at larger sizes it preserves that mutation prefix and fails under the default overflow feature.

Rehash installs new arrays and visits old physical slots through the retained spill cursor in ascending order.
Each old name is interned again through the ordinary add stage.
The implementation borrows its old quad range while copying the replacement entry; it does not allocate a redundant native temporary quad vector.
All old arrays and names remain live and charged throughout that traversal.
The copied-count guard retains its completed replacement-table prefix when it reports the source consistency failure.
Growth above 65536 clears both arrays and resets offsets/count in place, retaining their existing capacity and continued canonicalization.

Jackson216 compares count with a floating 80-percent threshold; Jackson221 uses its unsigned long multiply/shift helper.
The selected source arithmetic is retained for each profile.
On the supported power-of-two table sizes, the integer count decisions coincide.
Jackson221 explicitly rejects a negative wrapped long-name end before arraycopy; Jackson216 reaches the arraycopy bounds error for that overflow.
LongNameOffset retains the source profile so these unchecked source paths stay distinguishable.
Signed source array-length overflow is separate from native address/allocation overflow.
No complete exception text, stack or location rendering profile is established here.

Release ignores unchanged/shared children and same-count current-root snapshots.
A differing completed child proposes replacement rather than union merging.
Counts above 6000 propose a fresh 64-slot table.
Publication compares the actual current snapshot read for that proposal and can lose to another publication.
Source collision and consistency failures remain releasable; native poisoned children do not publish their partial state.

== Owners and admission

ByteSymbols is a passive factory identity holding one immutable table snapshot behind a synchronous publication lock.
ByteChild is a passive parser-local single-writer Shared/Private/Poisoned transient.
Table is one size/count/tertiary-geometry/spill-offset/long-offset/quad-array/name-array value.
Area owns one admitted vector and its original reservation.
Quads borrows immutable input storage for one operation; FactoryProfile is an immutable source-observation value.
The existing immutable SymbolName owns exact JavaString text and its full shared-owner reservation.
No active object, condition waiter, parallel state registry or additional budget pool is introduced.

Root/table publication-owner storage, quad/name arrays, copy-on-write replacements, long-area growth and decoded shared names are admitted before allocation.
Vector replacement is admitted while the old vector remains live.
Child creation retains every inherited table/name reservation in the same context without reserving its backing again.
Release also retains a current root that another child may have published.
Returned text and persistent roots retain their original full reservations after the context ends.
The context retains accepted charges through its region after transient backing drops.
Native allocator overhead and complete parser/global interning memory still require later qualification.
