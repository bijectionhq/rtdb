= Observed-window Registry decoding

`schema_string_from_window` and `schema_from_window` consume an owned `WindowInput` plus borrowed `LexicalObservations` in the caller's existing ConversionContext.
WindowInput contains an already detected UTF8 byte window, UTF16 parser character window or UTF32 parser character window.
The caller supplies the exact published bootstrap, decoder and parser-window observations before handing over that owner.
Transfer occurs before the first parser byte/character is consumed: directly after bootstrap for UTF8, or after constructing a new parser character window from a fresh detected UTF16/UTF32 decoder.
The caller must not have called parser next or decoder read/read_one/ready before transfer.
Bootstrap lookahead and BOM removal belong to the earlier detection stage and are permitted.
The transferred UTF32 reader's retained Jackson profile must equal the requested lexical profile; a mismatch is rejected before first-character demand and the owner is still closed.
No entry point selects an HTTP segmentation, recycler capacity, Jackson profile or symbol seed.
The production HTTP routes do not call these entry points.
All24 regression sources are unexecuted.

== Demand and lifetime

The passive ObservedCursor advances its owned window only when the token machine demands the next byte or Reader unit.
A single inline lookahead retains an already consumed physical unit until the logical token step accepts it.
Peek, repeated field-name comparisons, map-key copies and numeric-string publication never replay the read tape.
The current numeric spelling uses1008 inline UTF16 slots; an accepted number has at most1001 digits and four punctuation/sign units.
Overlong numbers continue lexical scanning without retaining additional spelling, then use the existing demanded number-length guard.
Both pinned Reader fast paths count an absent fractional or exponent part as zero, while ReaderBasedJsonParser._parseNumber2 passes minus one for each absent part to ParserBase.resetFloat.
A leading-zero integer part forces that slow path; crossing a physical parser window while scanning the token or its terminator also selects it, including an EOF refill.
The cursor retains the initial physical processed counter before signed-number lookahead and compares it after scanning.
A slow Reader float with one absent component can therefore contain1001 digits while its measured length remains1000.
The fast Reader float, UTF8 float and integer guards retain their corresponding original lengths.
All typed bean constructors, duplicate fields, coercions and ordinary-setter buffering use the existing bean machine.

Field names finish before colon/value prefetch.
UTF8 names retain admitted raw spelling while completing escape and byte-length validation, then decode that retained spelling without reading the source again.
Reader names retain the actual UTF16 units produced by the parser window.
Completed names become admitted immutable JavaString values.
The next field and its value token are prefetched before a ready creator runs.
A prefetched quoted value retains only its opening quote and does not demand its body until the bean getter or following token step needs it.
Unknown scalar strings remain lazy until that following step; unknown containers use the same iterative admitted frontier as known containers.

The entry point establishes cursor ownership before requesting the first token and closes the window after either decoding outcome.
An already completed root does not force a trailing-token or EOF request under the pinned default mapper settings.
A successful bean followed by a close failure returns that close failure.
A failed decode/read keeps its primary failure and retains a subsequent close error in `ObservedDecode.suppressed_close`.
`observations_consumed` includes bootstrap calls already consumed by the transferred window and its demanded close calls.
Window buffers, frame vectors and string scratch drop before the call returns; their accepted context charges remain until the existing context region ends.
Returned JavaStrings and collections retain their own full leases after context drop.

All Values growth admits replacement storage while old storage is still live.
String scratch remains admitted while shared JavaString backing is admitted and copied.
The cursor retains no admission callback, external task, generic JSON tree or additional budget pool.
Numeric spelling and lookahead are bounded inline state and allocate no heap storage.

== Observations and qualified branches

NameObservation.start is the opening-quote position for one field occurrence.
UTF8 positions count bytes from the original InputStream origin, including a consumed BOM.
Reader positions count UTF16 units from the first decoded parser character, excluding a consumed encoding BOM.
Failure.offset follows those same units, while the legacy slice entry points retain their byte offsets.
The shared diagnostic label is therefore `offset`.
Negative/wrapped source positions or positions outside native usize return an unsupported capability failure.

Each demanded field requires the next NameObservation to contain that exact position and the successful Java canonicalizer's exact UTF16 result.
An absent or mismatched observation returns an outer unsupported-source-profile anomaly before colon/value prefetch.
Capability failures created by this observed-window boundary have AnomalyCategory::Unsupported.
The caller must retain and admit any observation storage for the whole call.
The helper does not establish the actual ByteQuadsCanonicalizer/CharsToNameCanonicalizer hash, collision, interning identity, overflow outcome or allocator behavior.
UTF8 raw-name decoding failures are also gated because a pre-existing symbol lookup can change whether the decoder is reached.
An accepted-name observation is a source-profile condition and cannot be assumed for live HTTP.

TextBufferObservation retains its existing opening-quote position and actual positive UTF16 segment capacity contract for UTF8 values.
At most one observation may describe each position.
Reader value strings through20million units preserve their actual unit accessor path; over-limit Reader text remains unsupported.
Reader names longer than50,000 units are unsupported until their shared-buffer/text-segment and final canonicalizer branches are modeled together.
The UTF32 pending-unit differences and UTF16 replacement/readiness branches come from the actual transferred reader owners, never raw-byte redecoding.

Invalid literal spelling and identifier suffixes require the source diagnostic-token scanner and return unsupported-source-profile here.
Core2.21.7's non-ASCII UTF8 literal suffix also remains gated until its same-window rewind and reload-dependent error decoder are integrated.
Core2.16.0 retains the inspected lead-byte reread failure for that suffix branch.
Unexpected value-token dispatch outside the supported token grammar is gated rather than assigned a guessed Java syntax exception.
Custom document/name/string/number constraints, non-default parser features and source error-reporting configuration remain outside this capability.
Default document limits remain unbounded as pinned by the input-window prerequisite.

Native admission, allocation and overflow failures remain the original Failure::Native anomalies.
Observation-tape mismatches have registry-input-observation diagnostics, source I/O and zero-read errors have registry-input-io diagnostics, and source encoding failures have registry-input-encoding diagnostics.
These outer diagnostics do not become bean coercion or constructor failures.
The lexical FailureKind tags retain the existing decoder's diagnostic vocabulary and do not establish a complete Java exception/message/location rendering profile.
