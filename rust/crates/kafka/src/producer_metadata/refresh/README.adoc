= Producer metadata refresh and throttle state

`RefreshState` holds Java Metadata's caller-driven request demand, signed versions, refresh timestamps and backoff counts.

* Response application has a visible stage before snapshot construction.
** `begin_response` checks close, compares the captured request version, updates refresh time and version, clears failed-attempt count, and increments equivalent-response count.
** A full response also clears full-refresh demand and advances the last successful full-refresh time.
** A later snapshot failure retains these mutations.
** Leader-epoch progress calls `metadata_progress` at the corresponding `updateLatestMetadata` branch.

* Backoff preserves the Java observation sequence.
** `JavaBackoffObservations` supplies the pinned JVM's `Math.log`, `Math.pow` and `ThreadLocalRandom.nextDouble` results.
** Construction observes logarithms only when maximum backoff exceeds initial backoff.
** Delay calculation observes attempt backoff before expiry can reset the equivalent-response count, then observes equivalent-response backoff only when that count remains positive.
** Signed versions, counters and millisecond arithmetic wrap; floating-point-to-long conversion truncates and saturates.
** A production observation provider remains required; this prerequisite does not substitute Rust's native logarithm, exponentiation or random generator.

* `ConnectionThrottle` belongs to one existing connection.
** A positive Metadata throttle applies from response version 6 onward.
** The caller's callback increments that connection's remaining in-flight request throttle times before its deadline can change.
** The deadline never regresses under Java's signed comparison.
** Readiness uses the deadline comparison; connected poll delay uses a positive remaining throttle delay.
** `NetworkClient` applies this throttle before its metadata updater processes the response.

Eight source regressions exercise observation order, dominated backoff draws, full and partial request scopes, pre-snapshot mutation, close rejection, equivalent-response expiry, failed-fetch backoff, truncation and cap, signed wrap, protocol gating and throttle deadline arithmetic.
The integration fixture imports the production source directly.

The producer owns serialization, metadata response routing, snapshot construction, topic retention, waiter notification and actual send readiness.
The metadata updater's empty-broker retry and rebootstrap handling remain integration obligations.
The production math/random provider, retained snapshot and whole-native-producer allocation bound remain unfinished.
