= Producer metadata state

* D1: `ProducerMetadata` is a passive owner driven by one serialized caller.
** It owns topic expiry, request membership, refresh state, last-seen epochs, producer-lifetime RoundRobin counters and the last successful bootstrap address owner.
** `MetadataRequest` retains the chosen request version and topic sequence until its response arrives.
** `PreparedSend` retains one selected partition with the record and the immutable generation used for selection.
Retries reuse that selected partition.

* D2: `Snapshot` is an independently retained immutable generation.
** Its broker, partition, topic-ID and set collections retain the shared Java HashMap engine's table/tree encounter geometry and leases.
** Partial updates build the merge map, then replay its values into the final snapshot map.
** The reverse UUID collector rejects duplicate IDs before the final partition map is constructed.
** Broker duplicate rejection occurs in the response holder before topic wrappers are built.
** Partition availability requires a resolved leader node, including a node with an empty host or negative port.
** `brokers()` exposes holder-map encounter order.
Qualified ordinary responses retain a shuffled `Cluster.nodes()` list sharing the map's original Node owners.
Bootstrap generations retain a shuffled list of independent Node owners built in resolved endpoint order.

* D3: Response application preserves source mutation stages.
** The holder and the network response error map precede the rebootstrap/empty-broker branches.
`MetadataResponse.errors` rejects every null topic name before checking its error code.
** Refresh mutation precedes snapshot construction.
** Snapshot publication precedes recoverable error-set copies and epoch pruning.
** Epoch pruning uses HashMap iterator removal with its saved-next traversal, stored hash and `movable=false` tree geometry.
** Errors, nullable names and epoch sentinels follow the pinned Java wrappers.
Only epoch `-1` is absent; all negative leader IDs are absent.
Unknown Kafka error codes become `UNKNOWN_SERVER_ERROR`.
** New-topic membership prevents expiry until the topic appears in a successful update's response.
The expiry boundary is `expiry <= now` after that membership is removed.

* D4: Admission follows the retained native owners.
** `Text` retains replacement-decoded UTF8 bytes, its Java string hash and a lazy identity witness.
** Partition keys, replica arrays, brokers and snapshots retain their own shared payload reservations.
** Vector replacement admits the new storage before moving values and freeing the old storage.
** Shared-map collection reservations remain with the actual table owner.
** Each reservation adds a checked control allowance for the budget and every ancestor reported by `MemoryBudget::reservation_lease_count`.
The per-control allowance is `size_of::<MemoryReservation>() + 4 * size_of::<usize>()`.
Allocator metadata and the already constructed budget graph remain part of the enclosing infrastructure domain.
** Native admission, allocation or unsupported-profile failure ends the mutable producer capability.
Already retained snapshots remain readable and charged until their last owner drops.
This termination policy is native resource behavior, not Java recovery parity.

* C1: Activation requires the remaining collection and owner profiles.
** Active topics implement the single-writer ConcurrentHashMap String-key profile, including ordinary append order, resize threshold and last-run transfer geometry.
Treeification retains the first-list order, subsequent tree insertions prepend to that list, and the lookup root remains independent of the encounter head.
Removal balances tree links and uses the source shape criterion for untreeification.
Transfer retains first-list split order, flattens sides of at most six entries and preserves an unsplit larger tree's original root.
Tree links occupy admitted inline entry storage; tree conversion, insertion and removal allocate no separate native tree node or bin.
Only non-null immutable String keys are accepted by this owner.
Their equal-hash comparison uses unsigned UTF16 units, and distinct String values cannot reach the generic Java identity tie-break.
** HashMap tree ties request a Java identity witness only at the actual `KeyOps.identity_hash_code` boundary.
The default provider rejects a required witness.
Native addresses, region IDs and allocation counters do not supply Java identity hashes.
** String comparisons use unsigned UTF16 units; UUID comparisons use signed 64-bit halves.
Primitive integer and UUID lookup operations have no externally supplied callbacks.
** Java math/random operations remain supplied through the refresh observation provider.
** The network adapter must resolve source bootstrap endpoints, supply the qualified Java shuffle authority, select brokers and own throttles, fatal errors and waiter notification.
It must carry the captured request scope into `apply` after connection throttling and use `PreparedSend` for actual enqueue retries.
** Construction, broker/thread growth, automatic native metadata caches, ApiVersions sort storage, TLS/SASL, ordinary outbound owners and compression overlap need their own finite admitted domain.
Receive-frame and ordered-request accounting do not bound those owners.
** The production module is awaiting its coordinated registration and DLQ adapter.
The standalone integration fixture imports these production sources directly.

== Bootstrap generations

`prepare_bootstrap_addresses` creates an admitted immutable owner for an already resolved source address list before the source bootstrap call.
Hosts are the caller's exact InetSocketAddress.getHostString values within the represented UTF8 domain, and ports use the source address's unsigned16-bit domain.
It performs no DNS lookup, canonicalization, reverse lookup or re-resolution.
Clones retain the original endpoint owners and budget domain; unrelated-budget input is rejected after the source refresh prefix.

`bootstrap` first marks a full refresh and increments the signed update version with wrapping arithmetic.
It builds MetadataSnapshot's default HashMap using source negative broker IDs beginning at -1, then independently constructs Cluster.bootstrap's source input node list.
Only the Cluster list is shuffled.
`brokers()` retains map encounter order, while `bootstrap_cluster_nodes()` borrows the qualified shuffled list and `is_bootstrap_configured()` exposes the source flag.
Bootstrap has no controller even though its map contains broker -1.
Ordinary response generations continue resolving their actual signed controller ID, including -1 when present.
The closed cluster profile stores that distinction together with its applicable state.

JavaShuffleObservations denotes the pinned Collections.shuffle default Random acquisition and complete Random.nextInt operations.
`begin` is called even for empty or singleton lists; larger ArrayList profiles request bounds n down through two and swap from the end.
The provider retains its own source generator state, including class-global Random acquisition/reuse and any seed/rejection history.
It admits its native state and scratch through the supplied synchronous byte authority and retains those leases through actual final release.
The producer and snapshots retain no provider or callback.
Missing, exhausted or out-of-range observations fail explicitly; this implementation supplies no native random fallback or invented fixed order.
The caller supplies the history shared with the initial and ordinary Cluster constructors.

A completed Snapshot is published before the already prepared address owner is installed.
Construction failure keeps the previous snapshot and addresses while preserving the source full-refresh/version prefix.
The existing native failure policy then ends mutation, with previously retained snapshots still readable.
Missing-address rebootstrap instead preserves that prefix as a distinct source semantic failure and permits later bootstrap.
`rebootstrap` reuses the retained resolved owner and preserves topic/epoch/counter/error/backoff state beyond the source prefix.
It neither resolves addresses again nor adds a closed-metadata guard absent from the inspected source.
Endpoint vectors/text, both Node collections, HashMap storage, shuffled list storage and immutable Snapshot owners are admitted before their actual allocations.
Thirteen additive source cases cover those orders, lifetime/failure boundaries and state preservation; no runtime result is claimed.

== Initial and ordinary Cluster node order

`new_with_cluster_nodes` observes the default Random acquisition for `Cluster.empty()` before initializing the source backoff.
`apply_with_cluster_nodes` shares the response holder's Node objects, starts from its broker map's values in encounter order, and shuffles that independent list.
It observes the shuffle after the reverse topic-ID and partition maps are complete and before the Cluster's grouped index work.
Both full and partial response publication use this same node-list constructor.
Responses with duplicate brokers, duplicate reversed topic IDs, REBOOTSTRAP_REQUIRED, no brokers or closed metadata can end before any shuffle is requested.
A native shuffle failure preserves the previous generation after the source refresh prefix and ends mutation.
`Snapshot::cluster_nodes()` borrows the node order from the retained ordinary or bootstrap generation.
The unqualified `new` and `apply` entry points preserve the fixtures that inspect response state without a shuffle observation.
They yield an unqualified snapshot instead of a node-order substitute.
Transport scheduling and production qualification of Java class and clock histories remain separate obligations.
Five additive source cases cover initial, full and partial observation demand, shared Node identity, failure order and retained ownership.

== Bounded Random and serialized shuffle acquisition

`JavaRandom` implements stock Random's 48-bit seed and bounded int draws, including rejection draws and the signed overflow test.
`JavaRandomSeeds` owns a class's default-constructor seed uniquifier and advances it before requesting the constructor's signed nanosecond observation.
`JavaShuffleRandom` borrows the caller's Collections slot for serialized acquisition and reuses its generator on later shuffles.
The caller supplies the slot, seed history and clock and owns admission for any enclosing heap allocation.
Concurrent replacement of the Collections slot during first acquisition requires a separate observation.
The existing observer interface remains available for other qualified histories.

== Ordered request exchange

`ProducerMetadata::start_exchange` captures the producer request's scope and delegates the admitted topic list to the selected native bootstrap endpoint or learned broker.
The native producer must match the metadata owner and enable automatic topic creation.
The temporary descriptor array is admitted through the metadata budget and borrows the request names until native submission copies them.
Polling the native exchange returns the original scope with the borrowed response, even after the metadata owner has requested a later generation.
The transport retains the response and its account through producer shutdown.
The network owner still needs to qualify the target, manage the request lifecycle, process throttles and apply each response once.

== NetworkClient refresh decisions

`MetadataUpdater` owns the source in-progress request scope and the rebootstrap attempt start.
It computes refresh backoff before the in-progress wait in `maybe_update` and skips that computation in `is_update_due` while a request is pending.
It starts or resets the attempt clock at the source mutations and repeats the node scan after a successful rebootstrap.
The selected node's send eligibility is checked again, followed by the cluster's connecting states and the selected node's reconnect eligibility.
The updater retains the distinct attempt-clock outcome of a published response, an empty response and a server-requested rebootstrap.
A synchronous unsupported-version send reports the fatal cause and failed refresh before publishing the original request scope.
Disconnect bookkeeping records any due failure before a fatal authentication cause and the request for a full refresh.
The caller owns actual native completion, connection and clock observations, diagnostics, response application and waiter delivery.

`sources.json` records the exact consulted Kafka and OpenJDK archive members.
`COPYRIGHT` retains each complete pre-package prefix, including adjacent legal blocks.
The accompanying license and notice files are verbatim copies.
The source regressions cover duplicate failure stages, UTF8 replacement, epochs and UUID changes, both partial map replays, expiry, request versions, topic errors, rebootstrap ordering, immutable selection ownership, admission release, ordinary-bin transfer, unsupported identity profiles and native admission failure.
Twelve additional source functions cover active-topic trees: independent first/root geometry, small-table collision presizing, equal-string identity retention, shape-triggered flattening, deletion balance, both transfer profiles, unsigned UTF16 comparison, admission failure, slot reuse, full request order and response-driven expiry.
Runtime validation remains gated by the source-only phase.
