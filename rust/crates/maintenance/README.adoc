= Maintenance

`available_jobs` selects work from an immutable trie-catalog snapshot.
Selection covers L0 plus partial L1C, historical L1 size tiering with partial L2H, and four-way IID tiering.
Only live inputs participate, and every recorded output shard contributes its high-water mark, including a nascent output awaiting its siblings.

`SegmentCompactor` is a passive capability executing one immutable `CompactionJob` on the caller's task.
It opens immutable inputs, merges pages by IID and descending system position, resolves L0 same-transaction overlap, partitions historical output by recency, and writes data and metadata files.
Small uncompressed primary files without dictionaries can supply Arrow buffers directly from admitted object bytes, including local read-only mappings and authenticated remote reads.
Encoded primary bytes shared by a job use at most 1 MiB or one eighth of the shared memory limit, whichever is smaller.
File-backed inputs use the job's temporary directory, and compaction can retry preparation and merge with file-backed primary inputs under the same catalog hold after memory pressure.
Temporary files use the filesystem's available space by default.
An explicit `MergeConfig::temporary_byte_limit` bounds a job's temporary work.
Entity history and directory builds use the same retained reader for stored primary files, release it after each source, and keep using the file reader for staged local inputs.
An artefact read that runs into memory pressure can spill its admitted bytes and restart that source before artefact publication.
The system position pairs the commit time with the assertion's position inside a hosted Proposal landing.
Governed pages store the position in `_commit_position`.
Compaction retains the full valid interval and image of each positioned assertion until it crosses an erasure.
A positioned assertion's recency is at least its commit time, including when a later assertion in the same commit covers its entire extent.
Recency partitioning uses `CivilDate` for the complete signed 64-bit microsecond input range, including dates beyond Chrono's calendar range.
Weekly, monthly, quarterly and yearly partitions include their UTC midnight ceiling.
Persisted partition metadata and scan ceilings check the separate signed 64-bit microsecond bound when converting a trie date back to midnight.
The final layout supports IID branches, bounded recency cells, single-entity recency pages, and optional run-end encoded historical IIDs.
Data page copies retain signed decimal precision and scale and preserve raw coefficients under the merged field schema.
They reject parameter relabeling and check physical coefficient width without imposing ordinary writer precision limits on stored cells.
Data and metadata files are published through `ObjectStore::put_file` before a notification is returned.
Repeated publication accepts only identical bytes at an existing object key.
An upload in progress must finish before the job's temporary files are released.
Publication errors retain the storage anomaly's category, code, message, and context, and add the requested relative object key and `put_file` operation.

`CompactionDriver` and `CycleDriver` are active objects whose `run` methods own their event choices.
The database owner runs and joins them.
Compaction belongs to the database lifetime; each garbage-collection driver belongs to one leader term.
With automatic compaction disabled, a pending `compact_all` request drives scheduling until quiescence.
Driver queues are bounded, block signals are conflated, and request handles backpressure callers when their queue is full.
Completion channels are per-request monitors; merge heaps, page builders, file writers, and cycle work lists are single-owner transients.
The cancellation token is checked between object operations, and started compaction jobs are drained before driver teardown completes.

`CompactionPublisher` completes after a source `TriesAdded` record is durable and admitted processing has applied it.
`TrieDeletionPublisher` is a leader-term capability completing after admitted replica read-back applies the deletion.
Its owner must fail outstanding requests when that term ends.
These capabilities own publication and progress waiting; maintenance never writes serving catalog state.
An executor or publication failure records that job as failed for the driver's lifetime, and later `compact_all` callers receive the failure without an automatic retry.
A new database lifetime may retry the deterministic object keys.

`CompactionObserver` is a passive synchronous diagnostic capability retained by `CompactionDriver`.
The driver reports each non-cancellation worker failure once, including a failure returned while shutdown drains that worker.
The exact `rtdb.maintenance/closed` code and the `Interrupted` category are excluded, following the cancellation and interrupt exclusions in `Compactor.kt`.
Cancellation of the owner does not suppress an actual storage or publication error returned during draining.
Later signals and `compact_all` requests that encounter the retained failure do not emit it again.
`CompactionFailure` is a passive event value containing the job's `schema/table` name, output trie key, typed anomaly code/category, operation, relative object key, and message digest.
The default `LoggingCompactionObserver` logs one ERROR event per failure through `tracing`, carrying the failure's fields, without an exporter or background task.
`with_observer` replaces that sink before the driver starts.
Observers return promptly and do not panic; an unavailable log output does not alter the worker result.

`CompactionFailure::write_json_line` encodes the event as JSON: `compaction_failed`, with `table`, `output_trie_key`, `anomaly_code`, `anomaly_category`, `operation`, `object_key`, `permission_denied`, and `message_sha256` fields.
Missing operation or object-key context is serialized as null.
`permission_denied` comes only from the typed `rtdb.storage/permission-denied` code.
`message_sha256` is lowercase SHA-256 of a present message's UTF-8 bytes, including the digest of empty bytes for an empty message.
An absent message has a null digest.
The event omits the raw message, provider URL, local root path, and arbitrary anomaly context.
Operation context accepts lowercase ASCII identifiers and object-key context passes `ObjectKey` validation.

`TrieCollector` and `BlockCollector` are passive cycle capabilities.
Trie collection uses one immutable snapshot, bounded table/delete concurrency, and chunks containing at most 1024 trie keys.
An uncoordinated sweep removes data before metadata, drains started deletes, and publishes one deletion record per completed chunk.
Coordinated sweeps use a durable intent, an installed replica receipt and a storage retirement grant.
Age-based collection uses canonical block roots through the captured catalog's installed block.
Compactor reset stages its superseded compacted pairs in the same retirement journal, with a required successor checkpoint block and naming epoch.
Collection can resume those intents after restart even when the age policy selects no new garbage.
L0 recovery files are excluded.
Block collection removes expired catalog and table-block files without replica publication.
Installed serving stores can queue expired oversized-message files for journal-checked reclamation.
Per-table failures are reported through `CollectionObserver` and isolated from other tables.
Each deleted trie's deletion duration is reported through `CollectionObserver::trie_deleted` (`xtdb.gc.tries.delete.timer`).
An administrative awaiter receives a cycle started after its request; automatic signals alone are subject to the enabled flag.

== Reference and qualification

Selection follows `job_calculator.clj` and `job_calculator_test.clj`, including the nascent-output case in issue #4930.
Merge and layout follow `SegmentMerge.kt`, `PageTrieWriter.kt`, `StreamingIidTrie.kt`, and the compactor tests.
Collection follows `TrieGarbageCollector.kt`, `BlockGarbageCollector.kt`, and their test classes.
Failure reporting follows `Compactor.kt`'s job/output identity and caught exception; the native event retains classification and a message digest rather than the JVM exception text.
`tests/failures.rs` covers exact-once reporting, retained failure suppression, publication errors, shutdown draining, JSON sanitization, and actual data-success/metadata-denial publication for local and remote storage anomalies.
The executable test sources in this crate cover selection, historical splitting, raw decimal preservation in current and historical pages, deterministic retries within the Rust writer, temporary-file cleanup, failure retention, concurrent cycle awaiters, block retention, deletion ordering, and L0 preservation.
No Rust compilation, test execution, JVM comparison, or simulation has run during Phase 1.

Cross-JVM Arrow byte identity remains unverified, including schema child order, dictionary encoding, FlatBuffer allocation order, and exact page boundaries.
Compressed data and metadata inputs reserve their declared decoded buffers before opening dictionaries or pages.
The job enforces temporary disk growth before writes and holds memory reservations for input pages, decoded rows, output pages, and retained metadata.
Same-time resolution and recency calculation reserve the current entity's temporal ceiling in the compaction budget and read polygon ranges from it.
Those conservative estimates are not a proof of bounded peak allocation for every nested Arrow schema.
Catalog enumeration, object-store listings, and protobuf decoding still need complete peak-memory accounting.

`block-gc.allium` describes a zero-retention sweep followed by failure.
The pinned collector validates positive retention during construction; this implementation follows that source behavior and rejects the configuration before deletion.
The discrepancy is unresolved rather than an executed compatibility result.
