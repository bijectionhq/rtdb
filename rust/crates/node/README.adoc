= Node and session source

Session control expressions and transaction characteristics use caller-owned asynchronous evaluation.
BEGIN validates its preconditions and evaluates characteristics before publishing transaction state, so dropping a pending option evaluation leaves the session idle.
Successful BEGIN still installs the same transaction characteristics atomically through `begin_with`.
`tx.allium` requires complete option evaluation and validation before the transaction becomes observable.
`tests/native.rs` retains a cancelled SLEEP-in-BEGIN case followed by a successful sibling command, as unexecuted source.

Prepared query execution admits unsigned arguments at their signed vector width.
`PreparedSql::open_query_typed` retains supplied vector field types for typed nulls and empty containers; `open_query` infers fields from its values.
Result-schema description preserves supplied physical parameter fields, while opening a query binds against the signed execution field view.

`NativeSession::reserve_ordered_present` requires a database write grant and an idle native session in autocommit mode with read-write access.
It submits an empty transaction without caller-supplied system time or an idempotency key and returns the transaction key after apply, advancing the connection's await token.
Transactions in the same database history that resolve after the reservation take strictly greater system times.
Each call can append a fresh reservation, including a retry after an unknown outcome.
The reservation changes transaction bookkeeping only and marks its `xt.txs` metadata with `rtdb_present_reservation`.

`NodeOptions::owned_relations` enables the native owner-scoped relation API.
`NodeOptions::default` reads no environment: it takes the reference's block-cut defaults from `ReplicationConfig` and half the available processors for compaction.
The server configuration passes its startup environment to `NodeOptions::default_compaction_threads`, which reads `XTDB_COMPACTOR_THREADS`, and reads `XTDB_NODE_ID` and `XTDB_PASSWORD` itself.
Enable this mode only on an installation where every serving and replay member supports the owned relation format.
`TxOp::OwnedInsertDocs` resolves create-only writes in the authenticated principal's namespace.
`NativeSession::open_owned_point` reads a single entity in that namespace at a store-reserved present.
Normal SQL and ordinary native writes cannot access the reserved scope.
Owned write transactions contain only owned operations.

Session parameter entries, database and timezone strings, await/snapshot tokens, pinned transaction bases and buffered SQL carry execution-budget reservations for their retained lifetime.
Rejected parameter updates retain the previous value.
The failed-transaction marker stores only the state needed to reject subsequent commands; it does not retain the command's diagnostic payload.
Borrowed parameter iteration lets protocol adapters reserve before copying response settings.

`Node` is a passive shared handle over a catalog, resource factories, runtime catalog providers, and cancellation.
`NodeDriver` is the active owner of catalog commands, database worker completion, and database I/O drain completion.
`DatabaseCatalog` publishes immutable membership generations; its owner removes a detaching database from lookup before cancellation and releases its name after its workers join and admitted I/O drains.
A database whose driver has already failed remains a queryable member until an explicit detach, which closes and drains its I/O region before releasing the name.
`Database` is passive and retains partition snapshots, logs, storage, progress, maintenance handles, and its I/O region.
`DatabaseDriver` supervises the active replica, maintenance, and log drivers, cancels and joins consumers before stopping log owners, and reports ingestion failure without terminating unrelated databases.
`MaintenanceSupervisor` owns each leader term's GC and external-source region and joins it before assigning the next term.
It retains one passive `ExternalSource` for the database lifetime and asks it for a fresh assignment driver after each previous term has joined.

`NativeResources` opens independent memory or local source and replica logs plus the configured storage root.
It opens the storage provider and scoped cache before opening logs, so a provider-opening failure does not create Kafka topics or acquire local-log writers.
The passive `DatabaseStorage` capability owns the opened store and its child I/O region.
`DatabaseFactory` recovers persisted block and table catalogs before asking `ResourceFactory::open_logs` to open logs in that region.
The factory's `open` convenience method composes both resource phases for direct backend inspection without recovering catalogs between them.
Storage recovery or later log-opening failures drain the partial region before database opening returns.
The passive `LogAccess` value distinguishes read-only logs, a writable source with a read-only replica, and two writable logs.
An eligible leader opens both writers; a writable follower opens only the source writer, allowing compaction publication without replica-writer ownership.
Source owners are created only on nodes eligible to lead.
The node owns its resource region and calls `ResourceFactory::close` after database drivers join or an ordinary startup failure.
Native resource closure cancels cache downloads and waits for cache, local-store and remote-provider I/O regions, including work whose I/O caller was cancelled.
Each database receives a fresh child I/O region shared by its local stores, local-log read offloads, remote provider operations, and scoped cache work.
The node parent tracks each admitted operation; idle child handles do not delay its drain.
Remote provider factories receive the database child when opening a store; closing it leaves sibling databases available.
Ordinary resource-opening failures drop partial owners and drain the child before returning.
Cancellation of an in-progress attach leaves its admitted operations in the node parent's final drain.
Custom resource-factory wrappers must forward closure to their wrapped factory.
Each native resource factory belongs to one node lifetime; a later node opens a new factory and I/O region while immutable provider configuration and clocks may be shared.
In-process connections inherit the node's configured time zone, which defaults to the fixed UTC offset `Z`.
Opening a node fixes the process case locale once through `rtdb_expr::host_defaults()`, falling back to the root Unicode locale if the host locale cannot be read.
Remote storage requires a shared `DiskCache`, with file keys scoped by database and partition.
Database names that cannot form a safe single path component use an injective hexadecimal cache-directory encoding.
Production local-log writers sample the configured clock for source transactions and the system clock for other messages, unless `with_local_log_clock` enables the configured clock for all records.
`with_log_clock` replaces that clock with a fallible host clock for in-memory and local source transactions, keeping the local log's policy for other messages.
The clock is sampled during append, after queue admission.
`Node::snapshot_export` requires indexing and compaction to be disabled and loads the exact checkpoint root and its table manifests.
The export includes table declarations without data files and derives the primary trie dependencies from the checkpoint's own table manifests.
The plan copies through the existing object-store capability, accepts completed immutable copies on retry and publishes the checkpoint root after its dependencies.
`Node::prepare_compactor_reset` catches up through a block and verifies the live and nascent primary data and metadata pairs named by the installed checkpoint.
An incomplete inventory refuses the reset before installing a replacement catalog.
`Node::prepare_compactor_reset_from_retained_base` rebuilds the catch-up checkpoint in a private local store from a detached anchor and the database's held replica journal.
Both reset paths relocate compacted pairs before the term-owned reset request and preserve prior L0 source descriptors for ordered replay.
The passive `CompactorReset` plan retains its catalog generation, term capability, retirement inventory and memory reservations.
Its application requires an exclusive maintenance node with indexing enabled and compaction and automatic GC disabled.
The active replication driver accepts the reset only against that catalog and block, owns the reset completion within its leader term, and acknowledges it after adopting the replacement block.
On coordinated stores, the plan stages the compacted pairs before publication and submits them for retirement through the installed replica receipt and catalog floor afterwards.
Earlier readers can defer release, and collection resumes pending retirements after restart.
On an uncoordinated store the exclusive plan deletes compacted metadata before data after adoption.
Planning alone performs the initial catch-up flush and reports the prospective retirements.
Feature-gated provider factories supply Kafka, S3, Azure, and GCS implementations.
`PostgresSourceFactory` is a passive immutable registry of node-local remotes and native indexer factories.
The database source retains its native indexer and metric registration across leader changes; each active assignment driver owns its PostgreSQL sockets and confirmation state until teardown.
Kafka Connect likewise retains its custom mutable indexer across assignments, with converter and transform state scoped to one assignment.
Remote credentials stay out of persisted database configurations.
Catalog admission checks shared configuration shape without consulting node-local provider registries.
A skipped member retains its durable configuration even when its backend is not configured on this node.
Provider availability is checked only when the database opens locally.
Read-only local log readers do not acquire a writer lock or mutate log files.
One cache allocation ceiling is shared across database buffer pools; a retained lease remains charged after its pool is dropped.

`Session` is a passive object owned by one caller.
Its transaction, buffer, characteristics, session settings, and last-submitted record are mutated only through that caller's exclusive borrow.
`QueryBasis`, transaction settings, and commit results are passive values.
`DmlBuffer` is a transient that coalesces adjacent executions of identical SQL only when both carry argument batches.
An absent argument batch and an explicitly empty batch remain distinct.
`SessionService` is the passive node capability used to await applied positions, capture the time basis, submit a source record, and await its transaction result.
The service binds the authenticated identity; transaction options cannot choose another user.

BEGIN leaves the read basis unpinned.
The first query awaits the effective await token, then captures the snapshot token and clock unless read-only settings override them.
Plain SQL snapshot tokens are stateless XTDB `TimeBasis` tokens (base64 protobuf mapping each database with a completed transaction to its partitions' system times), so no server-side registry, hold or expiry is kept and tokens are interchangeable with XTDB.
Redeeming a token caps each named database's current catalog at its recorded times using the redeeming session's clock and time zone (omitted databases or partitions read through their head, times ahead of the head fail with `xtdb/unindexed-tx`, malformed tokens fail with `xtdb.basis/invalid-basis`, and erased rows stay erased).
On a placed database with a receipt codec, tokens use the sealed `rtdb-sealed-snapshot-v4:` form bound to the issuing principal, journal history and storage generation, which XTDB refuses as `xtdb.basis/invalid-basis`.
The pinned query clock retains nanoseconds through later commands and frontend tickets.
`Clock::query_instant` supplies the exact reading; injected clocks that implement only `now` retain their explicit microsecond precision.
Typed SQL `CLOCK_TIME` literals resolve after the same statement's timezone option, before Arrow value admission.
Durable transaction system times and SHOW clock output retain their microsecond representation.
A later query in that transaction keeps the same basis.
A writing transaction buffers operations and rejects queries.
Autocommit applies only when no explicit transaction is open.
Manual mode opens lazily on its first operation.

COMMIT of a writing transaction submits even an empty buffer.
The explicit commit mode overrides the transaction's asynchronous setting.
Synchronous commit awaits admitted application through the service; asynchronous commit returns the submitted position.
SET TIME ZONE commits its session change and rolls it back on ROLLBACK.
BEGIN and SET TRANSACTION time-zone overrides apply only to the open transaction.
Closing a session discards its buffer and cancels its children.

`NativeSessionService` connects the shared session state to native source submission, admitted application waiters, immutable snapshot capture, and the native SQL/XTQL query engine.
When the requested transaction is older than the retained progress result, the node reads its outcome from `xt.txs` at a fresh basis.
Autonomous submission can target another database without changing the connection database and advances the await token for the target database.
Authentication revalidation is asynchronous and completes before reads or writes; synchronous session settings check only local connection lifetime.
Frontends revalidate before their protocol commands.
`NodeCatalogRuntime` forwards configured users and metric snapshots and reads role membership from a fresh primary snapshot independently of the outer query basis.
`HealthChecks` is passive and retains the replica targets captured at startup.
Its current observations distinguish critical from noncritical database failures, check a five-block lag threshold, and submit explicit block-flush requests.
Block lag is zero on a database's leader, which writes every block; a follower probes forward from the highest block it has adopted or seen, one fresh HEAD per block, and lists `blocks/` only when it knows of no block still stored.
HTTP serving and metrics export are separate operational adapters still requiring composition.
`PreparedSql` retains charged source and prepared metadata, rebinds at execution, and exposes separate PostgreSQL signature checks and dynamic Arrow schemas.
`PreparedSql::prepare` and query rebinding reserve an estimate for temporary lexer, grammar and binding work before parsing.
The temporary reservation stays live while the prepared source and metadata or the rebound query plan are admitted.
It releases when preparation or rebinding returns.
Native session SQL queries, stored transaction-result reads, and role membership reads reserve the same estimate from their query context and release it before execution.

The session tests preserve state observations from `InProcessAdbcTest`, `ConnectionTest`, and `tx.allium`.
Native node tests cover data-dependent SQL writes, historical reads, asynchronous await tokens, local recovery, retained batches, skipped membership, and detach ordering around running or failed drivers.
The I/O lifecycle regressions hold canceled reads through detach, partial-opening failure and node shutdown, check storage reads after worker failure, and keep sibling cache/provider scopes usable.
These are test sources and contain no execution evidence.
SQL transaction-option execution, Flight handles, protocol entry points, and production server assembly remain incomplete.
`PreparedSql` retains ordered planning warnings with its allocation charge and exposes them independently of execution-time rebinding.
PostgreSQL DML preparation collects warnings on a best-effort basis when the caller supplied no parameter OIDs; planning errors still defer to transaction resolution.
Time-zone validation shares expression conversion's named-zone and Java fixed-offset parser.
Fixed-offset spellings are normalized for session output.

The failed-transaction guard is enforced by the shared session API.
The JVM connection exposes lower-level commit methods whose callers must choose rollback when failed; the frontend integration must preserve that distinction for pgwire COMMIT in a failed transaction.
No source in this crate has been compiled or executed during Phase 1.

`PreparedSql` query execution binds against its supplied `QueryContext` every time, so newly published table OIDs and union legs enter the execution plan.
The dynamic signature policy supports ADBC schema discovery; the PostgreSQL policy rejects changed column counts and incompatible PostgreSQL result descriptors.
Null results and empty lists retain a compatible PostgreSQL description.
ADBC parameter fields have empty names and unknown nullable types in positional order.
Prepared DML preserves the original SQL and the distinction between absent and explicitly empty argument batches, and resolves tables only during transaction execution.
It preserves the supplied argument width for validation during submission and transaction resolution.
Session read-basis capture, access checks, and authentication revalidation precede prepared execution.
`tests/statement.rs` contains source regressions for these contracts and the pgwire cached-plan guard.
Preparation metadata has retained-byte accounting; SQL parser and planner transient allocations and operator descriptors still share the resource qualifications documented by the query crate.

`tests/catalog.rs` carries source observations from `information_schema_test.clj`: namespace OIDs, the Npgsql columns/type join, role namespaces, redacted passwords, declared empty catalog schemas, and metrics tag Arrow layout.
== SQL session controls and inspection

`rtdb_sql::parse_control` binds transaction options and classifies session controls for the native session, PostgreSQL, ADBC, and Flight consumers.
`NativeSession::execute_control_with` applies timezone options before coercing temporal values, preserves absent options separately from `DEFAULT`, and returns typed commands, SHOW cursors, or frontend-owned PREPARE, EXECUTE, and COPY instructions.
ADBC and Flight reject BEGIN, COMMIT, and ROLLBACK submitted as SQL; their transaction APIs remain the entry points for those operations.
Preparation awaits the session token without resolving a bare pending transaction.
Unchecked contexts admit SHOW and EXECUTE argument evaluation in a writing transaction, and pin a pending transaction only when it was declared read-only.
Operation cancellation tokens descend from the session token; query cursors also observe the independent node lifetime.

The five `xt` log and block inspection tables require the same explicit predicates as the pinned JVM producers.
Log cursors capture a finite durable range and retain an allocation reservation with every input payload and returned row.
Block scans preserve the reference's 1024-candidate windows, including termination when a window produces no readable block rows.
Source operation rendering retains named union tags, keyword key normalization, null omission, and charged decoded ownership.
Kotlin database configuration reflection strings and Java Throwable class prefixes remain display qualifications; the durable protobuf and Transit values are decoded without substituting fabricated contents.
The standalone expression evaluator's transient output peak, including control expressions that expand strings, is not yet proven against the execution byte budget.

== Connection and database observation

`NodeServices.execution_observer` supplies shared synchronous query, transaction and protocol callbacks.
Native session contexts carry that observer into cursor execution; direct node contexts leave internal queries unobserved.
Asynchronous submission and synchronous execution have distinct timers, and only the synchronous await contributes to `node.tx.await`.
The session counts presubmit failures and synchronous abort results; the resolver counts ingestion aborts separately and excludes configured skips.
`Node::metrics_provider` observes database watermarks, leadership, the most recent successful block upload and the shared cache budget.
It holds weak node-resource references between samples, and each returned catalog snapshot retains its own allocation reservation.
Runtime metric catalogs await caller-owned live provider samples, including PostgreSQL WAL lag.
All new Rust fixtures are source-only until the implementation gate permits compilation and execution.

Prepared SQL temporal casts capture the preparation context's zone for advertised fields and rebind against each execution context's zone.
Dynamic and PostgreSQL result-signature policies admit compatible rebinding; exact signatures reject changed zone metadata.
Prepared control expressions retain a passive session-zone marker and read the current borrowed evaluation context on each execution.
The statement and control regression sources cover both lifetimes.

External-source factories receive the database I/O region when they open a source.
Kafka Connect assignments capture their legacy date environment through that region.
The source factory retains its provider initialization time and caller-owned clock; formatters sample that clock when they are constructed and when they observe timezone names.
The assignment retains the captured locale and default timezone independently of SQL session timezone settings.
Database removal drains admitted platform reads after source workers join, including reads whose assignment caller was cancelled, before releasing the database name.
Node shutdown drains all database regions through their shared parent.
The source-assignment regression holds a cancelled capture through detach and node shutdown; the Kafka adapter regression checks result cleanup and sibling-region admission.

Source-log transaction inspection prints URI objects using Unicode 16 NFC followed by ASCII percent encoding.
Inspection admits decoded operation rendering scratch before building the EDN text and retains that charge with the page.
Stored URI text remains unchanged.
The URI log-inspection regression source is unexecuted.
