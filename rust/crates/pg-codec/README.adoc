= PostgreSQL value codecs

`rtdb-pg-codec` supplies native PostgreSQL text and binary conversions for the `rtdb-types::PgType` registry.
The frontend and PostgreSQL CDC source share the text decoder.
No source or test in this crate has been compiled or executed during Phase 1.

== Ownership

The codecs are passive functions.
`decode` reserves before constructing the value and returns `DecodedValue`; `into_parts` transfers the value together with the reservation that must accompany it.
`encode` returns an optional `EncodedValue`, with SQL null represented by absence and payload storage charged until that owner is dropped.
`SessionEnvironment::new` reserves before copying session parameters and the effective timezone.
`read_text`, `from_transit`, `encode_value`, and `encode_error` are allocation-producing primitives for callers that already hold a decoding or serialization reservation.
Their output allocations must remain covered until transferred into another charged owner.

== Compatibility

Text input follows `core/src/main/kotlin/xtdb/pgwire/PgType.kt`, `PgTypes.kt`, and the Arrow object writer's value-type choices.
Binary numerics follow `core/src/main/kotlin/xtdb/pg/codec/NumericBin.kt`, including the pinned sign bit for zero.
The signed-short fields wrap on output, and a zero digit count returns zero before reading the remaining header.
Numeric text retains the signed 32-bit scale and Java's bounded canonical scientific notation.
Negative-scale binary output reserves its expanded base-10000 representation before encoding; the minimum signed scale fails like the pinned power conversion.
Timestamp and date binary values use PostgreSQL's 2000 epoch.
Binary timestamptz input carries the UTC offset `Z` in its Arrow timezone, matching the reference's offset date-time value.
Millisecond date text truncates epoch milliseconds to days toward zero, including in JSON, JSON-LD and Transit output.
Binary date output accepts day vectors; the pinned millisecond vector has no integer reader and fails with an internal-error category.
Timestamp output, local and zoned, floors submicrosecond fractions, so binary sends the microsecond the text form shows.
Numeric conversion preserves decimal coefficients without a floating-point intermediate.
Interval text follows the pinned `Time.kt/asInterval` grammar, including ordered components, nine fractional digits, checked Java period/duration arithmetic and empty `P`/`PT` values.
Duration text uses Java's separate case-insensitive grammar with optional plus signs and comma fractions, then enters the microsecond vector with the pinned wrapping conversion.
The reference accepts a day component followed by bare lowercase `t`, while bare uppercase `T` fails.
Both parsers borrow their input and use fixed-width component storage without decimal-power allocation.
Transit period-duration values parse their two components independently, retain wrapping month/day admission, and normalize oversized durations into days after the reference vector-type selection.
The Transit interval reader returns null when its outer lexical grammar does not match; component parsing failures still raise errors.
JSON output preserves integer and decimal digits.
Untagged fractional JSON input opens as double precision, while JSON-LD decimal tags retain exact decimal input.
JSON-LD and Transit use the pinned scalar and container representations.
Transit legacy dates accept signed epoch milliseconds and convert them to UTC timestamps for storage and query arguments.
Transit UUIDs accept both text and the JVM MessagePack pair of signed 64-bit words.
Transit vectors and tagged sequential lists both map to Arrow lists, including nested and empty lists.
Embedded MessagePack requests reserve native conversion storage from the decoded Transit graph and retain the resulting value's storage until its next owner adopts it.

Several pinned encoders differ from PostgreSQL's usual binary representations.
Interval and timestamp-range output remain textual in both formats, and OID/regclass/regproc output remains unsigned decimal ASCII in both formats.
Duration has no binary writer, JSONB has no writer, and integer binary arrays reject null elements.
The text-array binary writer can emit null elements, while the pinned array reader rejects them.
Known types without a pinned reader fail explicitly; unknown CDC OIDs remain strings.

`tests/wire_values.rs` records numeric bytes, temporal rounding, the textual binary writers, array null handling, JSONB versioning, exact JSON digits, float exponent boundaries, malformed inputs, and reservation lifetimes.
The cases map to `PgType.kt`, `NumericBin.kt`, `xtdb.pgwire-test`, and `PostgresSourceTypesPropertyTest`.
Protocol framing is specified by https://www.postgresql.org/docs/17/protocol-message-formats.html[PostgreSQL frontend/backend message formats].

== Remaining qualification

Runtime compatibility and property coverage remain unexecuted.
Temporal text uses the shared Java-range calendar and OpenJDK timezone tables; the selected TZDB version must match the reference artifact during qualification.
The native decoder rejects trailing non-numeric fixed-width binary bytes and malformed arrays that the JVM may consume differently.
`tests/interval_text.rs` covers interval/duration grammar, overflow order, nanosecond endpoints and allocation-owner release; exact Java exception messages remain runtime qualification.
Decimal text follows OpenJDK 21's BMP decimal-digit grammar in both coefficients and exponents.
Java floating-point text conventions are reproduced around the decimal/scientific thresholds and subnormal minima; exhaustive shortest-decimal parity is pending.
The broad JVM object families carried by JSON-LD and Transit still require fixture qualification, including exception metadata and form values.
Reservation estimates bound ordinary decoded payloads, but a proof covering every nested JSON/Transit amplification and library-internal temporary remains outstanding.

Transit URI imports validate Java URI syntax before constructing the native URI value and preserve its original spelling.
`tests/uri.rs` retains valid registry-authority cases and invalid input rejection as unexecuted regression source.

Anomaly output omits an absent message in plain JSON and retains it as null in JSON-LD and Transit.
A present empty message remains a string in every representation.
JSON-LD error input retains absent, null and non-string message fields as an absent message, matching the pinned string accessor.
