= SQL source implementation

PG_SLEEP and PG_SLEEP_FOR cast their operand to a millisecond duration before calling SLEEP, following `sql.clj/visitPgSleepFunction` and `visitPgSleepForFunction`.
Floating-point seconds and the existing duration-text formats follow the shared cast path; integer seconds do not acquire an implicit floating-point cast.
`tests/volatile.rs` retains the `pg2_test.clj/pg-sleep-test` and `pg-sleep-for-test` inputs, lazy conditional branches, null/error cases and rejection of expression-only RANDOM calls.
Timing tests use a paused Tokio clock and remain unexecuted.

Aggregate preparation retains supported factory spellings such as `BOOL_AND` and `EVERY` and distinguishes integer percentile literals from floating-point literals in EXPLAIN.
Computed aggregate inputs and ARRAY_AGG ordering keys run in a projection before FILTER masks.
Each parsed aggregate occurrence receives separate input and output fields, including repeated calls with identical text in SELECT and HAVING.
The passive binding replacement keys distinguish source-span aggregate identities from structural grouping and window substitutions.
The pinned grammar does not expose ANY, SOME, VARIANCE, or STDDEV aggregate aliases, ARRAY_AGG set quantifiers, or ordinary-aggregate WITHIN GROUP clauses.
Unsupported aggregate factories and modifiers fail during preparation.
`tests/aggregate_forms.rs` retains these cases as unexecuted regression source.

Text expressions bind POSITION with CHARACTERS or OCTETS units, OVERLAY with an explicit or inferred replacement length, and binary substring/trim/concatenation.
`CHARACTER_LENGTH` and `CHAR_LENGTH` count Unicode code points with no units clause or with `USING CHARACTERS`.
`USING OCTETS` counts bytes in text and binary input.
Both unit forms propagate null.
The parser retains the operand's original parameter slots and locations.
Binding visits the operand first and then requires uppercase `CHARACTERS` or `OCTETS`.
Other spellings of these keywords report `xtdb.error/illegal-arg` during binding.
`tests/strings.rs` retains the six planning observations from `xtdb.sql.expr-test/test-character-length-expr` and `test-char-length-alias`, and adds execution and error source cases.
`tests/generic_admission.rs` retains prepared parameter cases.

`OVERLAY` accepts a trailing `USING CHARACTERS` or `USING OCTETS` inside the parentheses.
`SUBSTRING` accepts the same clause after a start expression and optional length in forms without comma separators.
Comma-separated `SUBSTRING` uses commas for both separators.
These clauses accept case-insensitive unit keywords.
For either unit, positions and lengths count Unicode code points in text and bytes in binary input.
In `SUBSTRING` without commas between operands, an unsigned decimal integer, `?`, `$n`, or `(` can begin the start expression without `FROM`.
The parser reads the complete source expression before checking for that operand.
The same starters can begin the length without `FOR` after the complete start expression.

The string scalar tests also cover virtual temporal columns whose runtime type is Null, preserving STR, FORMAT, and string-to-array null policies.
REGEXP_REPLACE retains literal pattern, replacement, optional start/occurrence and flags metadata separately from its source expression.
The SQL binder validates the literal arguments before retaining their metadata in the recipe.
Applicable UTF8 source types reject unsupported start/occurrence arguments during emitted-type admission; null-only sources leave metadata uninterpreted.
Integer metadata uses the SQL signed 64-bit literal boundary, including when the source is null.
Session-information expressions expose CURRENT_USER, CURRENT_CATALOG, CURRENT_DATABASE, CURRENT_SCHEMA, CURRENT_SCHEMAS, and CURRENT_SETTING.
CURRENT_CATALOG accepts a bare spelling or an empty argument list, with an optional single qualifier.
The pinned user/database value is `xtdb`, and the explicit search path is `public`, with `pg_catalog` prepended when CURRENT_SCHEMAS requests implicit schemas.
CURRENT_SETTING accepts the case-sensitive names `server_version_num`, `search_path`, and `xtdb.version`; other names retain the requested key in an unsupported-setting diagnostic.
VERSION and XT.VERSION retain the PostgreSQL and XTDB display forms and report the actual native process version, including an available source revision in XT.VERSION.

The parser and binder are passive objects.
Each preparation owns its transient column allocator, parameter map, and CTE scope.
Prepared statements retain immutable plans and their source text.
Their ordered planning warnings retain one entry per source occurrence; PostgreSQL renders them as WARNING with SQLSTATE 01000.
Parsed statement metadata exposes the operation kind and lexical parameter count before table binding.
Ordinary physical scans expose temporal columns to explicit expressions while keeping their synthetic column identities outside wildcard expansion.
Base-table alias column lists declare the available document names, preserving declaration order and discarding duplicates.
Derived-table alias column lists rename output fields positionally.
An alias on a grouped table reference belongs inside its outer parentheses, as in `FROM (docs AS d)`.
An aliased parenthesized expression can still introduce a derived table, as in `FROM (VALUES (1)) q(n), (q.n) AS t(v)`.

The parser tokenizes before binding so anonymous parameters follow lexical order across projection, predicate, nested query, and temporal clauses.
Query parsing, session-control parsing and statement splitting skip nested block comments and line comments, including `/*! ... */` and `/*+ ... */` contents.
Parameters and semicolons inside comments do not enter statement syntax; comment delimiters inside quoted text remain text.
Parsed statement batches use a single semicolon between statements and allow one at the end.
`tests/comments.rs` retains lexical metadata, prepared-plan, control, source-span and nested-comment regression sources; execution remains pending.
Unquoted identifiers start with an ASCII letter or underscore and continue with ASCII letters, digits, underscores or dollar signs.
Quoted identifiers retain Unicode and escaped quotes and reject slashes, following the pinned lexer.
Plain single-quoted string literals must stay on one line.
The recognition diagnostic quotes the token prefix through the first invalid character and reports its original line and character column.
All three lexical entries reject invalid character tokens before returning statement metadata; `tests/identifiers.rs` retains admission and error-order regression sources.
Dollar parameters retain their explicit one-based spelling and use zero-based plan indices.
Temporal clauses retain the source location of their table and become scan dimensions before execution.
Error contexts retain byte spans and one-based positions in the original SQL text.

Base-table `_valid_time` and `_system_time` references project `period(from, to)` before joins.
They remain hidden from base-table wildcards and NATURAL join keys unless declared in an alias column list; an explicit SELECT exports them as ordinary derived-table or CTE columns.
Correlated references capture their projected column identities, and unmatched outer-join rows carry NULL period values.
The binder's passive `TablePurpose` value distinguishes query projection, mutation scans, and erase scans.
UPDATE and DELETE resolve period names through physical document fields, normally NULL, matching the pinned `DmlTableRef` plan; ERASE exposes only declared document names and temporal endpoints.
Mutation output excludes scope-only period columns from documents.
The stateless SQL dialect delegates sqlparser 0.63.0's generic syntax flags and parses period predicates using the original token locations.
PERIOD and TSTZRANGE constructors, LOWER, UPPER, LOWER_INF, UPPER_INF, period intersection, variadic OVERLAPS, and infix period predicates use the existing passive expression and projection operators.
An open upper endpoint is stored as MAX, UPPER returns NULL for it, and LOWER preserves the MIN lower sentinel.
Virtual tables advertise the ordinary temporal endpoint types but emit NULL vectors for their absent endpoints.
Their period projections construct the unbounded range; the execution retains separate advertised and runtime schemas.
The SQL LEADS predicates retain the endpoint comparisons in `sql.clj`; quoted scalar period predicates are absent from the SQL function registry and fail binding.
`tests/periods.rs` maps `test-valid-time-correlated-subquery`, `cte-exporting-valid-time-4054`, `test-lower-upper-period-fns-3660`, `test-derived-columns-with-periods`, the period-intersection assertions in `sql/temporal_test.clj`, and the DML period-reference golden plan.
Exact diagnostic wording remains outstanding; these source assertions have not been executed.

Implemented source paths include SELECT, VALUES, non-recursive CTEs, joins with ON, grouping and aggregate filters, set operators, ordering, limits, array and object expressions, prepared parameters, INSERT, UPDATE, DELETE, ERASE, ASSERT, PATCH RECORDS, INSERT RECORDS, standalone RECORDS queries, CREATE TABLE declarations, GRANT/REVOKE role membership, and basic transaction and session controls.
`CREATE TABLE` and `CREATE OR ALTER TABLE` accept optional column types, such as `CREATE TABLE invoices (_id TEXT, effective TIMESTAMPTZ, amount BIGINT, extra)`.
Typed columns contribute their nullable native shape to the catalog even before a row is written.
Declarations contribute types to the existing row-derived union and do not coerce or constrain writes.
GROUP BY accepts and ignores an ALL or DISTINCT set quantifier before its grouping elements, as the pinned visitor does.
A RECORDS query's columns are the union of its record keys in first-appearance order, with null where a record omits a key; the pinned planner orders them by hash-set iteration instead.
An explicit column list on INSERT INTO … RECORDS selects fields by name in the declared order.
Records can omit selected fields, which appear as null in the input projection.
Canonical mutation lowering preserves unassigned document fields, derives valid-time windows, and builds PATCH gap filling and shallow merge plans.
Static mutation preparation exposes literal and parameter sources to the transaction submitter.
All execution results remain pending for Phase 2.

`VALUES` evaluates every cell when its table opens, including unprojected cells and cells in a query limited to zero rows.
The query opens an inline CTE at its references and opens an explicitly materialized CTE when it enters that binding.
An enclosing lateral operator opens a dependent table with the current outer arguments during execution.
Plain `EXPLAIN` stops after operator emission.
`EXPLAIN ANALYZE` consumes the query before reporting its execution observations.

PERCENTILE_CONT and PERCENTILE_DISC accept a numeric literal or parameter fraction, one WITHIN GROUP ordering expression, and FILTER.
Null input is excluded; explicit NULLS FIRST or NULLS LAST produces the pinned `NullOrderingIgnored` warning and does not change the result.
Continuous results are nullable doubles; discrete results retain the nullable input type.
Both functions reject fractions outside `[0, 1]` up front with `xtdb.operator.group-by/percentile-fraction-out-of-range` before reading input rows, matching upstream XTDB.

INSERT, UPDATE, and DELETE accept RETURNING select lists and ignore them, as in the pinned planner.
This includes INSERT RECORDS; ERASE and PATCH reject RETURNING.
The parser validates select-list syntax without binding its names, functions, subqueries, or typed expressions.
It checks cast types, literal forms and expression modifiers inside the list and its subqueries.
The Direct and batch diagnostic entry points replay the reference grammar for rejected INSERT, UPDATE, and DELETE statements, including INSERT VALUES, RECORDS and query sources.
The replay follows the source, predicates and assignments before it enters RETURNING, so an earlier syntax error takes precedence.
The listener counts Unicode code points in each line and the lexer retains original UTF-8 byte spans.
Subqueries also use the ordinary query grammar checks for join constraints, aliases, set operations and row-limiting clauses.
Its passive borrowed `ReturningClause` descriptor retains the original token spans while the mutation prefix supplies parameter requirements and inline-XTQL descriptors.
RETURNING-only parameters do not increase the prepared parameter count, and mutation-prefix question marks keep their original indices.
The retained source SQL and statement span still include the clause.
The pinned select-list grammar permits empty lists and omitted items after commas; an unqualified wildcard appears once, first or last.

`WITH RECURSIVE` retains the pinned planner's Unsupported anomaly `xtdb.sql/recursive-ctes`, including when the body does not refer to itself.
Prepared-statement commands, COPY, and database lifecycle commands use the separate shared control parser described below.
Table names, table aliases and their column lists, INSERT column lists, UPDATE assignment targets, and JOIN USING columns apply XTDB's reserved-word rules.
Non-reserved keywords can appear unquoted in these positions, and double quotes delimit a reserved word or a case-sensitive name.
INSERT columns, UPDATE assignment targets, and JOIN USING columns are unqualified.
Query-level `SETTING` prefixes bind default valid/system extents into table scans, with explicit table extents taking precedence.
The passive `QuerySettings` value retains clock, snapshot-token and snapshot-time metadata alongside the prepared relation; repeated settings are all planned and the last occurrence determines the value.
Its passive `SettingValue` distinguishes literals, unadmitted `CLOCK_TIME` timestamp literals, parameters and unevaluated forms, retaining the parameter count of forms whose scalar type is never needed.
Ignored snapshot-time settings and overwritten settings still validate expression operators, function names, arities and typed literal spelling without scalar type checking.
Temporal defaults retain their syntax in the preparation transient and bind scalar types when a scan uses the default.
`PreparedQuery::from_prepared` carries this metadata into the shared node, transaction, ADBC/Flight and PostgreSQL execution path.
Clock and snapshot-token settings resolve literals and parameters at query opening; scalar forms are recorded as unevaluated metadata and fail when consumed.
Prepared queries retain parameter requirements from overwritten settings, including through dependency restoration in the SQL logic harness.
The pinned `query.clj` ignores planned `SNAPSHOT_TIME` metadata and applies only the API snapshot-time option; native execution preserves that behavior.
Typed DATE, TIME and TIMESTAMP literals are validated during preparation, including within ignored snapshot-time settings.
TIMESTAMP uses the reference formatter's SMART resolution: day 29–31 clamps to the last day of its month, and exact 24:00 advances to the next date.

== Rejected constructs

A construct sqlparser admits but the pinned `Sql.g4` has no production for is a parse error, as it is for the reference listener: Incorrect, `xtdb/sql-error`, with a message beginning `Errors parsing SQL statement:`.
The binder raises it through `grammar_rejected`, and binding then reparses the statement under the ported `directSqlStatement` grammar; where that recognizer reports the input, its listener text replaces the binder's description.
Text before the statement is blanked rather than dropped, so line and column count from the start of the batch.
A grammar rejection is reported alone rather than folded into accumulated planning diagnostics, since the reference parses before it plans.

Constructs the grammar admits keep the pinned visitor's outcome.
Its `err/unsupported` codes are reproduced exactly; window names, window frames, a second window function and CTE column aliases, which the visitor rejects with a raw JVM exception or assertion, are Unsupported `xtdb/sql-unsupported` with the visitor's message.
Remaining Unsupported sites are native gaps for constructs the grammar admits, such as ranks, NTILE and aggregate windows, DISTINCT on aggregates without a reference distinct factory, schema-qualified wildcards and TIME WITH TIME ZONE casts.
The four standard isolation levels are accepted and ignored, as in the reference transaction-characteristics visitor.
The reference lexer's only binary literal is `X('hex')`; sqlparser's `X'hex'` hexadecimal string is a grammar rejection.
An odd-length `X('…')` body reports `Cannot parse binary string expr: X('…') - failed with message Odd number of characters.`, the reference planner's text.
A GROUP BY element is an expression, as in the reference `ExpressionGroupingSet`: `GROUP BY 1` groups by the constant 1, not by the first output column.
`tests/grammar_rejections.rs` covers a representative of each group.

Some RTDB extensions deliberately accept SQL the reference rejects and are kept:

* typed `CREATE TABLE` column lists (see above);
* the `RTDB_SEARCH`, `RTDB_NEAREST` and `RTDB_HYBRID` table functions and the full-text, vector and spatial scalars;
* scalar subqueries in an UPDATE's SET clause, which the reference planner rejects with `Subqueries are not allowed in this context` (see <<_subqueries,Subqueries>>).

== Qualified columns

Qualified plan fields own a passive `ColumnQualifier` describing their binding namespace.
Base-table references accept column, alias.column, schema.alias.column, and database.schema.alias.column forms, with the resolved schema and database retained when the table is aliased.
Derived tables, CTE references, UNNEST, UPDATE, DELETE, and ERASE use an alias scope.
The pinned scope destructuring ignores components before the database for base tables and before the alias for alias scopes.
Column prefixes do not change a mutation's target database.
Grouping, joins, period projections, and correlated subqueries retain the same namespace descriptors; a new derived-table alias establishes a fresh alias scope.
Qualified wildcards accept a single table alias and reject schema or database prefixes.

A dotted identifier chain is resolved as one column reference.
An array subscript binds to that qualified column before applying one-based indexing.
Struct fields after the subscript resolve against the indexed value.
Parenthesized expressions provide explicit struct-field access, such as `(xtdb.public.foo.payload).leaf`.

== Character casts

CHAR, VARCHAR, TEXT, BPCHAR and NAME cast to Arrow's variable-length UTF-8 type.
A parenthesized length after any of these type names is a syntax error.

== Decimal casts

`DECIMAL`, `NUMERIC`, and `DEC` retain existing decimal precision and scale when no precision is supplied.
Other numeric and text inputs use precision 64, scale 9, and 256-bit storage.
Explicit precision selects 128-bit storage through precision 32 and 256-bit storage through precision 64, with scale zero when omitted and half-even rounding.
Array casts apply these rules recursively and preserve element nullability.
Precision zero accepts null-only results; a non-null coefficient requires at least one digit.
Scales larger than precision are valid when the unscaled coefficient fits, such as `0.001::DECIMAL(1,3)`.
`rtdb-plan::CastTarget` is an immutable passive value retaining the distinction between an unspecified decimal target and fixed metadata.
Native prepared statements rebind that target against the current parameter types on each execution.

`tests/decimal_casts.rs` maps `xtdb.sql-test/decimal-casting`; expression and XTQL cast sources also map `test-cast-list-elementwise`, `test-cast-pg-array-text-to-list`, and `test-cast-list-applies-element-cast-opts`.
Decimal values, explicit SQL scale arguments, and result metadata retain the full signed 32-bit scale; the SQL grammar still requires unsigned scale arguments.
ROUND over a decimal or integer requires a constant scale and derives its result metadata from that scale, while FLOOR and CEIL return doubles.
ROUND over a DOUBLE input accepts a scale supplied by a column or parameter.
The expression implementation bounds coefficient work before rescaling and preserves the reference's rounding and overflow boundaries.
The source tests include wide-scale casts, aggregates, recursive arrays, and dynamic prepared-parameter rebinding.
They also distinguish a raw SUM cell retained by column renaming from computed casts, CASE, COALESCE, and nested results that pass through decimal vector-write checks.

== Subqueries

Scalar subqueries, EXISTS, IN, ANY, SOME and ALL bind through shared subquery scopes.
An uncorrelated quantified subquery builds its candidate relation once and compares each probe row through a mark join.
Window results, inline specifications, and their appended sort keys use the SQL symbol allocator in binding order.
An `ARRAY(query)` expression requires one output column and collects every row in the query's output order.
The vector aggregate preserves duplicate and null elements and returns an empty list when the query returns no rows.
Array constructors by query use the same lexical captures as scalar subqueries.
Their scopes include projection, WHERE, HAVING, grouping and aggregate arguments, VALUES, ORDER BY, mutation predicates and assignments, ASSERT, and inner/left/right join conditions.
Correlation scopes capture columns in apply-local parameters allocated above the statement's lexical parameter indices.
Nested subqueries and CTE reuse retain those bindings without adding client parameters.
Quantified comparisons count true and unknown outcomes separately, preserving empty-set and NULL behavior.
A NULL array contributes one NULL candidate; an empty array contributes none.
UPDATE retains the original target-column identities separately from subquery helper fields.

The source mapping is `xtdb.sql-test/test-subqueries`, `test-in-subquery`, `test-scalar-subquery-with-expressions`, and the array-quantifier paths in `xtdb.sql/visitQuantifiedComparisonExpr`.
`tests/subqueries.rs` contains native result assertions for correlation, nested CTEs, cardinality, null truth tables, parameter numbering, wildcard output, grouping and outer joins.
Full upstream plan golden comparison and optimizer-dependent error elision remain qualification work.
An independent scalar subquery becomes a single join with a right build side.
The join consumes that side once before probing its left rows, produces a nullable value for zero matches, and rejects multiple matches for a probe row.
A correlated scalar subquery keeps its captures and evaluates its dependent relation for each reached outer row.
Full outer join conditions, temporal scan clauses, RECORDS expressions and standalone control values still reject relational subqueries.

LATERAL derived tables and implicitly lateral UNNEST capture preceding FROM columns in the binding scope.
A scalar expression used as a table source yields one row containing its value.
An array-valued expression occupies one cell.
WITH ORDINALITY adds a signed 64-bit column whose value is one.
Table aliases can give these columns explicit names.
When the alias omits column names, the value and ordinal use the statement's generated source symbols.
An eager column table serves standalone UNNEST and dependent UNNEST outside the direct cross-Apply rewrite.
Its optional ordinality is a signed 64-bit sequence for the materialized page.
The list table binds its output fields directly in the alias scope, preserving the logical namespace through later rewrites and in EXPLAIN.
A direct captured UNNEST under a cross Apply stages the collection expression for the full independent page before expansion.
The staged collection has a separate rewrite symbol and is omitted from SQL name lookup and wildcard expansion.
That expansion produces signed 32-bit positions per input collection.
The binding pass chooses the expansion shape before resolving expressions that read the output fields.
Predicates using independent columns can move before collection staging.
Predicates using the generated element or ordinal remain above expansion.
Predicates in a dependent subtree can retain their captured parameters when moving below expansion.
Comma-separated sources, CROSS and inner joins emit every matching dependent row; left joins filter their dependent rows before adding one null-extended row when none match.
USING and NATURAL joins retain their ordinary common-column and qualified-column visibility.
Binding scopes distinguish lexical outer queries from preceding FROM items, so an ordinary derived table cannot expose a sibling merely by containing a nested LATERAL query.
The preceding FROM scope replaces the enclosing-query scope for LATERAL and UNNEST, following `TableRefVisitor`; first-position sources retain the enclosing-query scope.
Each binding owns its mutable capture map, and the completed plan contains immutable parameter arguments.
The query's existing cancellation scope and batch reservations own dependent cursor work and returned Arrow allocations.

`tests/lateral.rs` preserves query forms from `xtdb.sql-test/lateral-derived-table`, `join-lateral`, `test-select-star-lateral-join`, and `test-lateral-with-unnest-4009`.
It also covers lexical boundaries, nested CTE captures, implicit UNNEST, left-join filtering, parameter arity, cancellation, retained output batches, and the explicit recursive-CTE rejection in `WithVisitor`.
Uncorrelated LATERAL inputs support ordinary right and full outer joins.
Correlated right and full outer inputs are rejected: the pinned planner swaps the right-join inputs after binding the lateral captures and does not bind full-join captures.

== Named joins and ordering

NATURAL joins compare every shared visible name; USING joins compare their named columns with SQL equality.
Each side keeps its qualified columns and its wildcard expansion order.
The unqualified common name binds to the original left column, including RIGHT and FULL joins, as in the pinned `JoinTable` scope.
An unmatched right row consequently has a null unqualified common value.
Wildcard expansion retains both common columns; duplicate output names are rejected.
Explicit output names suppress matching names from an unqualified wildcard, and those explicit outputs follow the expanded columns.
A SELECT item uses its explicit alias when supplied.
Column references and field access retain their names through parentheses and unary plus, and the VERSION function supplies the label `version`.
Other expressions receive `_column_N`, where `N` is the one-based position in the select sublist.
A qualified wildcard occupies one sublist position and expands its fields in place.
An unqualified wildcard expands before the sublist and uses its own positions for unnamed fields.
Column binding metadata belongs to the immutable plan field and remains attached when a scope is captured by a subquery.
New table aliases establish a fresh name-binding scope.
An unqualified USER resolves through the local and enclosing column scopes.
When no column matches, it evaluates the current user and receives the positional expression label.

SELECT ordering evaluates after its output expressions and before final projection and DISTINCT.
Nonprojected sort columns do not participate in duplicate elimination.
Set-operation ordering sees only the resulting output columns.
Ordinal ordering refers to output positions; aggregate expressions must be projected and referenced by their aliases.
The source regression cases in `tests/joins_order.rs` map `test-named-columns-join`, `test-natural-join`, `test-order-by-3065`, `test-order-by-alias`, `test-order-by-unqualified-derived-column-refs`, and `test-duplicate-column-projection`.
Additional cases retain the pinned outer-join and DISTINCT behavior without assuming another SQL implementation's rules.
All execution results and exact diagnostics remain unverified pending Phase 2.

== Wildcard modifiers

Unqualified and table-qualified wildcards accept EXCLUDE followed by RENAME, with either one source or a parenthesized list.
EXCLUDE matches original unqualified column names.
An unqualified wildcard's RENAME can resolve a qualified column chain; a table-qualified wildcard's RENAME accepts unqualified names.
Quoted identifiers preserve case and literal dots, and AS is optional except before an unquoted DEFAULT alias.
INTERVAL introduces a literal when it precedes a character string and can also name a column.
RECORD and OBJECT followed by parentheses construct the same struct values as brace syntax.
Renames resolve original column identities, so renaming `x` to `y` does not change the source of a later `y` rename.
Repeated renames of one source use the last alias, missing rename sources are ignored, and excluded sources are not restored by a rename.
Unqualified renames resolve before exclusions; a table-qualified wildcard must retain at least one column after exclusions before its renames resolve.
Explicit projection names suppress original names from an unqualified wildcard before renaming, and expanded wildcard columns precede the explicit projections.
Final duplicate output names remain planning errors.
Wildcard lookup searches visible outer scopes when the local selection is empty, including after exclusions.

`WildcardRename` is a passive immutable source descriptor retaining the original identifier span and full source chain across sqlparser's single-identifier rename representation.
The caller-owned token scan and preparation context build these descriptors and projections; they add no execution state.
`tests/wildcards.rs` maps `test-select-star-projections`, `able-to-select-star-from-two-tables-bug-3389`, `test-select-star-asterisk-clause`, `test-select-star-qualified-join`, and `test-expand-asterisk-parenthesized-joined-table`.

=== Classic transaction outcome projection

Use wildcard `EXCLUDE` to select the five transaction outcome columns in pinned XTDB Classic order (`_id`, `committed`, `error`, `system_time`, `user_metadata`).

[source,sql]
----
SELECT * EXCLUDE (receipt_time, source_log_time, decision_clock) FROM xt.txs;
SELECT tx.* EXCLUDE (receipt_time, source_log_time, decision_clock) FROM xt.txs AS tx;
----

The exclusions apply only to the wildcard that declares them, including in prepared result descriptions.
The same SQL works when some or all of the extension columns are absent.

== Window functions

Each SELECT supports one ROW_NUMBER, LEAD, or LAG call, including a call inside a scalar output expression.
Partitions use column references, and their order follows the first input occurrence of each grouping key.
Window ordering accepts scalar expressions, preserves input order for equal keys, and applies explicit or default null ordering.
ROW_NUMBER returns a non-null signed 64-bit value starting at one in each partition.
LEAD and LAG take a column or a projected aggregate result and an optional unsigned integer offset; the default offset is one.
They retain the operand type with nullability, respect null rows, and return null beyond the current partition.

The pinned planner rejects multiple window calls in one SELECT, explicit frames, direct named-window references, default expressions, and explicit null treatment.
Its WINDOW definitions and existing name inside `OVER (name ...)` are inert; they do not supply partitioning or ordering.
QUALIFY is outside the pinned grammar, while an outer query can filter a projected window result.
Ranks, NTILE, value-selection functions, and aggregate windows have no implemented reference window factory and remain unsupported.
Subqueries and output ordinals in window ORDER BY remain rejected.

The passive `Window` plan owns immutable function and partition descriptors.
Its caller-pulled executor assigns group IDs, uses stable external sorting, and retains sequential spill readers for shifted values.
Spill quota, memory reservations, cancellation, and cursor drop govern those retained resources.
`tests/windows.rs` maps `xtdb.sql-test/test-window-functions`, `test-lead-lag-window-functions`, and the planner's `visitWindowSpecificationDetails` and `wrap-windows` behavior.
The query crate's window sources additionally cover multiple relational-algebra outputs, nonreflexive grouping keys, cancellation, output ownership, and spill failure cleanup.
Compilation, execution, differential assertions, and exact diagnostic matching remain unverified.

== Shared control parser

`COMMIT` accepts an optional `SYNC` or `ASYNC` keyword, and `ROLLBACK` takes no suffix.
`SHOW TRANSACTION ISOLATION LEVEL`, `SHOW AWAIT_TOKEN`, `SHOW SNAPSHOT_TOKEN`, `SHOW CLOCK_TIME`, `SET AWAIT_TOKEN` and `SET ROLE NONE` keep their dedicated reference productions; `SET SESSION AWAIT_TOKEN` is rejected.
SET and SHOW session parameter names fold case and preserve punctuation.
Quoted `"CLOCK_TIME"`, `"SNAPSHOT_TOKEN"`, and `"TIMEZONE"` in SHOW select the session parameter form and leave the transaction's read basis unresolved.
`SET TIME ZONE <expression>` and `SET TIMEZONE <expression>` take their operand directly.
Pgwire also sets the session timezone with the literal parameter form `SET TIMEZONE TO 'Europe/Paris'`, whose command tag is `SET`.
Session parameter binary literals use the contiguous `X('hex')` spelling.
The parser checks the literal positions in session settings and transaction ASYNC options before collecting the command.
Binding compiles the final transaction options in option order and resolves a CLOCK_TIME timestamp literal at that stage.
`split_statements` separates statements by tokenizer spans before classification, preserving semicolons inside strings and comments.
Before scanning the batch, Simple Query reserves an allowance for token payloads and tokenizer scratch.
It charges the located token array separately as the array grows.
Batch parsing releases both reservations before returning.
Extended Parse keeps its command allowance and admits the temporary located token array separately.
It reserves replacement array capacity before releasing the preceding array's charge.
Located comment slots preserve source positions without retaining ignored comment text.
The array reservation ends when classification and any nested PREPARE validation return.
Extended Parse classification returns the original bounded text for ordinary SQL and controls.
`parse_control_in` charges raw expression forms during binding.
Flight SQL uses `parse_admitted_control_in` to classify the full input under a tokenizer allowance and admit located token capacity as it grows.
A recognized control command reserves an estimate for parsing and binding, including simultaneous token copies and AST storage.
The bound command holds that reservation until dropped.
A separate scratch estimate uses the control expression parser's recursion limit to cap the number of nested speculative `POSITION` parses accounted for at once.
The frontend owns prepared statement registries and COPY wire state; `rtdb-node` owns session transitions and control effects.
COPY formats and ATTACH configuration accept standard, dollar-quoted and escaped character strings.
These control values retain escaped-string bodies verbatim, following the pinned control visitor; standard strings decode doubled quotes.
COPY classification selects the first format case-sensitively and retains an absent or unknown format for the frontend's format diagnostic.
Later COPY options are still parsed, including after an unrecognized first format.
Generic tokenizer literal admission and query-literal decoding still require the broader lexical compatibility work.
Quoted identifiers preserve doubled interior quote or backtick delimiters in query and control names, matching the pinned identifier visitors.
