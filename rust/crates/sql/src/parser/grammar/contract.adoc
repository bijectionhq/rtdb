= Pinned SQL grammar graph

`Grammar::load` constructs the parser graph from the included `Sql.interp` source artifact under a caller-supplied finite `AllocationScope`.
The graph contains 3,017 states, 176 rules, 43 token sets and 372 decisions.
Its 3,515 serialized transitions produce 556 distinct rule-stop return edges, for 4,071 retained transitions.
The five Action transitions retain their rule/action identity and take part in epsilon traversal.
The graph also retains the 42 precedence transitions, 142 marked return edges and five precedence decisions.

The constructor adapts ANTLR 4.13.2's https://github.com/antlr/antlr4/blob/4.13.2/runtime/Java/src/org/antlr/v4/runtime/atn/ATNDeserializer.java[`ATNDeserializer`] and https://github.com/antlr/antlr4/blob/4.13.2/runtime/Java/src/org/antlr/v4/runtime/atn/ATNState.java[`ATNState`].
Link completion and graph verification precede publication.
Transition insertion preserves source order; equal labels or epsilon transitions sharing a target retain the first transition.
The published archive, grammar, generated-source and runtime hashes are in link:UPSTREAM.json[`UPSTREAM.json`].
The upstream BSD 3-clause notice is retained in link:../../../LICENSE-ANTLR[`LICENSE-ANTLR`].

== Ownership and admission

`GrammarData` is a completed immutable passive value containing the graph and vocabulary.
Its construction transient has one caller and cannot publish incomplete links.
`Grammar::load` owns that data under the caller's allocation scope.
`OwnedGrammar::load` takes a finite `MemoryBudget` and owns both the data and an independently constructed `AllocationScope`.
Both constructors use the same private loader and admission schedule.
The owned graph drops its data before its scope and releases all construction reservations when it is destroyed.

`OwnedGrammar::view` returns a borrowing `Grammar` without allocating or copying graph storage.
State, rule, decision and transition views borrow their grammar; linked views retain the same graph identity.
Views from the same owned graph accept each other's invocation states, while separately loaded graphs remain distinct owners.
Generated numeric coordinates can be resolved through checked lookups, while internal identifiers have no independent dereference interface.
`Grammar` retains its allocation-scope borrow through destruction and provides no owned graph extraction or cloning operation.
An owned graph can outlive the constructor's budget borrow; its reservations retain that finite budget.
Borrowing views cannot outlive the owned graph.

Construction admits each requested container before allocation.
The decoded-word scratch contains 28,406 `i32` values.
Transition capacity includes every serialized edge and every serialized call's return candidate: 4,117 slots, with 46 slots unused after deduplication.
Vocabulary arrays contain borrowed static strings.
Builder state, rule-stop scratch, completed rule pairs, token sets, decisions and final state storage have separate reservations based on their actual element sizes and counts.
The final state array is admitted while the builder array remains live; transition backing stores move into the final states.
Reservations, including temporary and unused capacity, remain with the allocation scope until it is dropped.
These admission points define the native resource contract; they do not assert JVM heap-allocation equivalence.

Allocation failure returns the original admission anomaly and drops the unfinished graph.
Malformed artifact failures contain an inline issue kind and source coordinate, without an allocated diagnostic string.
The production constructor accepts only the included parser artifact.

== Tokens and display

Raw lexer kinds map to the pinned token numbers without decoding a literal or requesting another lexeme.
EOF is distinct from the expected-set epsilon symbol.
The fixed token-set value contains epsilon, EOF and token numbers 1 through 368; it owns no heap storage.
Its union, membership, epsilon removal and iteration operate on that fixed universe.
Iteration follows numeric token order.

Vocabulary display borrows the literal name when present and otherwise the symbolic name.
EOF's vocabulary name is `EOF`; expected-set formatting uses `<EOF>` and `<EPSILON>` as specified by https://github.com/antlr/antlr4/blob/4.13.2/runtime/Java/src/org/antlr/v4/runtime/misc/IntervalSet.java[`IntervalSet`].
`display_len` counts the exact output bytes without allocation.
`write_display` writes to caller-provided storage whose capacity and lifetime the caller has already admitted.
Neither operation returns an owned string.

== Expected tokens

`State::next_tokens` computes the tokens reachable within the state's rule, adding epsilon when the local rule end is reachable.
`next_tokens_with_context` follows the supplied caller path and adds EOF at the full root end.
`expected_tokens` starts with the within-rule result and visits caller follow states only while epsilon remains; its result excludes epsilon and includes EOF when the caller chain ends on a nullable path.
These operations adapt ANTLR 4.13.2's https://github.com/antlr/antlr4/blob/4.13.2/runtime/Java/src/org/antlr/v4/runtime/atn/LL1Analyzer.java[`LL1Analyzer`] and `ATN.getExpectedTokens`.

Caller invocation views run from innermost to outermost and exclude the root sentinel.
Full-context conversion collects the path and resolves its rule-follow transitions from outermost to innermost before traversal.
Expected-token chaining demands the next invocation only while the preceding follow set contains epsilon.
A demanded invocation must belong to the state's grammar and have a rule transition first.
Foreign grammar ownership is rejected before graph dereference.

Each operation owns a passive traversal workspace under its explicit allocation scope.
The workspace contains DFS continuation frames, immutable return-context nodes, visited membership and temporary invocation views.
Called-rule bits occupy three inline words for the pinned 176-rule universe.
Transitions are visited in source order, with called-rule bits cleared after descent and temporarily cleared and restored when returning through a rule stop.
Actions and precedence predicates contribute epsilon traversal without executing an action or predicate.

Local-end contexts and the canonical full-root context remain distinct.
Singleton contexts retain arena identity: aliases compare equal, while separately created singletons with null parents remain unequal even when their return states match.
Other singleton comparisons follow their nonnull parents iteratively.
Visited membership uses state and context equality; called-rule bits do not form part of that key.
Membership bucket order does not control traversal.

Frame, context and invocation vectors request 16 elements on first growth and double thereafter.
The visited table requests 16 slots on first insertion and doubles before exceeding one-half occupancy; a repeated visit does not cause growth.
Each growth admits the full replacement backing store before allocation while the old backing store remains charged.
Expected-token chaining clears and reuses that storage between within-rule traversals.
All reservations remain with the caller's scope until it is dropped.
The workspace retains its scope borrow through destruction and returns only an inline `TokenSet`.
Failure drops the private workspace; traversal and context equality have no input-depth native recursion.

The graph is private and is not connected to production SQL entry points.
All generated rule schedules, prediction, SLL/Bail-to-LL retry and diagnostic orchestration remain required parser work.
