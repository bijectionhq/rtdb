= Prediction values

This private parser component implements prediction-context values, ordered configuration identities and prediction-mode facts from ANTLR 4.13.2.
`UPSTREAM.json` pins the primary sources; link:../../../LICENSE-ANTLR[the ANTLR license] covers the adapted algorithms.
It does not perform token prediction, recognize SQL rules or change a production parser entry point.

== Owner and keys

`with_prediction_contexts` opens one passive, single-writer owner under an explicit `AllocationScope` and borrowed `Grammar`.
Its callback is universally quantified over a fresh invariant context-key lifetime.
The callback result cannot contain that lifetime; keys cannot escape into a later owner or be supplied to a different invocation of the factory.
Only the factory can construct an owner.
A `ContextView` borrows that exact owner, and input `State` views are checked against the retained grammar before transition access.
Invocation input excludes the root sentinel and runs innermost to outermost; conversion resolves follow states from outermost to innermost.

The owner retains flat immutable node slots with owned array payloads, mutable round-local memo membership, canonical-context membership and traversal scratch.
A candidate array remains private and mutable until operand reuse and common-parent normalization finish.
Published nodes and their edges do not change.
The derived local-domain bit records whether a node can be traversed by the SLL cached-context operation without following a null parent.
The owner has an explicit `Drop` lifetime witness, so its allocation scope must outlive storage destruction.
It exposes no storage extraction, cloning or mutable graph view.

The lifetime constraints can be read directly at the private boundary:
`with_prediction_contexts(..., |owner| Ok(owner.empty()))` cannot return its branded key as the factory's independent result type.
A key from an enclosing factory cannot be passed to a separately opened nested factory.
A borrowed view cannot survive the owner borrow, and a scope cannot be dropped before an owner which still holds it.
These are source contracts; compiler qualification remains unrun.
`PredictionStorage` owns an `OwnedGrammar` and retained context storage across accesses.
Its constructor transfers the completed grammar; it cannot replace that graph or reopen the context store against a different graph.
`with_contexts` creates fresh invariant keys, an allocation-free grammar facade and call-owned scratch under the supplied `AllocationScope`.
The facade borrows the retained store exclusively and cannot escape the callback.
The scoped and retained facades use the same equality, merge and canonicalization algorithms with sealed allocation policies.
Returning a retained facade's key or view as the independent callback result is likewise excluded by its invariant brand and access lifetime.
Each access keeps both the work scope and retained owner borrowed through facade destruction and the ensuing collection.

== Context values and identity

Canonical Empty, Singleton and Array remain distinct shapes.
A full-context EmptyReturn edge has a null parent; that null is not the canonical Empty context.
Array edges are sorted by return state and have no repeated return state.
An Array with one edge retains its Array class except at the source's explicit singleton reconstruction points.
A one-entry EmptyReturn Array reports empty and is returned unchanged by cached-context traversal.

Identity succeeds before value equality.
Two distinct nonempty null-parent Singletons are unequal even when their return states and hashes match.
Arrays compare ordered return states followed by nullable parents; null parent slots compare equal.
Hashes use the source Murmur3 word order and cached parent hashes.
Equality, merging, invocation conversion and canonicalization use explicit work states instead of input-depth native recursion.
Flat node/edge storage also makes destruction independent of context depth.

A merge round retains one memo across both local-wildcard and full-exact calls.
Keys follow source context equality, with forward lookup before reversed lookup and branch-specific insertion.
Merge mode is not an additional memo-key field.
Ending a round clears membership while retaining its already admitted capacity.
The graph and canonical cache survive the round.
Local-wildcard Empty absorbs a root; full-exact merging retains an explicit EmptyReturn edge.
Operand and parent identity reuse follows the source branches, and common-parent normalization retains the first equal parent only after operand-reuse checks.
An uncached merge uses the same traversal with every memo read and write disabled, without clearing or replacing an existing round memo.
This includes recursive array-parent merges and models source calls whose merge-cache argument is null.

Cached-context traversal first preserves any entire empty context, then checks identity-visited and canonical membership before visiting parents in index order.
Unchanged parents retain the original node.
Changed one-parent reconstruction uses Singleton, including when its input was an Array.
The result of adding that reconstructed node to the canonical cache does not replace its returned identity.
Full-context graphs with traversable null parents fail the local-domain check; no null-to-Empty substitution is performed.
Canonicalizing such a graph is an internal caller error, not an accepted SQL normalization.

== Admission and failures

The empty owner allocates no dynamic graph storage.
Node slots, invocation and work vectors admit requested capacities before allocation, beginning at 16 slots and growing by checked doubling or the larger concrete requirement.
An array candidate admits the exact requested edge count before construction.
Its completed node admits a separate payload of that length before admitting its node slot.
Lookup tables begin at 32 slots, stay at most half full, and admit complete replacement storage before rehashing.
Every byte product and capacity operation is checked before reservation.
Old storage and its charge remain live while replacement storage is constructed.
Candidate buffers and final storage are both covered while they overlap.
Scoped storage reservations, cleared memo capacity and discarded candidate charges stay with the caller's scope until it drops.
Retained blocks instead own their individual leases, charging each concrete capacity plus 256 bytes of native bookkeeping before allocation.
Replacing a retained block releases its old capacity charge only after that vector is destroyed.
No scope-only vector is transferred into retained storage.
These are native admission points, not a claim of identical JVM heap exhaustion.

The first allocation failure returns its original admission anomaly and seals further mutation or allocating inspection.
A later request returns the inline Aborted failure without attempting another allocation, even if other callers have released memory.
Completed views remain available for nonallocating inspection.
No partially constructed key is returned on failure; private storage completed before a later cache-publication failure remains inaccessible through the failed operation.
Failures do not create source-derived diagnostic strings in this component.

== Retained context lifetime

Canonical membership contains the actual persistent context roots, including both stored keys and values.
Ending an access destroys its facades and traversal work before a private guard traces these roots and their parents.
The trace uses pre-admitted slot links and marks; collection, failure cleanup and deep graph destruction allocate no traversal stack and perform no input-depth recursion.
Unreachable node payloads release their leases, while free slot capacity stays charged for reuse.
Slot generations advance before reuse and retire permanently on exhaustion, so a stale private ID cannot refer to a replacement node.
Binding a persistent ID to a fresh key checks its live generation; stored parent links remain within the completed graph.
Collection cannot run while a branded key or view is live.

Completed canonical publications survive later failures, including failure to record identity-visited work.
An unpublished array payload is dropped if admitting its node slot fails.
The failed access remains sealed, but a subsequent access has fresh work and abort state under the same retained budget.
Canonical entries are strong roots and are not evicted or reset to recover memory.
Dropping a work scope does not release retained cache storage; dropping `PredictionStorage` releases its context blocks and then its owned grammar.
The region exposes neither raw stores nor graph replacement, and takes no ambient budget or cache.
Configuration storage, DFA root integration and parser-environment sharing remain separate required work.

== Configuration objects and ordered sets

`with_configurations` opens a passive single-writer region using the exact grammar, allocation scope and context brand of its supplied prediction-context owner.
Its additional invariant configuration-key lifetime prevents config, set and conflict-object handles from escaping the callback or crossing independently opened configuration regions.
The context owner remains a separate collaborator; cached additions borrow its existing merge round, while uncached additions use its memo-free operation.
Configuration storage, set membership and completed conflict objects are flat owned values with an explicit allocation-scope destruction witness.
Views borrow their actual region and read the current configuration object.

A configuration constructor copies fields into a fresh object identity.
Set entries retain object identities, so a merge or canonicalization through one set changes the configuration observed through its other aliases.
Membership compares state, alternative and semantic value; it excludes the syntactic context and packed outer-depth word.
A distinct membership match merges into the first object without changing ordered membership.
Adding the same identity again appends another ordered occurrence, including when that identity is already in the membership index.
Set copies retain configuration and conflict-object identities, copy metadata, and start with mutable membership.

Addition updates incoming semantic and outer-depth flags before membership lookup.
On a distinct match, context merging completes before a replacement configuration value is published.
The replacement uses signed maximum of the packed outer words followed by the incoming suppression bit, not maximum of unpacked depths.
The word's increment wraps as a Java integer; depth masks only bit `0x40000000` and keeps the sign bit.
A failed merge leaves the aliased object unchanged while retaining the source's earlier set-flag updates.
Canonicalization updates objects in list order; failure after an earlier completed update seals further work without rolling that update back.

Full configuration equality includes context and suppression but excludes raw outer depth.
Its hash uses the source Murmur3 framing over state, alternative, context and semantic value; suppression and depth are omitted.
The unpredicated singleton uses a native hash discriminator because the Java object's process identity hash is not derivable from the source archive.
This discriminator is private lookup data, not an exposed JVM hash result.
Set equality compares the ordered full configurations, full-context mode, unique alternative, conflict-object identity, semantic flag and outer-context flag.
Equal conflict bit contents published as distinct objects do not satisfy the identity comparison.

Read-only membership drops its lookup index and rejects addition, clearing and canonicalization through that set.
Its referenced objects remain live, and metadata is independent of the membership state.
Hashing folds the ordered list with Java's wrapping 31-fold.
A read-only set retains a computed non-`-1` hash even if an alias subsequently changes a configuration.
The value `-1` remains the source cache sentinel and is recomputed on the next request.
Clearing a mutable set clears membership but retains semantic, outer-context, unique-alternative and conflict metadata.
Later closure and DFA containers must separately preserve their insertion-time hashes when aliased keys change.

== Semantic values and mode facts

The pinned graph has 372 decisions, with at most 87 outgoing alternatives; decision 65 at state 848 attains that bound.
Alternatives are checked against the actual decision, and the complete alternative set fits two inline 64-bit words.
The graph's 42 semantic transitions are precedence predicates with positive values no greater than 67.
Precedence construction checks a real owner-bound state and reads its indexed transition; a caller-supplied transition payload cannot establish this invariant.
Within this domain, semantic AND reduces precedence values to their minimum and OR to their maximum, after the source null and unpredicated sentinel branches.
The domain bound makes ordinary ordering equivalent to the source comparator's wrapping subtraction.
Unpredicated direct evaluation returns false; precedence simplification preserves the unpredicated sentinel, and later simulator call sites must retain their explicit sentinel checks.

Mode work is a passive transient retaining charged grouping and state-map scratch.
Its completed subset view borrows that workspace and cannot survive its reuse.
An all-rule-stop set terminates before allocating stripping or grouping storage, including an empty set.
SLL with semantic predicates creates fresh unpredicated configuration objects and adds them to a full-context set without a merge cache.
LL retains the original configurations.
Grouping traverses the whole ordered list before conflict reduction, and a state-to-alternatives map is requested only after the conflict predicate succeeds.
Groups use state and structural syntactic context, ignoring alternative, semantics and suppression.
Viable results distinguish empty input from conflicting minima, preserving the source's `-1` versus `0` distinction.
The all-subsets-equal operation rejects an empty outer collection explicitly.

Native grouping retains first representatives and insertion order within equal-hash collision chains.
Its final subset reductions are allocation-free bitset operations and do not depend on the source hash map's bucket enumeration.
During immutable grouping, a repeated get/put or reinsert comparison has already completed with the same context pair and retained equality-frame capacity.
Omitting that repeated traversal introduces no new allocation or effect; this argument does not apply to later mutable-key closure and DFA containers.
Neither grouping nor mode facts pull tokens, evaluate application predicates or select parser rules.

Configuration, set and conflict slot vectors begin with admitted capacity 16 and use checked full replacement growth.
A new set admits seven ordered entries and 32 native lookup slots before publication.
Lookup tables remain at most half full; group and state vectors admit only encountered entries.
Every old and replacement buffer remains covered while both are live.
Duplicate-identity append reserves list growth only when reached, and a distinct merge does not reserve an unused list slot.
SLL stripping reserves each new object in list order, after admitting its new set.
Mode and configuration failures seal their reached work, and mode failures also seal the context collaborator.
An operation accepting a context owner or merge round checks that collaborator before flags, membership, identity, empty-set or cached-hash shortcuts.
An aborted collaborator seals the configuration owner on entry; mode entry propagates a failed participant check to every supplied owner before returning.
Completed nonallocating views remain available; no owned error string or cloned anomaly is cached.
Native reservations remain with the scope until its destruction, including discarded scratch and copied set storage.

The factory and view signatures also carry the lifetime tests as source contracts.
Returning a `ConfigKey`, `ConfigSetKey`, `ConflictKey` or a workspace carrying that brand as the factory's independent result is not permitted by the invariant callback lifetime.
A key from an enclosing configuration factory cannot be passed into another factory, and context keys retain their separate owner brand.
A view cannot outlive the region borrow; the region's `Drop` requires its allocation scope through destruction.
These lifetime contracts and all regression sources remain unexecuted.

== Remaining parser work

Shared DFA/cache history and the captured ANTLR initialization option still require their production owner and demand review.
Diagnostics, raw UTF16 literal consumers, typed semantic adapters and whole-batch production parsing remain incomplete.
