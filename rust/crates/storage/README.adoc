= Storage publication contracts

Object stores are passive I/O capabilities.
`put` and `put_file` publish immutable objects and accept an existing destination only when its bytes are identical.
`put_file` takes a closed source file that the caller keeps unchanged and alive until the operation completes.

The local adapter copies into a temporary file, syncs its contents, publishes without replacing an existing name, and syncs the destination directory ancestry.
An existing file is compared in bounded chunks.
The remote bridge uploads sequential multipart chunks to a unique private name, conditionally copies that object to the destination, and deletes the private name before returning.
The provider must implement conditional copy; unsupported providers return an error without overwriting the destination.
Provider permission denials retain the requested object identity and become Forbidden anomalies; generic provider messages are not parsed to infer authorization outcomes.
Existing remote objects are compared through bounded range reads.
The memory adapter retains the whole object by definition.
Every local store offload and remote provider operation belongs to an `IoRegion` monitor.
Standalone stores create a region and expose `close_and_wait`; node stores share the region supplied by `NativeResources`.
Each database's child region tracks its admitted operations in the node region as well.
Closing a child rejects requests for that database and drains its active work while sibling regions remain open.
An idle child handle does not delay either drain.
The node's local source and replica log reader offloads share that same region.
Closing a region rejects new work and waits for queued and running I/O after its caller has been cancelled.
Provider adapters use `IoRegion::run_blocking` for auxiliary filesystem work such as Azure Arc challenge reads.
Successful delivery transfers the result to the caller; cancellation retains result destruction in the region's drain.
File uploads open their source before offloading so an unlinked temporary source remains available to admitted work.
Remote uploads retain that source through conditional publication and private-object cleanup.
Reserved remote reads transfer their allocation charge into the admitted operation and then into the returned bytes.
Local object copies stream through the destination's immutable file publication path.
Remote file publication compares immutable retries against one complete provider response.
Versioned remote file receipts identify the provider response that supplied the verified bytes, or the direct write acknowledgement for an empty file.
`LocalStore::copy_to` accepts an explicit destination store for copies across filesystem roots.
The open source file retains admission in the source region until the destination operation finishes, including after caller cancellation.
`RemoteStore::copy_to` accepts an explicit destination prefix backed by the same provider client.
Remote copies use provider-side conditional publication and compare existing destinations in one-MiB ranges.
Both source and destination regions retain a copy until provider completion.
The ordinary `ObjectStore::copy` method uses these paths within its configured root.

Native database buffer pools reserve cache entry metadata from the node execution memory budget before inserting a key.
An entry holds that charge while cached or in use by concurrent fetchers.
If metadata admission fails, the pool can reclaim one idle entry and retry.
An empty entry is removed when its last fetcher fails or is cancelled.
Pools sharing a payload budget report its retained encoded bytes and in-flight read reservations.
An evicted payload remains charged until its last lease or slice drops.

A scan maps requested byte ranges on local object files and on existing disk-cache files.
A cold remote range read can fetch those bytes directly.
Whole-object transforms such as authenticated encryption load the object once before reading its selected pages.
A retained mapping keeps any disk-cache lease alive until the last Arrow buffer referencing it is released.

`DiskCache` is a shared monitor for immutable remote files, with per-entry load exclusion and passive leases that prevent eviction during reads.
Downloads publish a complete temporary file atomically and charge each in-flight chunk and retained entry to the supplied allocation budget.
Cancelled or failed loads release their temporary files and allow a later reader to retry.
Concurrent readers share successful loads; cancellation of the loading caller permits a waiting reader to restart that load.
Pinned files can exceed the disk capacity; releasing their final lease evicts idle files until the capacity is met.
Existing complete files are reused at startup, with access/modification timestamps supplying their initial eviction order.
The cache acquires an exclusive directory lock before removing staging files left by a previous process.
The lock remains held until the final cache owner or lease is released.
File uploads warm the cache after durable remote publication; remote deletion leaves cached immutable files available until eviction.
Use `ObjectStore::head_fresh` when a decision depends on the current presence of a shared object.
The disk cache sends the metadata request to its backing provider and leaves cached files untouched.
Blocking range reads retain both their disk lease and allocation reservation until the I/O task finishes, including after caller cancellation.
Scoped cache stores admit cache hits and provider requests through their database region.
Blocking cache reads and cache publication hold both cache and database admissions through work completion and cancelled-result destruction.
The region owner calls `close_and_wait` to reject new work, cancel downloads, and join admitted operations and blocking reads before shutting down the runtime.
The native node closes this shared resource region after its database workers join, and after an ordinary startup failure.

Normal upload failures attempt multipart cleanup.
When multipart abort also fails, the diagnostic preserves the upload's typed category and object key alongside the abort failure.
A failed cleanup request, a forcibly stopped runtime, or a process crash can leave private objects or multipart parts behind.
The private `.tmp` namespace is excluded from object listings exposed to the database.
Shutdown owners join the I/O region after consumers finish and before stopping the runtime.
Provider lifecycle policies and orphan cleanup remain operational obligations; hiding a temporary object does not reclaim it.

All implementation and test source remains uncompiled and unexecuted during Phase 1.

`Log::range` captures a finite half-open offset range for inspection and returns a passive `LogRange` cursor.
Each `next` call requires its advertised allocation reservation before reading one record.
Returned `Bytes` clones retain that charge.
Local log ranges use byte-position record starts; interior malformed starts fail, while starts beyond the captured durable tip return an empty range.
Range reads never wait for later appends.

`LocalLog::open_with_timestamp_source` samples its passive timestamp policy for each record in the ordered writer.
Policy errors roll back the whole current write batch and fail its receipts.
`LocalLog::open` retains the caller-supplied timestamp contract for raw log consumers.
