= Certificate identifiers

`CertificateIdentifiers` is a passive immutable value decoded from an already parsed X.509 certificate's encoding.
It owns an independent memory reservation covering parsing scratch and retained identifier bytes.
It validates certificate identifier framing, not certificate signatures, validity, other extension contents or trust.
The shared value is intended for Java PKCS12 issuer-chain recovery and transport-owned PKIX path selection.

The source contract is Eclipse Temurin 25.0.1+8 `CertificateExtensions`, `X509CertImpl.getExtensionValue`, `SubjectKeyIdentifierExtension`, `AuthorityKeyIdentifierExtension`, `KeyIdentifier`, `SerialNumber`, and the `GeneralNames` implementations in `lib/src.zip`.
SKID access preserves the original inner extension encoding, including accepted BER forms.
AKI access returns a canonical DER OCTET STRING only after every AKI field parses successfully.
Serial numbers preserve arbitrary signed Java `BigInteger` values as minimal two's-complement bytes.
Malformed noncritical AKI is absent; malformed noncritical SKID remains available through Java's last-unparseable-extension fallback.
A successfully parsed SKID takes precedence over malformed copies regardless of input order.
Two successfully parsed copies of either identifier fail, while an unparseable noncritical copy does not displace a parsed copy.
Malformed critical identifier extensions fail.

General-name validation follows the constructor selected by `GeneralName`, including the permissive DER DNS constructor, opaque X400 values, EDI primitive context tags, and registered `OIDMap` extension classes that fail `OtherName`'s interface cast.
URI syntax uses the shared Java `UriParts` parser.
Numeric IPv6 scopes are supported through the signed 32-bit scope limit, and IPv4-mapped addresses with any scope are invalid.
Named IPv6 scopes, decimal scopes exceeding that limit, and trailing-dot URI hosts that reach Java's `InetAddress` fallback currently return `rtdb.tls/unsupported-identifier`.
These environmental resolution cases remain explicit errors even inside noncritical AKI; they are not classified as malformed extensions.
A passive local-interface and host-resolution adapter remains required for those cases.

The ASN.1 reader follows pinned `DerValue`, `DerInputStream`, and `DerIndefLenConverter`, including opaque definite bodies and zero padding produced when scanned length headers shrink.
Constructed OCTET STRING processing is iterative, with temporary ownership bounded by input size.
Admission failures propagate without becoming identifier absence, and the reservation releases when decoding fails or the result drops.
The regression sources cover signed serials, canonical versus original encodings, all general-name choices, malformed and duplicate extensions, BER forms, deep constructed octets, environmental URI errors, and allocation release.
No identifier regression has been compiled or executed during Phase 1.

`CertificateAlternativeNames` is a separate passive immutable view of a parsed subject-alternative-name extension.

* Its original inner extension bytes implement `SunCertPathBuilder.altNamesEqual`, which compares `SubjectAlternativeNameExtension.getExtensionValue()` with `Arrays.equals`.
Case, name order and accepted BER encodings remain significant even when the parsed names denote the same values.
* Malformed noncritical SAN is absent.
* A parsed copy survives unparseable copies.
* Two parsed copies or a malformed critical copy fail.
* The view reuses the same `GeneralNames` parser and environmental URI errors as certificate identifiers.
* The certificate-framing scanner is shared with `CertificateIdentifiers`.
* It owns its parsing reservation independently until the view drops.

SAN regression sources cover original-byte equality, empty and malformed names, duplicate handling, BER retention, environmental URI errors and reservation lifetime.

`CertificateBasicConstraints` and `CertificateKeyUsage` expose passive immutable Java certificate-constraint results.
Each view owns its parsing reservation independently until it drops.

* BasicConstraints follows `BasicConstraintsExtension` and `X509CertImpl.getBasicConstraints`.
Absent extensions, empty sequences and non-BOOLEAN first fields yield `-1`.
A nonzero CA flag without a path length yields `i32::MAX`.
Explicit signed path lengths retain negative values and accept redundant BER sign bytes within Java's integer range.
Fields after a parsed path length are ignored.
* KeyUsage follows `KeyUsageExtension`, `KeyChecker.verifyCAKeyUsage`, `AlgorithmChecker` and `EndEntityChecker`.
Absent usage permits certificate signing, digital signatures and cryptographic primitives.
Parsed usage requires bit five for certificate signing, bit zero for digital signatures and any bit from zero through six for an algorithm primitive.
Short arrays supply false for missing bits; isolated encipherOnly or decipherOnly bits grant no primitive.
`permitted_bits` exposes the first eight decisions in high-bit-first order, with absence represented by `0xff` and undeclared parsed bits masked to zero.
The parser accepts one primitive OCTET STRING wrapper and masks BER padding bits beyond the declared bit length.
Signed length arithmetic and backing-capacity checks follow `DerValue.getUnalignedBitString` and `BitArray` on the standalone extension-value array.
* Malformed noncritical extensions are absent.
* A parsed copy survives unparseable copies.
* Malformed critical extensions and duplicate parsed copies fail.

Constraint regression sources cover Java defaults, signed integer limits, ignored fields, all first-byte permission masks, wrapping capacity boundaries, framing, duplicate handling and reservation lifetime.

`CertificateExtendedKeyUsage` is a separate passive immutable view with independent parsing admission.

* The view follows `ExtendedKeyUsageExtension`, `CertificateExtensions`, `X509CertImpl.getExtendedKeyUsage` and `EndEntityChecker`.
  Every usage OID is validated, including unrecognized purposes after an accepted server purpose.
* Absence permits TLS server authentication.
  Parsed lists permit `serverAuth`, `anyExtendedKeyUsage`, Microsoft SGC or Netscape SGC; an empty parsed list denies permission.
* An unparseable-only noncritical extension remains a decoded state.
  Requesting its server-authentication decision returns a TLS-material error.
* A parsed copy wins over malformed noncritical copies in either order.
  Malformed critical copies and two parsed copies fail during decoding.
* The view validates extension contents independently of certificate signature, validity and trust.
  Its admission remains owned through the last use of its decision state.

Extended-usage regression sources cover every accepted server purpose, empty and unrelated purpose lists, malformed and duplicate copies, OID framing and size limits, BER conversion and reservation cleanup.

`CertificatePublicKeyEncoding` owns the normalized SubjectPublicKeyInfo encoding used by OpenJDK 25.0.1 `X509Key`.
It is a passive immutable view with independent memory admission.

* `AlgorithmId.parse` and `AlgorithmId.encode` normalize absent and empty NULL parameters and emit NULL only for their pinned OID set.
  Non-NULL parameters retain their content after Java BER conversion while their outer length becomes canonical.
* `ObjectIdentifier` validation rejects empty, unterminated, overlong and nonminimal base-128 encodings.
  Accepted OID content remains unchanged.
* `DerValue.getUnalignedBitString`, `BitArray` and `DerOutputStream.putUnalignedBitString` preserve the declared bit count and clear unused bits.
  Signed integer wrapping and the backing-buffer capacity check follow the pinned implementations.
* Parsing scratch is reserved before decoding and released before the view returns.
  The surviving reservation covers the retained encoding capacity and its owner until drop.
* `PartialEq` compares normalized `X509Key` encodings.
  `same_public_key` applies the pinned SunJCE DH numeric comparison and uses encoding equality for other OIDs.
* Both `1.2.840.113549.1.3.1` and `1.2.840.10046.2.1` resolve through `AlgorithmId.getName` to the registered SunJCE `DiffieHellman` parameters and key factory.
* DH comparison validates signed `p` and `g`, optional signed 32-bit private-value length, and signed `y` before comparing numeric `y`, `p` and `g`.
** Signed integer magnitudes follow the pinned `BigInteger` range limit.
** Private-value length does not participate in equality.
** Bytes after the first inner `y` INTEGER are ignored.
** Invalid DH fields fail even when the encoding is compared with itself or with a non-DH key.
* Call-local comparison values borrow the existing encoding owner without additional allocation.
* Other `AlgorithmParameters` and `KeyFactory` acceptance checks, custom provider equality, global certificate admission, signatures, validity and trust remain outside these operations.

Public-key regression sources cover parameter framing, converter padding and opaque nested values, the NULL-emitting OID set, OID validity and size boundaries, unaligned bits, integer wrapping, nested conversion and reservation cleanup.

DH regression sources cover both OIDs, signed numeric padding and magnitudes, virtual `BigInteger` range boundaries, private-value length boundaries, ignored key tails, malformed fields, encoding equality and allocation ownership.
