= Java private-key factory admission

`PrivateKey::decode` checks recovered PKCS8 through the pinned Java 25 default private-key factory rules before a SunX509 PKCS12 entry can be filtered for an empty certificate chain.
The caller owns decryption, the recovered-key algorithm preparse, and empty-password retry.
The preparse accepts one or two AlgorithmIdentifier fields, so this module retains that restriction when reading the identifier even though the DH factory alone ignores later identifier fields.
Generic `KeyStore`, deferred NewSunX509 recovery, and SunX509 JKS recovery have separate entrypoints.
This decoder never imports a key into OpenSSL and never compares it with a certificate.

`PrivateKey` is an immutable passive owner of provider-returned PKCS8 bytes and its memory reservation.
Parsing and encoding complete on the caller, with no tasks, global mutable state, retained password, or published construction state.
The PKCS8 frame, algorithm identifier, parameters, integer slices, and optional fields are call-local views or zeroizing transients.
The resulting key owns zeroizing encoded bytes and retains its lease until drop.
Copies made by a transport require separate admission.

== Default provider behavior

The provider and helper sources are pinned in link:sources.sha256[the source manifest] from Eclipse Temurin OpenJDK `25.0.1+8` for Linux x64.
The archive SHA256 is `8daf77d1aacffe38c9889689bc224a13557de77559d9a5bb91991e6a298baa0d`, and its `lib/src.zip` SHA256 is `3ed5aadae786d9e35101a67e94818c4590f5b8a81e7ee44ad4ce4add58881482`.
The built-in SUN, SunRsaSign, SunEC, and SunJCE registrations determine algorithm dispatch and parameter services.
Installed providers, configured PKCS11 providers, and Java system-property overrides remain outside this source-owned decoder.
RSA admission uses the pinned default `sun.security.rsa.restrictRSAExponent=true`.

Common PKCS8 factory implementations accept signed integer versions zero and one, primitive private-key OCTET STRINGs, optional opaque attributes, and the version-one implicit public BIT STRING.
Attributes are omitted from version-zero output and emitted with constructed context tag zero for version one.
Public bits normalize unused padding bits and use primitive context tag one.
AlgorithmId NULL normalization follows the shared Java DER helper, while provider AlgorithmParameters validation belongs here.
An unregistered key algorithm fails before empty-chain filtering.

RSA and RSASSA-PSS require a PKCS1 sequence with version zero and eight nonempty integer components.
The components use Java's unsigned interpretation even when their encoded sign bit is set.
Modulus length rounds up to a byte and must be between 512 and 16,384 bits inclusive.
Above 3,072 modulus bits, the default provider limits the public exponent to 64 bits.
The factory checks these limits before deciding whether CRT components are present.
A zero public exponent, prime, prime exponent, or CRT coefficient rebuilds a version-zero non-CRT key containing only the normalized modulus and private exponent.
The private exponent may itself be zero.
RSA, its historical PKCS1 alias, and its ITU X509 alias dispatch to the RSA factory.
The ordinary RSA CRT path retains non-NULL parameters because the default providers register no `AlgorithmParameters.RSA` service.
A non-CRT rebuild uses the canonical RSA identifier and drops those unparsed parameters.

PSS parameters accept absent or NULL parameters and the provider's explicit context fields, including repeated fields whose last value wins.
Salt length must be a nonnegative signed 32-bit integer, trailer field must be one, and the mask-generation algorithm must be MGF1.
MGF1 digest names are SHA-1, SHA-224/256/384/512, SHA-512/224, SHA-512/256, and the four SHA3 digests.
The main hash identifier is not restricted to that list at factory admission.
The CRT path retains its parameter encoding; the non-CRT path regenerates the parameter sequence from its resulting hash, MGF digest, and salt values, omitting defaults.
Context-field contents may retain unused trailing bytes as Java does.

Nested AES, DESede, and Blowfish hash parameters require primitive OCTET STRING IVs of 16, 8, and 8 bytes respectively.
AES's parameter-spec overload accepts additional IV sizes, but encoded parameters do not.
Nested ChaCha20-Poly1305 hash parameters accept primitive or constructed OCTET STRINGs containing exactly 12 nonce bytes.
These services require complete parameter consumption, while absent or NULL parameters skip service initialization.
The containing PSS CRT key retains those parameter bytes; non-CRT regeneration retains the hash algorithm name and omits its IV parameters.
Cipher-specific OIDs without a registered parameter service retain opaque parameter values.

The six legacy PBE parameter services are `PBEWithMD5AndDES`, `PBEWithSHA1AndRC4_128`, `PBEWithSHA1AndRC4_40`, `PBEWithSHA1AndDESede`, `PBEWithSHA1AndRC2_128`, and `PBEWithSHA1AndRC2_40`.
Their encoded parameters require a complete SEQUENCE containing exactly a primitive salt OCTET STRING and a signed 32-bit iteration INTEGER.
Every salt length and every signed 32-bit count, including zero and negative counts, is accepted at parameter admission.
The cipher's salt and iteration restrictions apply when that cipher is initialized.
BER framing and redundant integer sign padding are accepted through the shared Java DER parser.
Absent or NULL parameters skip service initialization; CRT keys retain nested parameter bytes, while non-CRT regeneration retains only the hash algorithm name.
Nearby PBE OIDs without registered parameter services retain opaque values.

DSA accepts absent or NULL parameters, or a sequence of exactly three signed integers for p, q, and g.
Its private x value is signed, and trailing bytes after that integer inside the private-key octets are retained without parsing.
The historical OIW DSA identifier dispatches to the same factory.

DH accepts only version zero, requires a sequence containing signed p and g plus an optional signed 32-bit private-value length, and rejects optional outer PKCS8 fields.
Its signed x value may have trailing bytes inside the private-key octets.
Both registered DH names select these rules, including the X9.42 OID that Java maps to DiffieHellman.
The DH factory retains the original input encoding, including BER length forms and integer padding.

EC requires one of the 53 named-curve OIDs initialized by `CurveDB`, and an inner ECPrivateKey sequence with version one and primitive scalar octets.
The factory does not impose a scalar length or range check during this path.
Inner context zero carries opaque domain parameters.
Inner context one contains a nested BIT STRING that is validated and replaces any outer version-one public bits.
Its backing-length checks retain local unparsed suffixes after BER conversion and retain enclosing suffixes only for borrowed views.
Remaining fields after that public field, and bytes after the inner ECPrivateKey sequence, are ignored by the factory.
link:curves.rs[The curve OIDs] are derived from active `CurveDB.add` calls and `KnownOIDs` values; commented-out curve registrations are excluded.
Upstream headers are retained in link:COPYRIGHT[COPYRIGHT], with link:LICENSE[GPLv2 with Classpath Exception], link:ASSEMBLY_EXCEPTION[assembly exception], and link:ADDITIONAL_LICENSE_INFO[additional license information].

X25519, X448, Ed25519, and Ed448 require primitive inner scalar octets of 32, 56, 32, and 57 bytes respectively.
Bytes following those octets are retained without parsing.
Non-NULL AlgorithmIdentifier parameters remain opaque because the pinned providers register no AlgorithmParameters service for these names.

ML-DSA-44/65/87 and ML-KEM-512/768/1024 use `NamedKeyFactory` and `NamedPKCS8Key`.
They require absent or NULL AlgorithmIdentifier parameters and primitive inner key octets.
This factory stage imposes no cryptographic key-length check, including on empty key octets.
HSS/LMS private-key generation always fails in the pinned provider.

== Recursive PSS and OAEP parameters

PSS hashes can name another PSS or OAEP service, and either service's main hash can nest again.
The complete nested identifier is validated before its name is consumed.
MGF and pSource identifiers likewise initialize any registered service before the wrapper's required OID is checked.
Absent and NULL parameters skip service initialization.
CRT keys retain the original containing parameter bytes; non-CRT PSS reconstruction retains only the outer hash service name, without its nested parameters.

PSS requires a SEQUENCE and frames all of its context fields before evaluating any field.
Repeated fields retain their last valid value, field order is unrestricted, and a context's unused inner tail is ignored.
Every encountered value must be valid even if a later duplicate would replace it.
OAEP reads ordered optional context fields zero, one, and two, each containing exactly one value.
Duplicate, reordered, unknown, and trailing fields fail.
Both primitive and constructed context tags are accepted.
OAEP uses the outer value's content without checking its tag, unlike PSS's required SEQUENCE.

Both services require MGF1 and admit SHA-1, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/224, and SHA-512/256 as its digest.
PSS additionally admits SHA3-224, SHA3-256, SHA3-384, and SHA3-512; OAEP rejects those MGF names.
Main hash names are not restricted to that allowlist.
OAEP's pSource must be PSpecified with present non-NULL parameters containing primitive or constructed OCTET STRING data.
An empty label is accepted.

== PBES2 parameter names

A nested PBES2 AlgorithmIdentifier selects the general SunJCE PBES2 parameter service before initialization.
Successful initialization derives one of fourteen names of the form `PBEWith<PRF>AndAES_<bits>`.
The PRFs are HmacSHA1, HmacSHA224, HmacSHA256, HmacSHA384, HmacSHA512, HmacSHA512/224, and HmacSHA512/256; the AES sizes are 128 and 256.
AES-192 is rejected by this parameter service.
The initialized names have no reverse OID in the pinned KnownOIDs registry or default provider alias lookup.
A CRT key therefore retains valid PBES2 parameters, while non-CRT PSS reconstruction fails if its final hash name is an initialized PBES2 name.
Absent and NULL PBES2 parameters retain the ordinary PBES2 name and OID.
A PSS or OAEP main hash containing a PBES2 descendant keeps the ancestor service's own name after the descendant validates.
Initialized PBES2 names are not admitted MGF digest names.

`DigestName` is a passive value distinguishing an OID-backed name from a typed initialized PBES2 name.
The PBES2 `Name` enum represents exactly the fourteen derived names, while `Prf` and `Aes` are call-local passive selections.
Only the outer PSS result retains its resolved hash name.
The encoded parameter bytes remain owned by the existing AlgorithmIdentifier and key buffers.
No salt, IV, iteration count, key length, or PBES2 parsing state escapes the validation call.

The parameter service requires an outer SEQUENCE, PBKDF2's OID and a SEQUENCE of PBKDF2 parameters.
Salt is a primitive OCTET STRING of any length, including zero.
Iteration count and an optional key-length INTEGER accept the full signed 32-bit range, including zero and negative values.
Key length is parsed before being overwritten by the selected AES size and imposes no further constraint.
An optional PRF is selected only by an immediate SEQUENCE tag; otherwise HmacSHA1 is retained.
Its contents require one admitted Hmac OID and optionally one NULL-tagged value of any content length, followed by end of input.
The encryption value's outer tag is not checked, and its IV must be a primitive OCTET STRING of any length.
These are parameter-admission rules; cipher initialization has separate salt, count, key, and IV constraints.

Unconsumed PBKDF2, KDF, encryption, and outer sequence tails are ignored.
An optional field whose tag matches is parsed and can fail, while an unmatched trailing tag is left unread.
A historical wrapper whose first value has OID tag six skips that value and treats the next value as the real PBES2 parameter sequence.
The skipped OID's contents are not validated or required to identify PBES2.
The real parameter value still requires a SEQUENCE after its KDF is parsed.
The historical wrapper's remaining tail is ignored.

== Admission and remaining source work

Decode reserves `384 * input_bytes + 65,536` before parsing, with checked arithmetic.
The source estimate allocates `128 * input_bytes` to the existing normalized PKCS8 and algorithm owners, provider views, encoded fragments, final output, and one active Java BER conversion.
On a 64-bit target, the converter's section payload is at most 40 bytes per section, with each section requiring at least two input bytes; old and replacement vector capacities can overlap during growth.
RSA component collections have eight members, optional PKCS8 fields have at most two members, and only the outer PSS result retains its last resolved hash name, MGF digest, and salt values.

Nested PSS and OAEP services use a passive iterative evaluator on the caller's task.
Its `Frame` values are call-local transients: a field continuation owns only its compact undecoded sibling suffix and parsing position, while an MGF continuation owns an OID and its allowlist choice.
A rejected wrapper continuation has no payload.
The shallow `Identifier` owns an OID and a single encoded parameter value, without a full duplicate AlgorithmIdentifier encoding.
The enclosing parsing buffers drop before the next child frame is evaluated.
Pending sibling regions and active child regions are disjoint; an ancestor does not retain its consumed subtree or vector capacity.
No frame contains another frame, and dropping a pending traversal is iterative.

Each live frame corresponds to at least two consumed input bytes.
A compile-time assertion bounds its payload to 64 bytes on the target.
Allowing old and replacement vector capacities during growth, frame storage is bounded by `96 * input_bytes` in the source estimate.
An additional `32 * input_bytes` covers simultaneous frontier, suffix-copy, OID, and shallow parameter-encoding buffers, including BER-normalized views.
The remaining `128 * input_bytes` is margin for normalization expansion and overlap between those categories.
PBES2 adds a bounded number of DER views and normalized temporary owners, without another growing collection or traversal stack.
Its deepest path retains at most the parameter, historical wrapper, KDF, PBKDF2, and PRF views; each owned BER view is bounded by the containing input.
Those views fit within the existing frontier-copy and normalization allowances, and `Frame` keeps its existing size and compile-time bound.
The retained derived name is a fixed-size enum.
There is no fixed nesting-depth limit.
Repeated suffix copying and BER conversion can take quadratic time for adversarially nested inputs, while simultaneously owned byte storage remains linear.
The fixed allowance covers small owner/control allocations and bounded OID representations.
The estimate is conservative source accounting rather than a measured allocator high-water bound.
Temporary owners drop before the reservation shrinks to retained encoded capacity, owner size, and 128 bytes of reservation overhead.
Malformed data, unsupported factories, unsupported nested parameters, and budget exhaustion release their reservations.

Nested PSS hash identifiers can select arbitrary AlgorithmParameters services.
This decoder validates nested PSS, OAEP, PBES2, DSA, DH, EC, AES, DESede, Blowfish, ChaCha20-Poly1305, and legacy PBE parameters for the six services above.
It preserves parameters for identifiers without a registered service.
The parameter-dependent `SpecifiedSHA2withECDSA` name remains unsupported in that nested position.
Successful factory admission does not establish native TLS import, signing, key/certificate consistency, or cryptographic validity.

Regression sources cover PKCS8 fields and BER framing, provider aliases, RSA range and CRT fallback behavior, PSS defaults and errors, signed DSA/DH values and retained tails, all registered EC curves, nested EC public bits, XDH/EdDSA scalar lengths, named post-quantum acceptance, HSS rejection, and reservation lifetime.
Nested IV regressions cover encoded-length boundaries, primitive versus constructed OCTET acceptance, BER forms, malformed components, absent and NULL parameters, CRT retention, non-CRT regeneration, cipher-specific OIDs, and admission release.
Legacy PBE regressions cover all six services, arbitrary salt lengths, signed iteration boundaries and padding, primitive-only salt, complete sequence consumption, BER framing, absent and NULL parameters, CRT retention, non-CRT regeneration, unregistered nearby OIDs, and reservation release.
