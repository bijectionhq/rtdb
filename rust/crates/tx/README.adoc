= Transaction resolution

SQL containing PG_SLEEP or PG_SLEEP_FOR remains a SQL source operation through submission-time static expansion.
The resolving transaction evaluates it through its ordinary asynchronous query path, under transaction/database cancellation.
`tests/submission.rs` checks that sleep and query-clock operations retain the SQL union leg in the actual encoded source payload and that an unregistered RANDOM call fails SQL admission; the tests have not run.

`rtdb-tx` prepares source transactions, reads current and legacy source payloads, resolves operations against an explicit partition snapshot, and emits staged commit or abort values.
The caller owns source-log submission, leadership, replica append order, durable read-back, catalog effects, completion handles, and publication.
The crate starts no tasks.
Source transaction options carry timezone, user, user metadata and an optional backfill system time.

`prepare_submission` expands literal and parameter INSERT VALUES/RECORDS and PATCH RECORDS through SQL-owned binding.
Submission reserves temporary SQL syntax work before lexing and holds the reservation until the static plan has been consumed or discarded.
It preserves raw SQL for data-dependent statements and distinguishes absent arguments from an explicitly empty argument batch.
Compatible Arrow arguments retain their typed columns in the source log and through replay.
Scalar evaluation reads and charges one argument row at a time.
INSERT, UPDATE, and DELETE RETURNING clauses are syntax-checked and ignored by shared SQL preparation, including during static INSERT expansion.
`tests/returning.rs` maps `ignore-returning-keys-3668` through staged mutation, parameter binding, committed reads, and static source encoding; its assertions have not run.
Source replay decodes its recorded operations without repeating submit-time expansion.
The source encoder builds each operation body column independently before assembling the operation union.
The transaction result table declares its nullable Transit error column even when every written result is successful.
Document batches retain their column order in either representation.
Compatible Arrow puts retain their arrays through replay and staging, with transaction headers prepared independently.
Staging can gather compatible columns directly from their arrays when a table combines Arrow puts and individual row operations.
When replay constructs document values, it bounds scratch to one row and shares the ordered Arrow layout across puts.
The resolver carries declared column types to the staged write, including columns whose cells are all null.
The source encoder carries document columns in first encounter order in each table and mutation leg, and the decoder recovers that order from the Arrow field layout.
The encoder builds one document column at a time, retains its measured Arrow buffers and releases the builder scratch before building the next column.
Each SQL statement and each argument row binds against durable rows, resolved predecessors, and the current transaction's preceding writes.
Resolution reserves temporary SQL syntax before lowering each mutation.
For a mutation that opens a query, the syntax reservation stays live through plan admission and releases before execution.
The cursor retains the plan charge.
A query opened by a `TransactionWriter` reads the transaction-local snapshot.
Its temporary SQL syntax reservation releases after plan admission and before execution.
SQL argument payloads retain their physical Arrow fields and raw values through source encoding and replay.
Binding uses their signed execution field view, and parameter evaluation admits unsigned cells at the same signed width.
Static SQL expansion applies that admission before producing logical documents.
An invalid temporal literal leaves the mutation in SQL form so transaction resolution records the planning error and the aborted transaction.
`TxOp::InsertDocs` checks each document's valid-time interval for absence at the transaction's ordered primary view.
A conflict includes earlier staged transactions and writes in the same transaction and aborts the submission atomically with `rtdb.tx/exists`.
The source record retains the create-only operation and the replica replays the resolved outcome.
Static SQL inserts and direct document writes share the source encoder's entity ID validation before publication.
Forbidden fields in concrete document writes abort during source-log resolution and are reported in document schema order.
SQL mutations that read live data or depend on transaction context report forbidden projected fields as planning diagnostics during resolution.
Replica event decoding and durable page copying retain their physical representations.

Canonical SQL mutations emit IID, valid bounds, and a document for puts, or IID and bounds for deletes.
UPDATE compares old and assigned values with type-sensitive equality before writing a new version.
UPDATE keeps unassigned columns and evaluates assignments simultaneously.
DELETE and UPDATE default to the window from transaction time through end-of-time.
ERASE can select historical versions.
PATCH sorts old versions by IID and valid-from, fills uncovered intervals, and applies the shared shallow `_patch` function.
Explicit table declarations survive empty batches; a mutation producing no rows does not create its target.
GRANT and REVOKE require the caller's explicit authorization capability.

`TxResolver` is a passive, term-scoped transient with one mutable caller.
Its immutable `ResolvedTx` queue is visible to subsequent resolution and remains unpublished until the caller admits replica read-back.
The caller takes the queue head before validating its transaction ID against read-back.
Term cancellation drops staged values and fails completion handles owned by the replication layer.
An external `TransactionWriter` must retain its resources within its cancellable future and must not independently commit effects.

Source transactions, argument chunks, metadata, encoded bytes, table buffers, and abort errors retain byte-budget reservations with their allocation owners.
`RetainedBytes::into_bytes` transfers that ownership to a cloneable transport buffer.
Decoded aborts retain their original Transit representation, including historical exception tags, while exposing a normalized anomaly to callers.
Absent and present empty anomaly messages remain distinct through persistence, replay and retained transport clones.
An abort containing an anomaly with no message still contains an error.
Replica payloads contain only the transaction's deltas, including declared zero-row schemas.
Follower decoding finishes all tables before returning a value that can be applied atomically.
Typed source documents and SQL arguments, resolved query rows, and replica batches preserve exact decimal parameters and raw coefficient bytes.
These copy boundaries retain values produced by vector accumulation even when their coefficient exceeds the declared precision.
Computed expression projections and ordinary column writes validate precision and physical width.
Canonical INSERT and UPDATE document packing uses the passive `RowCopy` descriptor to retain selected input cells; PATCH's computed document expressions pass through vector-write validation.

The decimal regression carries raw document cells through source serialization, replay, SUM insertion, staged writes, replica decoding, and the block-page copy seam.
Separate fixtures preserve raw SQL argument metadata in the codec and reject an overprecision parameter when compiled VALUES writes it.
Submit-time static document expansion re-infers decimal metadata from actual coefficient digits throughout nested values, choosing precision 32/width 128 or precision 64/width 256 and retaining scale.
Coefficients above 64 digits fail before submission, following `ValueTypes.kt` and `PutDocs.openFromRows`; decimal-cast expressions remain SQL operations for compiled execution.
These fixtures have not been compiled or executed under the implementation gate.

The SQL parser's remaining general SQL coverage limits also apply to transaction SQL.
The resolver intentionally rejects the removed XTQL DML and transaction-function source legs with their reference anomaly codes.
Database attach/detach validation and application belong to the node catalog capability; this crate stages the supplied verdict and payload.
The pinned database-operation resolver uses the source message timestamp directly, whereas document transactions smooth their default clock and reject a nonadvancing explicit clock.
An earlier database-operation timestamp can therefore fail index predecessor validation; this source/spec disagreement requires a separate decision.
`allium/live-index.allium` records the unresolved specification question about zero-row declarations.

`prepare_submission_with_sql_options` uses the submitting node's captured SQL preparation settings during static SQL expansion.
An eligible prepared INSERT or PATCH can retain one static plan from a successful submission expansion.
Reuse requires the same statement source, target database, submission search path, endpoint policy, effective transaction time zone, and positional execution types after argument coalescing.
Static planning uses the transaction-scoped submission catalog, whose table lookups are empty.
Each submission evaluates its own arguments and bounds, then encodes the result through the ordinary source and retry digest paths.
Source SQL still goes to transaction resolution when static expansion declines, including expressions that need transaction time or live catalog data.
The node also supplies its endpoint policy to transaction-time SQL resolution.
The endpoint setting remains process configuration and adds no field to the source log.
Computed GENERATE_SERIES calls remain SQL source operations and use the resolving node's endpoint policy.
Submission and resolution regressions cover both endpoint modes.

Static PATCH expansion distinguishes literal NULL or FALSE clause endpoints from parameter values.
Either literal becomes the corresponding time sentinel; a null parameter leaves the optional document-operation bound absent and a FALSE parameter fails datetime conversion.
Non-null endpoint objects use `TimeConversions` semantics, including string date fallback and typed local-date midnight resolution.
The `submission::patch_endpoint_tests` sources record these conversions and retained-memory release; they have not run.
