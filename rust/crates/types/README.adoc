= Logical types and physical encodings

Logical types are passive immutable values.
`LogicalType::run_end_encoded` replaces the outer run-end width while preserving nested child encodings and nullability.
Null and bottom types reject run-end encoding.
`unencoded` removes encodings recursively, and type joins operate on these plain value types.
The source regressions distinguish outer layout replacement from recursive removal; execution remains pending for Phase 2.

`UriParts` validates OpenJDK 25 URI syntax and borrows the original component spelling without normalization or network access.
It distinguishes opaque URIs, hierarchical paths, registry authorities and server authorities, including bracketed IPv6 scope identifiers.
Decoded accessors preserve empty components and use Java UTF-8 replacement grouping for percent-escaped bytes; a plus sign remains literal.
Object equality folds ASCII scheme and host case and raw percent-escape hexadecimal case without decoding octets or normalizing path segments.
ASCII object rendering applies Unicode 16 NFC and percent-encodes non-ASCII UTF-8 bytes after callers admit its allocation bound.
The parser, decoding, equality and ASCII rendering source regressions are unexecuted.
Isolated UTF-16 surrogate inputs remain outside the current UTF-8 string carrier and require a wider representation for complete Java parity.

Runtime version metadata is one immutable process value initialized on the first version or revision lookup.
The initialization monitor captures a nonblank `XTDB_VERSION` override or the Cargo package version, plus `GIT_SHA` or the build-time `RTDB_REVISION` when available.
The command-line version and SQL session-information functions share that value.
Release builds embed their recorded source revision in the native executable.
`compiled_build_info()` returns the full build revision, crate version and selected TZDB version and digest without consulting runtime overrides.
The server and configuration migrator expose that same immutable report through `--build-info` for release-package validation.

== Calendar and timezone values

`CivilDate` and `CivilDateTime` are immutable ISO proleptic Gregorian values covering Java LocalDate's year range, −999,999,999 through +999,999,999.
Their constructors validate calendar fields; Arrow unit conversion and narrowing remain caller responsibilities.
`Instant::parse_iso` and `to_iso_string` cover Java Instant's additional boundary years, using checked final instant limits and grouped fractional output.
SQL timestamp parsing has its separate SMART calendar rules and accepts the pinned offset and region suffixes.
Local field extraction, zoned resolution and query-clock date fallback are distinct entry points.

`CalendarDate` couples a validated date to its selected day or millisecond unit.
Object admission truncates day counts to signed 32 bits; expression admission checks that narrowing.
Both millisecond admissions use wrapping multiplication.
`tests/calendar_value.rs` covers these boundaries and serialization as unexecuted regression source.

`Value::calendar_date` preserves calendar dates that cannot be represented losslessly as physical day or millisecond cells.
Its `CalendarDate` retains the validated date and selected unit until an explicit admission boundary.
Expression output checks signed 32-bit day narrowing, while object input truncates days to signed 32 bits; both use wrapping multiplication for millisecond storage.
Admission recursively visits nested values without allocating.
Durable Arrow schemas retain their existing physical date types.

`ZoneId` uses immutable tables compiled from the selected OpenJDK TZDB input, including historical offsets and recurring future rules.
Overlaps prefer the earlier offset unless a valid preferred offset is supplied; gaps move forward, and start-of-day uses the first valid instant of the date.
`ZoneId::offset_at` accepts every signed 64-bit second for fixed offsets and fixed-rule regions; regions with transitions retain Java Instant and calendar bounds.
The default bundle, source archive checksum, license files and override contract are in link:data/tzdb/README.adoc[timezone data provenance].
The selected version and SHA-256 are embedded as constants; qualification must compare them with the actual reference JVM's installed data.
Calendar, parser and zone regression sources remain unexecuted.

`LegacyTimeZone` supplies the separate OpenJDK25 `java.util.TimeZone` interpretation of the same selected database.
Its historical table uses the final raw offset before the retained transition range and its future tail follows the `ZoneInfoFile` conversion to `SimpleTimeZone`.
Local readings choose the standard side of overlaps and the preceding offset of gaps.
The legacy parser supports Java25 short IDs, custom GMT offsets through ±23:59:59 and GMT fallback for unrecognized IDs.
It accepts raw signed 64-bit Date milliseconds and preserves Java wrapping at that storage boundary.
Building the legacy view retains standard-offset transitions and aliases from the bounded TZDB decoder.
The derived tables are limited to one million entries before generation; an oversized custom input fails decoding explicitly.
Existing `ZoneId` lookup and local resolution remain independent of the legacy view.
`tests/legacy_zone.rs` exercises historical, recurring, overlap, custom-ID and signed64-boundary cases as unexecuted source.

`java_date` supplies the October 1582 cutover calendar used with `java.util.Date`.
It translates raw signed 64-bit milliseconds to hybrid calendar fields without first wrapping a timezone-adjusted sum.
The inverse accepts lenient fields and wraps when the Date storage domain overflows.
Kafka Connect's legacy calendar and date truncation use these shared primitives.

`UriParts::java_hash_code` provides the URI object hash beside object equality, including UTF-16 hashing and component-specific case folding.
`tests/uri.rs` records numeric and equivalent-spelling fixtures as unexecuted regression source.

`decode_java_utf8` applies Java replacement grouping to byte sequences, including encoded surrogate triples.
URI percent decoding and stored Unix Path rendering share that decoder without copying URI percent-byte runs.
`tests/utf8.rs` records malformed-prefix, surrogate and supplementary decoding as unexecuted regression source.

== Finite memory admission

`MemoryBudget` owns a finite byte limit with atomic retained and peak counters.
Child scopes charge the same ancestor limits while retaining their own counters.
A `MemoryReservation` keeps its budget chain alive until the final shared lease drops.
`MemoryBudget::reservation_lease_count` exposes the number of reservation controls a successful reserve creates across that immutable chain, including zero-byte reservations.
The read-only query allocates nothing and changes no counters; callers can combine an explicit per-control native allowance with payload demand before admission.
It does not specify allocator-exact control sizes or change the requested-byte accounting contract.
Exclusive `shrink_to` releases excess bytes from that chain without lowering peaks; attempts to grow the lease fail before changing counters.
Exclusive `grow_to` admits only the additional bytes through the same budget chain before the caller expands its allocation.
The requested total must be at least the current lease size; rejected growth preserves every retained charge and lease size.
Ancestor peak counters may include temporary admission during a failed attempt.
Neither operation resizes allocations, and shared lease handles prevent either operation until exclusive access is recovered.
Columnar allocation owners re-export these same types and retain their leases through Arrow slices and clones.
`AllocationScope` retains caller-owned intermediate and result charges until the scope is dropped.
The scope must outlive every allocation it admits, unless another charged owner takes over that allocation.
Calls may share one scope across threads; each reservation includes bookkeeping and charges the same finite budget chain.
Expression callers use the same concrete type through the `EvaluationScope` reexport.
Frontend planning admission still requires reservations before parsing and catalog-dependent binding; shared budget availability alone does not provide those reservations.

== Anomaly messages

`Anomaly` owns its category, code, optional message and context as one passive diagnostic value.
`new`, `incorrect`, `unsupported` and `fault` create a present message, including a present empty string.
`new_nullable` preserves an absent message separately from an empty message.
Native serde retains absence as JSON null; native display prints the code alone when the message is absent and `code: message` when present.
Wire adapters apply their own message rendering rules.
An optional `AnomalyKind` says what went wrong for the anomalies callers act on by what happened rather than by whose fault it was; `ResourceExhausted` marks a memory budget or byte limit that had no room.
Native serde carries a present kind and omits an absent one.
Formats that carry only the code, such as XTDB's Transit errors, recover the kind from the code with `AnomalyKind::from_wire_code`.

== Checked Clojure collection construction

`ClojureKeyIndex` moves caller-admitted entries into an immutable array-map or HAMT index while semantic hash and equality callbacks borrow their keys.
Checked maps use earlier-key/later-key comparison order through eight entries and transient HAMT insertion above that threshold; checked sets always use the HAMT constructor.
Null hash keys bypass hash and equality callbacks, and hash collisions retain the pinned incoming-key comparison and resident-key rehash order.
Logical bitmap spare capacity is independent of Rust buffer capacity: fresh bitmaps promote on their seventeenth occupied slot, while collision wrappers promote on their nineteenth.
`DuplicateKey` retains every input entry and identifies the earlier key for an array-map diagnostic or the incoming key for a hashed diagnostic.
Callbacks stop at the first error or duplicate, and traversal yields original source ordinals without semantic callbacks or allocation.

Both completed and duplicate owners retain their optional `AllocationScope` borrow through destruction.
Callers admit input storage before construction; the index reserves each new capacity while old buffers and their charges remain live.
`None` explicitly selects unscoped construction, and callers remain responsible for their input and work limits.
The cumulative index allocation bound includes per-reservation bookkeeping but excludes input payloads and the scope's initial charge.
For `n > 0` inputs, the 32-bit trie has at most eight levels including collision leaves, at most `8n` arena nodes, `256n` live bitmap-buffer slots and `2n` live collision ordinals.
Native geometric growth and retained old charges are covered by `allocation_bound`; checked arithmetic rejects an unrepresentable bound.
`clojure_index/tests.rs` and the scope-lifetime documentation examples remain unexecuted regression sources.

This constructor has no production host or reader adapter yet.
Shared UTF16, frontend numeric admission and reader singleton identity, quoted constant reconstruction, function-root identity and semantic host text remain required work.

== Shared JVM numeric values

`jvm_number` owns the numeric payload and operation descriptors shared by host expressions and stored Transit objects.
It retains fixed-width JVM categories, Clojure BigInt, Decimal coefficient and scale, and Ratio numerator and denominator.
Callers admit numeric inputs, scratch and outputs and retain their charges through the values' lifetimes; the numeric value owns no scope or object identity.
Operation-specific bounds support the existing arithmetic, comparison and extrema admission points.
Collection equivalence, Java wrapper equality and cross-category numeric comparison remain distinct operations, and an enclosing object owner supplies identity-sensitive equality such as shared NaN objects.
`jvm_number::decimal_parts_text` formats the same coefficient and scale used by numeric objects and physical decimal adapters.
`murmur3_32` supplies the shared borrowed-byte hash; columnar vector hashing and XXHash32 retain their columnar owner.
The numeric unit tests and `tests/jvm_number.rs` preserve regression sources for category behavior, primitive and boxed casts, decimal scale edges and hash vectors; they remain unexecuted.
Frontend semantic admission, shared UTF16, reader singleton identity and host collection/text adapters remain required work.

== Shared Java text

`java_text::JavaString` retains exact UTF16 units in shared immutable UTF8 or UTF16 backing.
Charged constructors admit the boxed backing, shared owner and bookkeeping before allocation; their leases survive until the final clone is destroyed.
`JavaString::copy_utf16_with_admission` delegates its checked complete byte demand to the caller's synchronous admission authority before copying exact units.
It retains the returned reservation in the existing shared backing; an undersized lease is rejected before storage allocation, and any larger admitted amount remains charged through the final clone.
This lets conversion contexts enforce their own per-record limits without exposing their budget or maintaining a second owner/lease collection.
`AllocationScope::memory_budget` lets a retained value acquire its own lease from the caller's budget without transferring the scope's existing charges.
Explicitly named untracked constructors serve programmatic contexts with the same native size checks.
Owned strings admit at most `i32::MAX` units, while borrowed `JavaText` views require no allocation.
Equality compares units across representations; shared backing does not establish Java object identity.

`JavaText` counts and slices in UTF16 units, including ranges that split a supplementary pair.
Unit and code-point iterators preserve unmatched surrogates; `java_utf8_bytes` explicitly applies Java String encoding and replaces each unmatched unit with byte `?`.
The borrowed UTF8 accessor succeeds only for scalar-aligned ranges on UTF8 backing.
The carrier has no serde, display, wire-format or implicit lossy conversion.
`tests/java_text.rs` contains unexecuted regression sources for exact units, slice boundaries, explicit encoding and retained allocation lifetimes.
Regex, SQL and EDN literals, host text and collections, object identity, serialized plan trees and raw diagnostics still require their consumer adapters.
