= Native timezone data

`2026e.dat` is the unchanged `lib/tzdb.dat` from Eclipse Temurin `jdk-25.0.5+8`, the JDK the reference XTDB runs on.
The native build decodes these bytes without executing Java.
All users of `rtdb-types`, including embedded bindings and remote backends, share the selected tables.

[cols="1,3"]
|===
|Source |Eclipse Temurin `25.0.5+8-LTS` JDK (`IMPLEMENTOR_VERSION="Temurin-25.0.5+8"`, macOS aarch64)
|Source entry |`Contents/Home/lib/tzdb.dat`
|TZDB version |`2026e`
|TZDB SHA-256 |`a02e3a23d67255782b11ab81070902235ab564080f0f65ffe2a989cdaa86fe89`
|===

`LICENSE`, `ADDITIONAL_LICENSE_INFO` and `ASSEMBLY_EXCEPTION` are byte-identical to that JDK's `legal/java.base` directory.
The binary layout follows OpenJDK25 `TzdbZoneRulesCompiler`, `TzdbZoneRulesProvider`, `Ser`, `ZoneRules` and `ZoneOffsetTransitionRule`.
The decoder is native Rust and does not invoke those classes.

Set `RTDB_TZDB_PATH` at build time to select another OpenJDK format-version-1 bundle.
The build validates at most one MiB and records the selected version and exact input SHA-256 in `rtdb_types::TZDB_VERSION` and `rtdb_types::TZDB_SHA256`.
Cargo tracks both the selection environment variable and the selected file for rebuilds.
Qualification against a JVM artifact requires its actual installed TZDB version and digest to match these values.
Changing the data requires rebuilding every artifact that links this crate.
