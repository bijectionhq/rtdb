= XTQL query preparation

`random` and duration-valued `sleep` use the shared scalar evaluator.
Their result types are double and null respectively; sleep's unit arithmetic is documented in the expression crate.
`tests/volatile.rs` retains type, range, null and awaited-duration source assertions without executing them.

Aggregate calls retain original case and hyphen/underscore spelling, including explicit `all` or `distinct` forms.
The passive `AggregateName` value validates a spelling against the closed evaluator set and fixes its quantifier; deserialization uses the same validation.
Each spelling resolves to a fixed evaluator variant; absent factories such as `average` and `vec-agg-distinct` fail preparation.
Computed aggregate arguments become input projections before grouping.
SQL integration fixtures in `rtdb-sql/tests/aggregate_forms.rs` retain the resulting explanations and execution results as unrun source.

`read` produces EDN forms with UTF-8 byte spans.
`parse_query` produces query, clause, binding, temporal-filter, and expression values.
`compile` binds those values against one supplied catalog and produces `rtdb-plan::PreparedStatement`.
The reader, parser, and compiler are passive.
Standalone compilation owns a transient column-ID allocator and nested parameter bindings; embedded compilation borrows the enclosing SQL preparation's allocators.
The supplied catalog retains the visibility basis.
`compile_query` binds a parsed query with explicit external parameter positions and advances the caller-owned internal parameter cursor for nested applies.

Native lowering covers scans, explicit and parameter relations, pipelines, unification, joins, left joins, projections, filters, unnest, ordering, limits, offsets, union-all, ordinary aggregates, and scalar/existence/pull subqueries.
Shared variables produce SQL equality predicates.
Parameterized dependent relations use `RelationNode::Apply`; bindings remain local to the dependent plan and do not increase external parameter arity.
Left-join unification predicates execute inside the dependent plan before null extension.
Shorthand binding symbols remain logic variables even when a function parameter has the same spelling.
Scan value predicates remain above temporal resolution.
Use `#(rel % [age])` to read a list of documents from the first query argument.
Declared function parameters use their exact symbol spelling, and SQL-inline functions take the argument positions assigned by the SQL statement.
An explicit `nil` for the optional database, temporal filters or join bindings selects the same default as omitting the option.
An expression map derives each field name by dropping the first UTF-16 code unit from the key's string representation.
Use keyword keys such as `:name` to express the field name directly.

The checked-in test source retains names from `xtdb.xtql-test` and `xtdb.xtql.plan-test`.
Its structural checks are native preparation checks, not receipts proving the upstream result assertions executed.
`tests/reference-cases.json` records the source identities and pending execution status.
Compilation and all execution remain pending for Phase 2.

The shared plan and executor implement SQL ordered-set percentiles.
Use SQL `PERCENTILE_CONT` or `PERCENTILE_DISC` with `WITHIN GROUP` for the ordered-set syntax.
The XTQL planner reports an invalid expression for these calls.

The following surfaces remain outside this checkpoint's implementation.

* The shared scalar function registry does not yet cover every JVM expression function, cast option, temporal operation, or collection operation reachable from XTQL.
* Submit one EDN query form.
Reader evaluation, reader conditionals, automatic namespace aliases, unreadable Java objects, and regex objects are outside the native text surface.
Use explicit namespace names or `#:namespace` maps, choose conditional forms before submission, and pass regex patterns as strings.
Use a fixed-arity `fn` with a list parameter in place of a variadic anonymous function.
* Compute a relational subquery for a temporal scan bound separately and pass its date or timestamp as a function parameter.
Use the same snapshot basis for both queries when the bound depends on database contents.
* SQL and XTQL share the catalog scan types for bitemporal columns, including nullable upper bounds for open intervals.
* Untyped prepared relation parameters require concrete argument types before they can produce their correct output schema.
* Protocol submission, result-key conversion, and transaction submission require the production frontend and session owners.

Supported literal tags include UUIDs, hexadecimal bytes, URIs, dates, local timestamps, zoned/offset timestamps, instants, local times, durations, intervals, period-duration values, and timestamp ranges.
Unsupported tags fail during preparation.
Explicit `#:namespace` maps follow Clojure 1.12's EDN reader: immediate unqualified keyword and symbol keys acquire the namespace, `_` removes it, and already-qualified keys remain unchanged.
Key spans retain the original source spelling; collisions are checked after namespace expansion.
The reader remains a caller-owned transient and returns the existing passive map representation.
Literal object compatibility, normalization collisions, exact failure signatures, and all result observations still require paired JVM/native execution.

`vec-agg` preserves input order and null elements and returns an empty vector for an empty global input.
Grouped empty input produces no result rows.
Its metadata is a nonnullable list, and the pinned registry has no distinct `vec-agg` factory.
The plan variant is passive immutable aggregate metadata; execution uses the existing in-memory caller-pulled aggregate cursor.
`sql/tests/inline_xtql.rs` retains the value assertions from `xtdb.operator.group-by-test/test-vec-agg` through the public inline XTQL path.

Cast forms accept `#xt/type` scalar, list, set, struct, map, run-end, fixed binary, and timestamp-range targets with decimal `:precision` and `:scale` options.
Nested `#xt/type` values resolve recursively.
Struct field names retain the string conversion of ordinary EDN values, including Java numeric spelling and readable collection children.
Map entry types retain their `:sorted?` flag using EDN truthiness.
Applying a run-end width replaces only the outer layout and retains child encodings and nullability.
Cast dispatch retains the requested nullable or encoded type separately from its lowered decimal and list conversion.
The fallback identity cast compares that requested type exactly; an encoded or nullable composite target does not turn a plain input into that layout.
Specialized numeric casts still dispatch through their value kind, and encoded decimal targets apply the same precision and scale options as plain decimal targets.
Nullable list elements use the list union-remapping path rather than a nullable scalar cast.
Known source types are checked during XTQL binding, and nonnull values supplied for previously unknown parameters are checked during evaluation.
Unspecified precision preserves existing decimal legs; explicit precision and scale apply recursively to list elements.
The parser retains the target as the shared passive `CastTarget` value, and binding tracks cast operands through unification and aggregate extraction.
`tests/casts.rs` maps the reference expression list-cast, array-text, and recursive decimal-option assertions.
Decimal literals and cast targets preserve the full signed 32-bit scale, including recursive lists.
ROUND with integer or decimal input requires a constant scale and retains it in result metadata.
String-to-decimal casts accept OpenJDK 21's BMP decimal digits; decimal literal tokens retain the ASCII grammar from https://github.com/clojure/clojure/blob/clojure-1.12.0/src/jvm/clojure/lang/EdnReader.java[Clojure 1.12 EdnReader].
The reader classifies BMP digit prefixes as numeric tokens and rejects Unicode decimal literals at that grammar boundary.
Nullable vector forms flatten their type constructor, such as `[:? :list :i64]`.
The pinned `serde.types/->type` dispatch passes a bare `:fixed-size-list` to the Arrow constructor, which then lacks its required width; this parser retains rejection for that form.
Nonpositive decimal precision remains valid metadata, although it rejects nonnull values at the vector write boundary.
Object-valued tagged struct field keys and hash-map/set iteration spelling remain source-completeness obligations.
Integer reader tokens normalize octal, hexadecimal, and explicit radix syntax before field-name printing or literal conversion.
An `N` suffix preserves the BigInteger distinction, while integers outside signed 64 bits become BigInteger reader values automatically, as in Clojure 1.12 `EdnReader.matchNumber`.
Their later vector-value conversion retains the existing signed 64-bit value limit.
Ratio tokens that divide exactly, such as `6/3`, read as integers and follow Clojure's Long and BigInt rules.
For fractional column values use a decimal or floating-point expression.
For exact fractions inside a computed regex pattern, use a supported division form such as `(/ 1 3)` within that pattern.
Strings and character literals support octal escapes and character literals can include punctuation delimiters such as `\]`.
Both `^` and `#^` metadata forms leave the underlying data form available to XTQL.
Duplicate reader keys and set elements compare integers across Long/BigInteger representation, decimals independently of scale, and lists/vectors by their sequence contents.

Temporal cast options retain `:precision`, including recursive list and encoded targets.
Interval cast options retain string-valued `:start-field` and `:end-field`, with `:leading-precision` and `:fractional-precision` validated according to the source value family.
Source-family rejection and qualifier validation precede numeric options that are read only to select the resulting interval representation.
Integer interval casts accept a start field alone; unused precision options have no effect.
An absent qualifier preserves interval input metadata; an explicitly empty option map retains the reference's distinct duration dispatch and fails for duration inputs.
Raw options remain passive values until the source leg consumes them, including malformed values ignored by timestamp-to-timestamp and integer-to-interval casts.
Consumed numeric options retain Clojure's unchecked primitive-long conversion during code generation and checked conversion in generated temporal calls for integer, floating, decimal, and BigInteger reader values.
`cast-interval` retains its earlier fractional option conversion when choosing the alias target type.
`tests/casts.rs` contains recursive temporal, encoded interval, integer qualifier, ignored malformed options, numeric coercion, and deferred parameter cases.
Consumed malformed option values retain native typed diagnostics rather than the JVM's class-cast or null-unboxing exception spelling.
`cast-tstz` and `cast-interval`, including underscore spellings, lower to the same passive cast descriptors.
`CompileOptions.default_timezone` binds the timestamp alias's result field; SQL-inline XTQL inherits its containing statement's preparation zone.
Native session execution passes its current query zone into compilation.

Tagged timestamp readers use the pinned `Time.asLocalDateTime`, `asZonedDateTime`, `asOffsetDateTime` and `asInstant` SQL grammar, including SMART dates and extended years within the Arrow microsecond range.
Local tags preserve parsed local fields; offset tags retain the zone's offset at the resolved instant.
The Clojure `#inst` reader retains its separate four-digit year, optional trailing fields, millisecond truncation, leap-second rollover and GregorianCalendar cutover behavior.
Calendar and timezone rules come from `rtdb-types`; the source tests cover these parser distinctions and future named-zone transitions without executing the JVM.
Tagged dates retain the full LocalDate calendar range inside expressions, with vector narrowing deferred until the completed expression result.

== Array bounds and trimming

`array_upper`, `array_lower` and `array_length` accept an ordinary list and an I64 dimension.
Dimension one returns the element count, lower bound one, and element count respectively; an empty list keeps lower bound one.
Other dimensions return `xtdb.expression/array-dimension-error`.
`trim_array` accepts a signed integer count and keeps a lazy view of the input list.
An overtrim returns `xtdb.expression/array-element-error` with the remaining length.
Negative counts extend the declared view, and reading beyond the input fails.
The view checks the signed 32-bit size limit when its size is observed; `array_lower` does not observe that size.
Null arguments short-circuit later argument evaluation.
`tests/arrays.rs` contains regression source; compilation and execution remain pending.

`col_description` and `pg_indexam_has_property` return NULL with the signed integer, OID and text signatures exposed by the pinned reference.
`tests/pg_null_functions.rs` retains the source assertions for those compatibility calls.
The numeric catalogue includes `log10`, `sinh`, `cosh`, `tanh` and `mod`; expression and XTQL callers also expose the `double` conversion.
`tests/math_catalogue.rs` covers nulls, result types and native numeric dispatch as unexecuted source.

`generate-series` and `generate_series` expose the shared three-argument exclusive series operation and optional fourth endpoint-inclusion Boolean.
Their endpoint behavior is independent of the SQL process setting.
`tests/series.rs` preserves integer results, explicit inclusion and lazy size/element observations as unexecuted regression source.

`#xt/uri` literals validate the shared Java URI syntax before constructing a value.
The seven `uri-*` component functions accept URI values, preserve absent versus empty components and expose the port as a nullable signed 32-bit integer.
Text casts retain the original URI spelling.
URI equality follows Java component equality, and nested text rendering applies NFC before ASCII percent encoding.
`tests/uri.rs` covers literals, casts, extractor types, invalid values, object equality, rendering and reached ordering failure as unexecuted regression source.

XTQL exposes `bit-not`, `bit-and`, `bit-or`, `bit-xor`, `bit-shift-left` and `bit-shift-right` through the shared signed-integer function contract.
`tests/bitwise.rs` covers alias binding, signed casts, null demand, arity and narrow shift-count overflow as unexecuted regression source.

`extract`, `date-trunc`, `date-bin`, `range-bins` and `age` use the shared temporal expression contracts.
XTQL temporal fields remain case-sensitive uppercase literal strings.
`range-bins` takes separate from/to endpoints and returns lazy `_from`, `_to` and `_weight` structures; SQL's period syntax is lowered before reaching that contract.
`current-timezone`, `local-date`, `local-time` and `local-timestamp` accept the underscore aliases, with compact `localdate`, `localtime` and `localtimestamp` aliases as well.
Clock precision is a literal integer, and current timestamp output metadata binds the compile options' timezone.
`tests/temporal_functions.rs` retains field, bin, calendar, clock and rejected-input regression sources; execution remains pending.

XTQL generic calls accept `is_true`, `is_false`, `distinct_from` and `_meta_double`, including their hyphenated aliases.
These calls share expression type selection, nested unknown equality and temporal metadata conversion.
`tests/scalar_aliases.rs` provides unexecuted regression source.

XTQL exposes `compare`, `compare_nulls_first` and `compare_nulls_last` through the shared scalar catalogue, including hyphenated names.
Their signed integer results retain the reference byte-comparator magnitude and explicit null placement.
`tests/comparison_calls.rs` supplies unexecuted source regressions.

`(. object field)` selects Struct members and Transit map fields, including stored error data and transaction-key records.
The field symbol retains its spelling; Struct literal member names follow the ordinary normalized-name rules.
`get-field` and `get_field` retain the shared generic call's absent field-name metadata.
`tests/field_access.rs` covers both call forms, null results, false-value behavior and evaluation demand as unexecuted regression source.

`like` and `ilike` expose the shared two-argument wildcard matcher.
LIKE accepts text or binary pairs; ILIKE accepts text pairs and uses Java Unicode case folding.
`tests/like_calls.rs` records generic-call admission and null-demand cases as unexecuted regression source.

`=`, `<>` and null-safe distinctness reject Set/Set pairs, including pairs nested in ordinary list alternatives or equal-shaped structs.
This admission precedes collection-length and selected-branch evaluation; different struct key sets retain their constant result.
Strict `===` has a separate object-equality contract.
`tests/set_equality.rs` retains these admission cases as unexecuted regression source.

XTQL generic calls admit `single-field-interval` and `multi-field-interval`, including their underscore spellings.
Single-field calls take source, unit, leading precision and fractional precision; multi-field calls take source, start unit, leading precision, end unit and fractional precision.
Consumed metadata uses literal uppercase unit names and integer precisions, with leading precision 1 through 8 and SECOND fractional precision 0 through 9.
Single-field fractional metadata outside SECOND is ignored after argument control selection.
`tests/interval_constructors.rs` records value, null, metadata and unused-payload cases; these sources remain unexecuted.

Scalar calls select argument types before consuming monomorphic payloads, so `(+ (/ 1 0) nil)` returns null.
Selected control expressions and polymorphic result boxes retain their demand.
`if` uses boolean coercion, while `true?` and `false?` recognize only booleans.
For example, `(if (/ 1 0) 1 2)` selects the first branch from the numeric type without consuming the division payload.

`nth` accepts signed integer indexes on nonnull sources and returns null for registered non-list source kinds.
A null source or index selects the strict null result before payload demand.

Generic function names require a matching registered method for every nonnull argument combination.
A definite null argument retains strict null selection even for an unregistered name.
The predicates `nil?`, `true?`, `false?` and `boolean` are registered; additional Clojure type-predicate names have no generic method.

`like-regex` requires three UTF8 arguments: input, pattern and flags, with strict null specialization.
Literal flags control matching; nonliteral flag payloads are ignored while their type-selection controls still run.
The selected pattern compiles before the input payload is consumed.

`_patch` discards a monomorphic null left payload and preserves both arguments’ control selection.
Constructed Struct fields are evaluated before the merge, and nested list cells remain deferred until read.

BETWEEN binds complex subjects once before evaluating bounds, including null-producing subjects.
Symmetric BETWEEN tries the reversed bounds only after the forward comparison fails to return true; reached bound expressions may be evaluated again.

== Raw replacement metadata

`regexp-replace` parses only its first argument as an XTQL expression.
Pattern, replacement, start, occurrence and flags retain raw forms, missing fields become nil, and later fields are ignored.
Raw metadata does not introduce variable, parameter or aggregate dependencies.
Flags consume a string's characters or direct character entries of raw sequences; symbols and strings inside a raw list are not evaluated.
Nil and false start/occurrence fields are false; zero, empty strings and empty collections are true.
Applicable emitted source types admit metadata before invocation, while a null-only source leaves it uninterpreted.
The owned carrier preserves nonliteral host pattern syntax through the native host compilation and invocation phases described below.
`tests/regex_replace_metadata.rs` records missing/extra fields, raw flags, dead COALESCE tails and host-form preservation as unexecuted source regressions.
Native REGEXP_REPLACE host patterns retain their own lexical compilation and invocation phases.
Simple lexical bindings and pure string/control forms compile independently of XTQL row variables, while raw replacement and flag fields retain their metadata contracts.
Use a string for a fixed pattern or `java.util.regex.Pattern/quote` to turn supported host text into a literal match.
Use the fully qualified `clojure.string` spellings listed in the link:../../../dev/doc/rust-regex.adoc[regex reference] when constructing a pattern from static text.
For row-dependent matching, use `like-regex` with a pattern expression and literal flags.
For a replacement that needs row values, ambient state, arbitrary interop or unsupported host functions, transform the text in the caller and pass the finished value as a query argument.
Host `if-let` and `when-let` support one simple-symbol binding.
Each evaluates its initializer once and exposes its value in the selected truthy branch.
Unqualified macro calls respect same-name local bindings.
The `clojure.core/` spellings select the core forms.
The link:../expr/README.adoc[expression reference] describes branch scope and return values.
Ordinary host calls reject known non-IFn function values before argument evaluation, while nil, vectors, maps, sets, keywords and symbols admit their arguments before invocation.
Quoted anonymous-function forms remain raw lists; successful collection invocation, null invocation diagnostics and exact JVM throwable payloads remain required work.
Host BigInt and BigDecimal literals preserve exact numeric text, and checked primitive conversions retain the difference between direct inline calls and calls through lexical function values.
Host arithmetic supports checked and promoting addition, subtraction, multiplication, increment and decrement, plus exact or floating division.
Direct n-ary forms retain left-nested execution and primitive overloads; calls through lexical functions retain strict argument evaluation and boxed numeric dispatch.
Host numeric comparisons and sign predicates preserve cross-category comparison and NaN behavior.
Comparison chains evaluate all argument expressions before skipping later numeric pairs after a false result.
Host `quot`, `rem` and `mod` preserve fixed-integer wrapping, BigInt and ratio results, decimal quotient scales and JVM floating remainder behavior.
Fixed inline `quot` and `rem` retain their compilation-time arity checks and primitive-versus-boxed result metadata; `mod` remains a strict boxed function call.
Host bit operations retain fixed-integer admission, signed-long results, Boolean bit tests and low-six-bit shift/index masking.
Direct variadic bit calls execute left-nested operations, while lexical function calls evaluate every argument before folding; inline and ordinary bit forms retain their distinct arity and result-metadata rules.
Host `min`, `max` and `abs` retain selected numeric categories, primitive widening, signed zero, NaN admission and Decimal scale.
Extrema preserve selected Object values, derive each nested direct overload independently and evaluate all arguments before indirect folding.
One-argument extrema return their argument unchanged; `abs` preserves minimum-long wrapping and nonnegative Decimal identity under the root nil MathContext.
Host numeric classification predicates distinguish fixed integers, BigInt, Float, Double, Ratio and BigDecimal without numeric coercion; `float?` accepts both floating widths and `rational?` excludes them.
`number?`, `integer?`, `int?`, `double?`, `float?`, `ratio?`, `decimal?`, `rational?`, `pos-int?`, `neg-int?` and `nat-int?` retain ordinary strict unary invocation, boxed result metadata and false results for nonnumeric values without reading collection contents.
The host compiler retains primitive-boolean and unresolved static-call metadata separately from boxed Boolean values, including through dead branches and lexical bindings.
`tests/regex_host.rs` records computed patterns, shadowing, strict arguments, UTF16 substring indexes and dead-branch compilation as unexecuted source.
Remaining host numeric functions and dynamic arithmetic bindings, interop, effects, object rendering and generated-local multiplicity remain required follow-on work.
