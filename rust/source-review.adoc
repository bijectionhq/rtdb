== Ownership review

`Binder` is a transient used by one preparation; schemas, expressions, relational plans, table bindings, and prepared statements are passive values.
`CompiledExpr` is passive and captures its input schema; evaluation borrows parameters, the query clock, time zone, and correlated rows.
`CatalogSnapshot` and `QueryContext` are passive query regions retaining the read view, storage, memory budget, clock, and cancellation token.
Pull cursors and their operator state are single-writer transients driven by the caller.
`TermFence` is passive state owned by the long-lived replica reader, and `Admission` is a passive decision value.
Neither term admission nor expression evaluation starts an autonomous task.

Arrow buffers retain their allocation charge through custom allocation owners, including child arrays, validity buffers, and slices.
Cache reads transfer their reservation into local blocking I/O so a cancelled fetch cannot leave an uncharged detached allocation.
`DiskCache` is a shared monitor; each load has one caller holding its per-entry exclusion guard, and passive leases prevent file eviction during reads.
`NativeResources` is a node-scoped passive factory retaining the shared cache, local I/O region and timestamp capability.
`IoRegion` is a monitor whose close rejects new work and joins admitted local blocking I/O, including calls whose waiters were cancelled.
Ordinary node/server startup failure, unstarted closure and joined shutdown all drain that region.
The disk-cache directory lock excludes concurrent owners and precedes abandoned temporary-file cleanup.
Cache identity retains the pinned database/partition layout; provider or epoch replacement under the same cache root requires explicit qualification.
`Writer` and `LocalTimestampSource` are passive; the local log driver chooses work, and the writer samples each record's clock before append.
The local log driver requires cancellation followed by joining its run task; forcibly aborting that task can leave an in-progress blocking append with an unknown result.
Several scalar and row-building paths still allocate transient values before charging their retained size.
These paths require further work before claiming bounded peak query memory.
Prepared parameters with an unknown type require rebinding to execution types before batch evaluation.
Prepared SQL rebinds against each execution context and checks PostgreSQL result signatures separately from dynamic Arrow schemas.
Query bases now carry requested per-partition system-time caps separately from captured snapshot identities.
Parser/IR transient allocation accounting remains incomplete.
Timestamp/duration/calendar arithmetic and unqualified interval/duration text casts have source and regression cases.
Temporal comparison, qualified interval/cast options, named-zone extreme dates and full temporal lexical compatibility remain incomplete.
Session parameters, buffered SQL, pinned read bases and retained token/timezone strings now carry co-owned reservations; failed transaction state retains a flag instead of an arbitrary error payload.
Server authentication, source factories and the node share one execution allocation budget.
Startup cache and execution ceilings divide the configured process allocation limit, while transport and cryptographic library allocation qualification remains pending.
Production configuration parsing reserves input, expanded YAML nodes and environment copies before construction and retains its transferred lease in the CLI or embedded lifetime.
Embedded handles resolve through a monotonic registry; its admission monitor rejects new operations during closure and waits for admitted operations before native resource teardown.
Arrow export owners retain native allocation leases until the foreign consumer releases its data, including after statement closure.
FFI and JVM source regressions cover stale handles, cancellation, statement database capture, SET/SHOW side effects and foreign buffer lifetime; none has executed.
TLS issuer-name and PEM conversion results own independent allocation reservations, including when multiple results outlive their source store.

== Findings against the reference

The native progress monitor serves an already-satisfied applied prefix after an ingestion failure, fails unmet waits with the current fault, and clears that fault after an explicit successful driver restart.
The pinned JVM Watchers fail every later await; `db.allium` retains the unresolved contract question.
The frontend source retains the pinned read-only COPY distinction, connection-ID-only cancellation routing, and Flight handle ownership by caller identity.
The corresponding policy questions remain in `tx.allium`; implementation status is recorded here rather than in the specification.

The block-cut specifications disagree about the row gauge.
`BlockCutter.kt` seeds its gauge from applied rows, then advances it as transactions resolve.
The open question in `allium/live-index.allium` records that discrepancy; the Rust live index tracks applied rows.

`trie-cat.allium` describes L1C supersession as making covered L0 entries garbage.
The pinned `trie_catalog.clj` removes those entries from the catalog without scheduling their files for trie GC, retaining a recovery substrate.
The Rust trie catalog follows that implementation, and the spec has an open question about the retention obligation.

The pinned memory trie shares mutable log storage between derived values.
Its bounded linear usage differs from the specification's general immutable-branch guarantee when two sibling descendants are extended before reading either.
The Rust implementation retains independent immutable roots.
This observation is from source; no JVM failure has been reproduced.

The Java IPC writer emits a four-byte end-of-stream marker where Arrow Rust's writer emits eight bytes.
The format writer adjusts that footer-relative marker.
FlatBuffer layout, metadata field allocation order, and bidirectional file compatibility remain unverified.

The repository protobuf files use edition 2023.
The Rust build script obtains descriptors from the unchanged schemas and lowers their presence and packed-field settings for `prost-build`.
That generation path has not executed.

The pinned HLL estimator contains the signed conversion of `2^32 - 1`.
The Rust estimator preserves the source formula; its serialized registers and estimates still require comparison runs.

The grouping comparator applies null equality to the outer key and delegates nested structures to ordinary equality.
A nested null can therefore prevent two otherwise identical compound keys from grouping together.
An equality-compatible total ordering cannot silently replace that behavior.

The Rust object key excludes parent traversal.
Local and remote copies accept explicit destination roots, retaining immutable publication and bounded payload buffers.
The source tests cover cross-root and cross-prefix destinations, exact retries, conflicts, missing sources and joined local cancellation.
Remote copies require a shared provider client; physical provider limits and the original direct multipart assertions remain qualification work.

The pinned `compactor` command initializes `xtdb/base` through `open-compactor`, and the inspected path creates no database-specific compactor registrations.
The command therefore appears idle in this revision.
The native `compactor` command deliberately opens database followers and compaction owners, writes source notifications and waits for a separate writer to apply them.
This source-level difference is explicit; concurrent execution needs a multi-writer source provider, while local logs retain exclusive writer ownership.
This is a source finding, not an executed observation.

The Rust term fence rejects sequence overflow without publishing a wrapped value.
The Kotlin implementation uses `Long.MAX_VALUE` as its voided sentinel and adds to sequence values without checked arithmetic.
A same-term record at `Long.MAX_VALUE` therefore applies after a gap in Kotlin, contradicting the lifecycle specification's `DiscardInVoidedTerm` rule; Rust's explicit voided state discards it.
Negative resumed or persisted sequence positions can also collide with Kotlin's unsequenced and unknown sentinels, while the Rust states remain distinct.
The sequence domain and exhaustion behavior need an explicit compatibility decision; ordinary nonnegative positions below these limits follow the existing rules.

== SQL subquery source checkpoint

SQL scalar, existence and quantified subqueries lower to the existing shared Apply executor.
Correlation scopes are preparation transients; their captured columns become apply-local parameters above the lexical client-parameter range.
The source follows `xtdb.sql/plan-sq`, `apply-sqs` and the quantified-array NULL normalization.
Native result test source covers nested correlation and CTE reuse, scalar cardinality, quantified truth tables, grouping, outer joins and parameter arity.
UPDATE's immutable plan identifies its original target columns, so dependent-query fields cannot enter the persisted document.
The scalar and quantified paths retain dependent execution; the JVM decorrelation optimizer and its error-elision behavior have not been ported or compared.
Full outer join conditions, temporal scan clauses, RECORDS expressions and standalone controls still reject relational subqueries.
ORDER BY can use nonprojected inputs and projected aliases, with final projection and DISTINCT following ordering.
NATURAL/USING joins preserve the pinned left-column common-name binding and qualified wildcard behavior, including unmatched right rows.
ROW_NUMBER and restricted LEAD/LAG lower to a caller-pulled window cursor with stable partition order, owned spills, and sequential shifted readers.
These paths have native regression source and independent source review, but no execution results.
Inline SQL XTQL query expressions share the caller's column allocator and apply-parameter scope, including derived tables, CTEs, set operations and relational subqueries.
Their source review follows the pinned occurrence-based parameter numbering and preserves original SQL spans through rewriting.
Explicit and correlated temporal endpoint columns resolve without exposing those columns through wildcard expansion.
Lateral derived tables and implicit lateral UNNEST lower to the shared dependent-query executor with the pinned lexical scope rules.
The pinned implementation explicitly rejects recursive CTEs, and native preparation retains that rejection.
Query settings, interval qualifiers and the outstanding shared scalar-function catalog remain reachable language gaps.
Shared decimal cast targets distinguish default decimal preservation from explicit precision/scale and recurse through list element unions.
Decimal values and logical fields retain signed 32-bit precision and scale through protobuf, Arrow files/streams, Flight, COPY and the C Data interface.
Native Arrow carriers retain validated full-parameter annotations internally; external schemas carry the actual Arrow parameters and reject those reserved annotations on ingress.
Decimal least-upper-bound promotion preserves signed Kotlin integer wrapping and its uncapped precision result.
SUM and typed cell copies preserve raw coefficients independently of declared precision through source replay, staged writes, replica decoding, block flush and compaction.
Ordinary value writes retain precision checks, and all coefficient writes retain physical byte-width checks.
Computed projections validate their final nested decimal cells; bare columns and canonical INSERT/UPDATE row packing retain raw cells.
Static submission converts parameter decimal objects back to inferred 32/64-digit document fields, while compiled VALUES performs ordinary projection validation.
Decimal arithmetic, comparison, canonical text and integer conversion bound powers by coefficient digits; expanding PostgreSQL binary and SQL logic fixed-point output reserves its expansion first.
XTQL target/options syntax and exact decimal diagnostics remain gaps; those paths are not declared equivalent.
