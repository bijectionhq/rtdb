== Counterexamples and amendments

[cols="1,2,2",options="header"]
|===
|Property |Small trace |Amendment or surviving rule

|Atomic batch
|Resolve, then publish the debit alone.
|Make the full batch the unit of the admitted log transition.

|Durable acknowledgement
|Resolve, then acknowledge without append.
|In the model, only an applied batch can be acknowledged.

|Term fencing
|Resolve in an old term, hand over, then publish the pending batch.
|Reject stale terms and preserve admission through deferred apply.

|Retry identity
|Resolve one identity, append, retry that identity, append again.
|Preserve a durable receipt or refuse an ambiguous retry under the provider contract.
The model checks uniqueness for its receipt policy.

|Read basis
|Pin, resolve a new request, append, apply and change the pinned read history.
|Keep the captured observation stable.

|Durable root
|Publish a manifest before storing its replacement object.
|Publish the durable replacement before retiring its predecessor.

|Shared reclamation
|Pin an old generation, store and publish its replacement, then collect the pinned generation.
|Allow collection only after references reach zero.

|Cache generation
|Start loading, invalidate, publish a replacement and complete the old load.
|An obsolete loader can publish only a private path.
In production, cache invalidation and pathname publication share the state lock.

|Search visibility and rank
|Merge two historical writes across their system origins, or count a row whose second MATCH predicate fails.
|Retain system origins, apply strictly later erases to older rectangles, and score only resolved rows that pass the scan restriction.

|Compaction schema
|Decode a spill page whose Arrow union has a null leg, then copy it into a writer whose declared field differs in nullability.
|Re-encode the original rows to the declared schema when passthrough would violate that schema.
|===

== Remaining proof obligations

The complete native temporal ceiling and rectangle emitter still need a refinement proof against the point evaluator.
The search ranking proof still needs coverage of the production floating-point score frontier, alternate physical recency page layouts, and optional build failure under memory pressure.
The durable protocol models assume provider behavior.
Provider faults, object-store recovery, the full trie coverage transition and cross-node lease accounting need production refinement evidence.
The observations here support specific component claims and bounded protocol claims.

== Expanded refinement run

Production sources through `b2609268a` now use the Verus-checked single-event rectangle subtraction and temporal recency fold step.
The combined proof run verified 19 functions across three areas and rejected all nine Verus mutations at their declared functions.
Lean checked the full mathematical recency fold against the early-exit fold for ordered valid intervals.
It also proved that retaining the required ordered prefix preserves top K and gave independence witnesses for whole batches, the admission horizon, the private prefix and operation order.
Public `Polygon::recency` preserves its existing behavior for arbitrary constructed shapes.
The early-exit refinement relies on ordered native intervals.

Seventeen node search tests passed.
The new tests compare plain MATCH and exact scores with a scan corpus when an index build exceeds the memory budget or historical physical pages are out of global IID order.
The count-star plan also keeps the projection empty when only cardinality is needed.

The native trie collector currently selects garbage from the latest catalog and a retention timestamp.
It has no distributed evidence of which generations readers still need.
The lease model requires generation validation at admission and an enforced expiry on reads.
The coordinated pin model requires an authority that serializes pin acquisition and reclamation, plus a contract for abandoned readers.
Both alternatives are conditional on the modeled provider and clock assumptions.

== Checkpoint interruption on local durable storage

The combined runner passed from `11131976a` with both Rust options enabled.
TLC explored all 97 reachable states of the single-root model.
The shortest early-root trace is three transitions.
A second variant loses a child after its durable write in eight transitions.
The log-retention variant removes the prefix, crashes, and then cannot find the root in eleven transitions.

Four native conformance tests passed, including interruptions immediately before and after the root write, loss of a source acknowledgement, and recovery against a closed history manifest.
The pre-write replay rebuilt from the retained log.
The post-write replay opened the stored checkpoint and observed the same single system-time row.
Moving the root write ahead of the table blocks in a disposable copy made the post-write replay fail at startup on the missing object `tables/public$docs/blocks/b00.binpb`.

The first combined run exposed a race in the fault fixture.
Injected closure can reach the shutting-down driver's log poll before cancellation is selected.
The final test accepts that exact injected error as an interruption and still checks the durable checkpoint and recovered history on both sides of the write.

These are local provider observations and a bounded model of checkpoint publication under the stated retention and durability assumptions.
The referenced-trie closure across concurrent compaction and GC, and behavior on remote storage, remain separate obligations.

== Azure pending copy counterexample

The checkpoint model that waits for copy completion holds in all 155 reachable states.
Treating copy acceptance as completion publishes a root without its data object in six transitions.
The offline Azure diagnostic passed through the production adapter at `6f0094f47`, with a provider returning `202 Accepted` and `x-ms-copy-status: pending`.
The adapter returned success from file publication and deleted the copy source.
The fixture observed the premature success on loopback.
Live Azure behavior under load, completion handling and cleanup of interrupted remote copies remain open.
