== Counterexamples and amendments

[cols="1,2,2",options="header"]
|===
|Property |Small trace |Amendment or surviving rule

|Atomic batch
|Resolve, then publish the debit alone.
|Make the full batch the unit of the admitted log transition.

|Durable acknowledgement
|Resolve, then acknowledge without append.
|In the model, only an applied batch can be acknowledged.

|Term fencing
|Resolve in an old term, hand over, then publish the pending batch.
|Reject stale terms and preserve admission through deferred apply.

|Retry identity
|Resolve one identity, append, retry that identity, append again.
|Preserve a durable receipt or refuse an ambiguous retry under the provider contract.
The model checks uniqueness for its receipt policy.

|Read basis
|Pin, resolve a new request, append, apply and change the pinned read history.
|Keep the captured observation stable.

|Durable root
|Publish a manifest before storing its replacement object.
|Publish the durable replacement before retiring its predecessor.

|Shared reclamation
|Pin an old generation, store and publish its replacement, then collect the pinned generation.
|Allow collection only after references reach zero.

|Cache generation
|Start loading, invalidate, publish a replacement and complete the old load.
|An obsolete loader can publish only a private path.
In production, cache invalidation and pathname publication share the state lock.

|Search visibility and rank
|Merge two historical writes across their system origins, or count a row whose second MATCH predicate fails.
|Retain system origins, apply strictly later erases to older rectangles, and score only resolved rows that pass the scan restriction.

|Compaction schema
|Decode a spill page whose Arrow union has a null leg, then copy it into a writer whose declared field differs in nullability.
|Re-encode the original rows to the declared schema when passthrough would violate that schema.
