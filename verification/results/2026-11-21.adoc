== Counterexamples and amendments

|===
|Property |Small trace |Amendment or surviving rule

|Atomic batch
|Resolve, then publish the debit alone.
|Make the full batch the unit of the admitted log transition.

|Durable acknowledgement
|Resolve, then acknowledge without append.
|In the model, only an applied batch can be acknowledged.

|Term fencing
|Resolve in an old term, hand over, then publish the pending batch.
|Reject stale terms and preserve admission through deferred apply.

|Retry identity
|Resolve one identity, append, retry that identity, append again.
|Preserve a durable receipt or refuse an ambiguous retry under the provider contract.
The model checks uniqueness for its receipt policy.

|Read basis
|Pin, resolve a new request, append, apply and change the pinned read history.
|Keep the captured observation stable.

|Durable root
|Publish a manifest before storing its replacement object.
|Publish the durable replacement before retiring its predecessor.

|Shared reclamation
|Pin an old generation, store and publish its replacement, then collect the pinned generation.
|Allow collection only after references reach zero.

|Cache generation
|Start loading, invalidate, publish a replacement and complete the old load.
|An obsolete loader can publish only a private path.
In production, cache invalidation and pathname publication share the state lock.

|Search visibility and rank
|Merge two historical writes across their system origins, or count a row whose second MATCH predicate fails.
|Retain system origins, apply strictly later erases to older rectangles, and score only resolved rows that pass the scan restriction.

|Compaction schema
|Decode a spill page whose Arrow union has a null leg, then copy it into a writer whose declared field differs in nullability.
|Re-encode the original rows to the declared schema when passthrough would violate that schema.

== Reader leases across nodes

The previous boundary left readers on other nodes unprotected, because their catalogs never reach the writer's collector.
Every node now gives each query snapshot a bounded read lease.
A node reads its monotonic clock, then the replica log tip, and anchors the lease once its catalog has applied that tip.
A snapshot captured afterwards may begin provider requests strictly before the anchor plus `reader_lease` minus `reader_lease_margin`, one hour and one minute by default.
The storage I/O region checks the lease as it admits each provider request and refuses a late one with `rtdb.storage/read-lease-expired`.
A node that cannot confirm its catalog waits up to the margin for its log processor and then holds an expired lease.
The trie collector deletes an eligible trie only after a whole lease has passed on its own monotonic clock since it first observed the trie as eligible.
In Multi, that deletion records a release that the cell reaper erases only after its grace.
A collector starts with no observations after restart or failover.
A node that reads a scan fragment for another node's query captures its own snapshot and holds its own lease.

The link:../verus/read_lease/laws.rs[read lease area] verifies the three production decisions and two laws.
The composed law relates each node's monotonic readings to real time: over one lease, measured and real elapsed time differ by at most `drift`.
It assumes the anchor precedes the collector's first observation in real time and a request takes at most `io_bound`.
Under `2 * drift + io_bound <= margin`, an admitted request finishes before any deletion the collector permits.
No clock synchronization between nodes is assumed; the default one-minute margin over a one-hour lease tolerates up to 30 seconds of drift per lease, less half the request allowance.
Admitting a request at the deadline fails the original contract, and fails both laws when the contract is weakened with it.
Dropping the margin or the collector's wait, together with its contract, fails the composed law.

=== Monotone fork reference manifests

Only initialization of a fresh fork adds reference edges.
Later collection edits withdraw the exact observed name and owner from the current manifest.
The edit writes the next immutable slot of the snapshot it read and confirms its withdrawal from the published head before continuing.
Lookups confirm the head after loading its bytes, and cleanup prunes only below that confirmed head.
These decisions assume authoritative listing, immutable conditional writes and a monotone head while the residence remains open.

The reaper withdraws shadowed fallback references before deleting its own object or release record.
An interrupted physical removal leaves the release record available for a later pass.
These changes preserve fresh manifest observations. The retained-manifest and physical-owner admission contracts remain separate obligations.
