= RTDB kernel study results, 2026-11-22

== W2 and R5 · Inherited serving reads and physical residence disposal

Production change `586330acad`.
An inherited serving read acquires a directory registration on the deployment and residence containing the provider path.
The provider operation retains that registration through caller cancellation.
Disposal closes that residence to new reads, drains its regions and transfers the observed fork references before removing the source.
A fork can read an owned copy without depending on a retired owner.

The native replay starts a fork fallback read, cancels its waiter while the provider operation is active, and confirms that disposal still waits for the physical owner.
After the provider work releases its hold, disposal completes and the same open fork reads the copy.
Two source controls fail at their named assertions when owner admission is skipped or a fenced owner admits new work.
The local replay exercised `ReferencingStore`, the in-memory directory and local object store, the provider I/O lifetime boundary and the disposal API.
It makes no claim about reproducing a failure of a query snapshot.

== W2 and R5 · Fork publication across whole-residence disposal

Production change `4ac4d1716`, tree `925442dae362203bcb0b3a1150cf074c0bd8b8d4`.
This increment uses the local reclamation lineage state introduced in `6e9d6182d`.
Whole-residence disposal acquires a distinct, persistent phase against the version of the drained physical owner. The phase advances the preparation generation before the referrer inventory is read.
An interrupted disposal can resume against the same physical scope. Its receipt and the reopening of that phase publish together.
A remote fork observes the open generation before storage preparation. After disposal, a stale preparation is refused and a fresh one can use the surviving copy.
