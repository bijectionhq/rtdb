= RTDB kernel study results, 2026-11-23

== W1 · Successor trie collector and lease expiry

The collector contract in link:../../dev/doc/gc.allium[gc.allium] starts a new wait after a collector restarts or takes over.
The study covers a newly selected trie under that contract.
It compares an observation scoped to one collector with a weaker design that permits a predecessor's observation to carry over.

== W1 · Transaction catalog retention through the local ledger

The external transaction fixture uses two independent local store handles on the same filesystem ledger.
It checks that the floor stays at its previous position while the resolver owns the capture.
The writer stages a row and opens a cursor over the transaction's overlay.
The cursor retains the captured catalog after resolution returns, still reads the row, and releases the hold on drop.
The next attempt advances the floor.
A source transaction attempting to use the earlier capture then receives `rtdb.storage/catalog-not-current` from the store.
The overlay mutation fails at the assertion that the cursor retains the hold after resolution.
All 120 transaction crate cases passed after rebase.
Exact commands and output are under transaction-catalog-hold-pzn3x9vi/ in the evidence directory above.

The fixture exercises production transaction resolution, query capture and the local directory lock protocol.
It uses a row in the transaction overlay and no remote provider work.
Shared admission on stores without a catalog ledger, scheduling across real elections, and transaction-cursor cancellation while a provider call drains remain open.

== W1 · Resuming a pending local retirement

The local collector fixture now reopens the collector while the earlier filesystem reader ticket is still held.
The successor retains both files and the one pending intent.
After the ticket is released, the same collector removes both files and clears the intent without another removal publication.
Admission at the earlier cut is then refused by the persisted floor.

The retirement replay's failure-propagation control now targets the collector's call to the deferred release adapter.
Its ordering control now targets the release ranking function used by the local and hosted adapters.
All seven controls were rejected at their declared assertions.
The ordering control tests the shared function with the deterministic fixture's store.
Hosted provider settlement remains a separate check.
