= RTDB Multi on consensus keepers, 2026-11-26

RTDB Multi ran on Logkeeper's keeper-hosted consensus streams through `journal-contract`, as described in link:../../dev/doc/rtdb-multi-consensus-keeper.md[rtdb-multi-consensus-keeper.md].
RTDB pins Logkeeper `749260efc462527b31609f6a3d22ae240a9e8b04` on Logkeeper `main`, which adds `ConsensusJournal` and the `consensus-testing` local cluster.
All runs used one Apple M6 host with keepers and RTDB on loopback.

== Process qualification

`rust/bench/v1_consensus_keepers.py` started three voter keepers in distinct failure domains and a catalog keeper as separate `logkeeper keeper` processes, each with enrolled media and mutual TLS.
It started release `rtdb dev --multi` with `--multi-journal-url logkeeper-consensus://...` and drove rtdb.v1 Transact commits over TLS Flight with 5-second phases.
Each phase checked every key it acknowledged with rtdb.v1.TxStatus, which must return the exact original receipt.
Each recheck replayed every key acknowledged since the start.

Every phase passed.
No acknowledged commit was lost or changed across the voter loss, the RTDB kill and reopen, or the full keeper restart.
The reopened RTDB process reported writer readiness again before the recheck.

Throughput stays near 600 commits/s from 1 to 16 clients.
The consensus batch appender commits a Multi group one record per keeper round trip, so one writer stream is bounded by that round trip.
A keeper-side batch command is the next step.
The phase after the voter restart ran at about half rate while the restarted voter caught up.

The debug `rtdb-db` test binary needs `RUST_MIN_STACK=16777216`. Without it, `native_checkpoint_keeps_original_occurrences_and_fences_reads_until_the_reciprocal_drain` overflows the default test thread stack, on `main` as well.

== Open

* Throughput: add a keeper-side batch append so one Multi group commits in one round.
* Timed originals: consensus keepers do not sign quorum-sync evidence, so funded appends are unsupported on this journal.
* Placement: streams use one configured voter triple. Directory placement and voter replacement are not wired.
* Bijection hosted cells and the installed ordered journals still use their existing journals. The old journals stay until this switch is qualified in a hosted cell.
